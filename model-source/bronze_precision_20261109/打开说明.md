## 贴图与精度

武器沿用原成品 512×256 青铜图集，保留原始像素和 UV 密度。人偶使用 2048×2048 独立贴图，保持每模型单位 8 像素，保留原有细密铜锈与铸纹，并处理新结构和眼部镶嵌。每张贴图为一帧；没有复制逐帧模型或叠加发光壳。

所有工程内嵌 PNG，同时在“贴图”目录提供原图，搬到另一台电脑也可编辑。各武器一份材质，人偶主体一份材质；持械展示场景使用人偶、武器两份材质。

## 保真与成本处理

五把武器与现有原成品做了正、背、侧、顶和斜视对照，25 张固定条件截图全部逐像素一致。实际 Java 导出的坐标、UV、材质和 Display 数据也按目标 Float32 数值逐位核对一致。四件基础武器清理了 1373 个已证明完全位于不透明刚体内部的面、17 个完全隐藏组件，保持可见轮廓与厚度。

曲线开锋、实厚铸纹和缠柄使用原成品的细分几何。已试验更紧凑的合并表示，但局部显示未通过逐像素对照，未纳入定稿；原有低组件候选也损失了所需细节。本版因此在原成品成本范围内保留立体结构，不以降低细节换取组件数字。

现有 `BronzeTwinRenderer` 按每个 cuboid 读取六个面，所以双刃保留六面字段及轴对齐结构，不添加它不支持的旋转。运行时的主、副刃合计 3539 个 cuboid，分别为 1894 和 1645。3539 个组件的整套工程用于编辑成套武器，不会与两个运行组件重复同时绘制。

持械展示场景将两把武器的同一套可见几何各整理为一个可编辑网格，方便 Blockbench 查看；保留了 28312 个原始顶点和 21234 个四边面。这是展示场景的节点整理，不代表游戏运行几何或 FPS 改善。手持武器的精细立方体仍可在第 05 个工程内编辑。

## 导出与接入

“导出/assets/tnc/models/item”提供 Minecraft Java 1.20.1 模型。双刃沿用 `bronze_halberd` 的历史成套 ID，以及 `bronze_twin_main`、`bronze_twin_off` 两个运行组件，保持其作为同一件双持武器的关系。

人偶仍使用现有原生 Humanoid 数据格式，文件位于 `assets/tnc/puppet/bronze_puppet_parts.json`，贴图为 `assets/tnc/textures/entity/bronze_puppet.png`。保留 head、hat、body、双臂、双腿的骨骼与枢轴，供现有战士连招系统驱动。该数据不属于 GeckoLib/Bedrock，不放进 `geo/`。

“导出/参考模型/BronzePuppetFineModel.java”为 Blockbench 原生导出参考；现有项目使用上面的 Humanoid 数据加载器。第 07 个通用持械场景只作展示，不覆盖运行人偶或战斗动画。

## 验证范围

七个工程已在 Blockbench 5.2.2 重新打开，几何、UV 和骨架检查通过；内嵌贴图与独立 PNG 像素一致。检查了多视角、头部近景、GUI 和第三人称右手 Display。实际工程与运行物品导出共 14 份结构审计无错误，详细记录位于“验证”。

`java-legacy` 审计只是共享结构预检，不是完整 1.20.1 schema 认证；通用审计也不能证明任意网格的游戏运行兼容。实际 draw call、客户端动画、光影和 FPS 未测量。

本次交付模型源文件和导出参考，尚未替换游戏内资源，没有启动 Minecraft。攻击、强化、合成、投掷、召唤和冷却代码未改动。
