## 1. 病灶：不是"方向一样"，是"刃面一样竖" ✓

先纠正一个容易误判的点：**26 片刃的飞行方向本来就是各不相同的** ✗。

`WaterSpellRules.slashDirections(yaw)` 发的是 **3 个纬度圈 × 8 个偏航 + 南北极点 = 26** 个方向 ✓：

```java
for(float pitch:new float[]{0,-45,45})for(int i=0;i<8;i++)result.add(Vec3.directionFromRotation(pitch,yaw+i*45));
result.add(new Vec3(0,1,0));result.add(new Vec3(0,-1,0));
```

**真正的问题在刃面朝向** ✗。客户端 `WaterWaveVisuals.crescent` 用飞行方向现推刃面基：

```java
Vec3 right=WaterSpellRules.right(dir), up=right.cross(dir).normalize();
```

`WaterSpellRules.right(dir)` 对水平方向取 `dir × (0,1,0)` ⇒ `right` 是**水平的**；
于是 `up = right × dir` 必然**恒等于世界竖直** ✓。
⇒ 8 片水平刃全是"竖着的 C" ✗，只是各自朝着不同方位飞 ✗。这就是作者看到的"都是竖着的" ✓。

> 顺带：`up` 恒为竖直也意味着这一批刃**完全没有滚转自由度** ✗，26 片刃的视觉信息量只有"方位 + 俯仰"两维 ✗。

## 2. 改法：绕飞行轴滚转，环内槽位 × 45° ✓

### 2.1 一套基，两个端共用 ✓

新增 `WaterGeometry.rolledBasis(dir, roll)`（客户端）与 `WaterFx.rolledBasis(dir, roll)`（服务端，
服务端没有 client 类 ✗），都是把 `(right, up)` 这组正交基绕 `dir` 转 `roll` 弧度（等价 Rodrigues ✗）：

```java
static Vec3[] rolledBasis(Vec3 dir,double roll) {
    Vec3 right=WaterSpellRules.right(dir),up=right.cross(dir).normalize();
    double c=Math.cos(roll),s=Math.sin(roll);
    return new Vec3[]{right.scale(c).add(up.scale(s)),up.scale(c).subtract(right.scale(s))};
}
```

因为 `(right, up, dir)` 本身就是正交基 ✓，绕 `dir` 转就是这组二维旋转 ✓，不需要矩阵 ✗。

### 2.2 滚转量：槽位 × 45°，另加缓慢自转 ✓

`WaterSpellRules` 新增三个常量/函数 ✓：

```java
public static final float SLASH_ROLL_STEP = 45F;   // 环内相邻槽位差 45°
public static final float SLASH_ROLL_SPIN = 4F;    // 每秒自转 4°（缓）
public static float slashRoll(int index) { return index % 8 * SLASH_ROLL_STEP; }
public static double slashRollRadians(float rollDegrees, double age) { return Math.toRadians(rollDegrees + age * SLASH_ROLL_SPIN); }
```

`slashDirections` 的索引排布是 `环×8 + 槽` ✓，所以 `index % 8` **正好是环内槽位** ✓
⇒ 同一圈的 8 片刃拿到 0/45/90/135/180/225/270/315 ✓，正是作者要的"45、90、135、180 这样转着射" ✓。
极点（索引 24/25）落成 0°/45°，无害 ✓。

**持续斩击另加整波偏移** ✓：t3 每 `SLASH_VOLLEY_INTERVAL=20` tick 放一波，
`emitSlash` 给每波整体再加 `volley × 22.5°` ⇒ 连看几波是**转着射**的 ✓，而不是每波重复同一组刃角 ✗。

### 2.3 三处表现同步滚转 ✓（缺一处就会错位 ✗）

| 层 | 位置 | 改动 |
|---|---|---|
| 刃面 | `WaterWaveVisuals.crescent(...,double roll)` | 用 `rolledBasis` 取代 `right/up` 现推 ✓ |
| 刃口亮线 | `WaterWaveVisuals.crescentGlow(...,double roll)` | **同一套基** ✓，否则亮线会与刃面错开 ✗ |
| 服务端粒子 | `WaterFx.slashFront(...,double roll)` | **同一套基** ✓，否则粒子和刃错开 ✗ |

滚转值经同步字段下发 ✓：`TNWaterFieldEntity` 新增 `EntityDataAccessor<Float> ROLL` +
`roll()` 读取器 ✓，两处生成点（起手 26 片 / 每波 `emitSlash`）都赋值 ✓，
渲染与粒子各自用 `slashRollRadians(roll(), age)` 加上同一个自转项 ✓。

## 3. 为什么判定完全不用动 ✓

判定走 `WaterSpellRules.slashIntersects(...)`，它算的是目标到**刃轴**的距离 ✓：

```java
Vec3 right = ..., up = ...;               // 两个横向分量
return dx*dx + dy*dy <= radius*radius;    // 只取"到轴距离"
```

滚转是**在 `(right, up)` 平面内旋转** ✓ ⇒ 两个分量的**平方和不变** ✗ ⇒ 命中集合逐点不变 ✓。
所以这是**零判定风险**的纯表现改动 ✓：伤害、命中、数量、时长、速度全部一字未动 ✓。
