## 一、以前的水阵为什么不好看

旧 `WaterGeometry.richCircle` 走的是 `WaterSolidModels.seal`：把一张约 120 个元素的
方块模型 `seal.json` 贴到法阵上。俯视就是一圈蓝/金**方块**，外圈锯齿、中心阶梯，
和光法重绘后的花瓣/日轮放在一起明显不是一套东西；水法自己的潮汐、月牙、漩涡
母题完全没有出现。

另外，水法释放前只有 SpellEngine 的粒子：读条 0.6–1.2 秒，除了粒子没有阵、没有聚水、
没有潮墙，和光法/雷法/暗法的读条仪式感差距很大。

## 二、新法阵：程序化潮汐印

`client/WaterGeometry.seal(...)` 现在全部用薄片几何现画，不再读方块模型。调色板仍是
水法的珍珠白、青、深蓝，金色只做少量刻度：

| 层 | 几何 | 低阶 t1/t2 | 中阶 t3 | 高阶 t4/t5 |
|---|---|---|---|---|
| 外环 | 白青主环 + 细金外圈 | ✓ | ✓ | ✓ |
| 潮圈 | 0.855R 青环、0.58R 白环 | ✓ | ✓ | ✓ |
| 内圈 | 三段断续内流弧（不再用 0.34R 整环） | ✓ | ✓ | ✓ |
| 符文 | 环上金色/青色浪形刻痕 | 8 | 12 | 12 |
| 浪鳍 | 外环上带宽度、尖端收细的浪鳍 | 4 | 6 | 8 |
| 月牙 | 两端收尖的月牙，0.465R | ✗ | ✓（小） | ✓（大） |
| 旋臂 | 从 0.27R 卷到 0.92R 的潮汐旋臂 | ✗ | ✗ | 3（t4）/4（t5） |
| 中心 | 三股螺旋 + 四缕细流 + 开口逗号 + 排水孔 | ✓ | ✓ | ✓ |
| 卫星 | 环外小印（由调用方给数量） | 2 | 3 | 2–4 |

关键点：

- 月牙不是一段等宽圆弧：`sealCrescent` 用 `sin(πu)` 把内外半径在两端收到同一点，
  所以是**两端尖的月牙**，不是“C 字环”。
- 浪鳍有实际宽度（根部 0.044R、中段 0.026R、尖端 0.010R），不再是细线。
- 旋臂是**渐细的薄带**，不是一条亮线；t5 有 4 条，t4 有 3 条，t1–t3 没有，
  这样低阶不会看起来像“小号 t5”。
- **中心漩涡**：`sealVortex` 先铺一层 0.225R 深色盆底，再画三股从 0.30R 卷到
  0.045R 的渐细螺旋带（t4/t5 多四缕更紧的亮细流），外沿只留 0.245R/0.205R/0.165R
  三段断续弧，不闭合；最里面是两道反向开口逗号和 0.04R 深色排水孔 + 0.011R 亮点。
  没有“圆环 + 实心核”，俯视读作水在往下漏，而不是瞳孔。
  旋转速度比外阵快（`time*0.032`），短读条里也能看出流向。

### 读条过程

`form = smoothstep(ratio)`，`glow` 为前段慢、后段快的聚能曲线：

1. **起手**：地面主阵淡入，半径只张开 72%，颜色偏深；
2. **聚能**：阵上的符文/浪鳍逐段亮起，半径到 100%，水珠/潮墙/水笼/雨线长出来；
3. **临放**：`glow` 快速抬升，t3 起轻微蓝色暗角/底部水线；t4/t5 加重，t5 有低频心跳；
4. **释放**：地面阵淡出，补 3 圈向外扩的水环 + 水花，和实体阵接管之间不留空档；t3 起释放有轻微震屏，t4/t5 更明显。

低阶刻意不做：**潮墙**、屏幕压暗、屏幕水线、震屏、心跳（水缚低阶只留 4 根短水柱，
不是完整水笼）。这样水弹/水波 t1 不会每次都变成屏幕灾难；t3 才第一次出现潮墙/水笼、
轻微暗角和释放震屏，t4/t5 才是完整仪式。

### 屏幕与水线

`onRenderGui` 只叠**蓝青暗角**，不是光法的暖白过曝：

- 顶部/底部深蓝，边缘青色，透明度上限约 0.16；
- t4/t5 底部有一条缓慢起伏的水位线；
- t1/t2 完全不压屏。

### 粒子

- 四条链都改用 `ParticleTypes.FALLING_WATER` 为主；
- 水球链加 `SPLASH` 做水珠碎裂，水波链加 `BUBBLE`，雨链加 `RAIN`；
- 粒子间隔按 `ParticleStatus.MINIMAL` 降频；低阶粒子密度明显低于高阶；
- 不新增服务端包；读条阵由各客户端按 `SpellCast` 状态本地绘制，释放后的实体阵仍然所有人可见。

## 五、Boss 也吃到了同一套视觉

### 水系 Boss：利维坦

利维坦不走 SpellEngine 的 `SpellCast.Process`，而是自己的 `actionTicks` 蓄力。这里只加了
四个同步 int，不改 AI、伤害和技能选择：

| 同步字段 | 用途 |
|---|---|
| `CAST_REMAIN` / `CAST_TOTAL` | 客户端算蓄力比例，保证法阵和真实前摇对齐 |
| `CAST_VISUAL_TIER` | 水球/水缚招对应的视觉档位（基础球 t3，龙吼 t3，龙毁/海神墓 t5） |
| `CAST_VISUAL_FAMILY` | 1 = 水球链，2 = 水缚链 |

客户端 `WaterCastFx.scanBoss` 识别利维坦，画：

- 脚下半径 10.5–18 的 Boss 尺寸潮汐主阵；
- 嘴部（真实 `MOUTH_FORWARD` / `MOUTH_HEIGHT`）一张竖直潮汐印 + 外环，读作“口中聚水”；
- 水缚招走 `BIND` 分支，水柱/横环按 Boss 半径加粗加高；
- 释放后仍由原来的 `TNWaterFieldEntity` / `TNWaterSpellEntity` 实体接管。

海神剑（`sea_god_crypt`）的路径印也一并换成 `WaterGeometry.staticSeal`，不再在 64 格
落剑路径上露出旧方块阵。

### 光系 Boss：阿波罗

阿波罗也不走 SpellEngine：他有 `pendingSpell` / `pendingTicks`，原版是“动画播完才生效”。

## 八、已知边界

- 本轮的预览和测试都是离线验证；**尚未在实际客户端里逐档试玩**。如果游戏内出现
  阵太亮/太暗、月牙比例不合适、漩涡太细或旋臂挡住视线，优先调 `WaterGeometry.seal`
  里的 `alpha`、`sealCrescent` 的 `mid`、`sealVortex` 的 `armSteps/threads`，不要动
  `WaterSpellRules` 的伤害/半径。
- 单侧小阵/小兽是**玩家读条专属**：`CastState.playerCast` 控制；Boss 的
  `bossRitual` 只复用主阵和脚边小水波，不会出现小兽。如果实际觉得小兽太小/太快，
  优先调 `sideBeast` 的 `size`、`beastStart/beastEnd`，不要改 SpellEngine 的
  cast time。
- 侧阵位置是随机的，可能落在墙里/树里；当前没有做视线遮挡检测，只保证不穿玩家、
  不切地面。如果试玩时频繁穿墙，可把 `sideDistance` 收窄到 1.3~2.0，或只允许平贴
  姿态，但会牺牲“不同角度”的观感。
- 海神剑的 36/24 格天印和 64 格落剑路径印都已改用程序化 `staticSeal`；路径印数量/位置
  未动，只换了外观。`WaterSolidModels.seal` 现在只剩模型审计页在用。
- 利维坦和阿波罗的前戏是**客户端读同步字段**，没有新增服务端实体；其他玩家看到的是
  Boss 实体本身的动画 + 本地前戏，不额外发包。
- 阿波罗召唤的旧 `TNMagicCircleEntity` 仍在服务端生成（已提到 `STYLE_LIGHT_GRAND`），
  和新的客户端日轮主阵是两层；如果实际观感太厚，优先降它的半径/寿命，不要删客户端主阵。
- `WaterCastFx` 的世界层用 `RenderType.lightning()`（加色、无剔除），因此读条阵是
  发光叠加，不是实体遮光；和释放后的实体阵在观感上会有材质差异，这是故意的：
  读条是“聚能”，释放后才是“实体水”。
