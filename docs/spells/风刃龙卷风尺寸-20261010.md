### 4.2 间距怎么定（**"大一些"是个模糊词，我按尺寸反推**）

`PAIR_SEPARATION = 24.0 格`（两个漩涡**中心**的间距 ✓），**左右对称**摆在施法者前方 ✓。

**为什么是 24**：t5 的龙卷风宽 **15 格** ⇒ 两个中心离 24 格时，
**两团漩涡外壁之间还剩约 9 格空隙** ✓ —— 既能明显看出"是**两个**"✓，
又不至于各打各的、中间漏一大片 ✗。若按老的距离（几格）摆，两团会**糊成一坨** ✗，
作者就看不到"两个"了 ✓。

### 4.3 ★ 顺手修掉一个**会咬人的**连带问题：出生距离

龙卷风原来是**固定**站在施法者身前 `SPAWN_DISTANCE = 3 格` ✓。
现在 t5 的漩涡**宽 15 格** ⇒ **施法者会直接站在自己的漩涡正中间** ✗
（而且会被自己吐出来的 23.6 格大风刃的判定够到 ✗）。

⇒ 近侧外壁**刚好擦着施法者身前** ✓，档位越大自动站得越远 ✓。

## 五、★ 视锥剔除：**大模型必须自己报包围盒**（不然会"凭空消失"）

**这是本轮最容易漏的坑** ✗，而且**黑夜之手早就踩过** ✓
（`TNNightGripEntity#getBoundingBoxForCulling` 的注释里写着同一句话 ✓）。

**问题**：原版按**碰撞箱**做视锥剔除 ✓，而这两个新实体的碰撞箱只有 **1 格** ✗。
尺寸一上来（t5 风刃 23.6 格 / 龙卷风 15 格）⇒
**模型中心一划出屏幕，整片模型立刻消失** ✗（玩家会看到"风刃飞着飞着没了"✓）。

**修法**（两个实体都加 ✓）：

```java
@Override
public AABB getBoundingBoxForCulling() {
    return super.getBoundingBoxForCulling().inflate(sizeScale() * 0.6D);   // 风刃
}
```

龙卷风同理（`inflate(0.9375D * sizeScale())` = 外壁半径 ✓），
并把 `shouldRenderAtSqrDistance` 放宽到 **96 格** ✓（它很大，不该"远远地就没了"✗）。

> **为什么之前没暴露**：第四批的尺寸是 1.0/1.3/1.6 倍（最大 3 格）✓，
> 碰撞箱 1 格和它差得不多 ⇒ **勉强看不出来** ✗。**这轮把尺寸拉到 20 倍才把它逼出来** ✓。
