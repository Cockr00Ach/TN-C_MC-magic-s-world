# 领域法术第三轮：范围化

2026-11-08 · 作者：「领域我希望来点范围的那种效果」

前两轮（[雷霆与暗黑](领域法术-雷霆与暗黑-20261108.md) / [七系补齐](领域法术-七系补齐-20261108.md)）
的领域其实是"点名"：每隔几秒挑**一个**目标、在他脚下铺一圈、砸一下，圈只有 2~3 格。
这一轮把它改成真正的**范围** —— 三层一起上：

| 层 | 之前 | 现在 |
| --- | --- | --- |
| 常驻 | 无（领域只是个开关，站着不动什么都不发生） | **光环**：身边 7 格，每秒一跳 |
| 出手点数 | 1 个落点 | 最多 **3 个落点**（互相至少隔 2 格，不叠成一个圈） |
| 单次范围 | 2.0~3.0 格 | **3.0~4.0 格** |

---

## 1. 常驻光环（`DomainService.aura`）

每 **1 秒**（`AURA_INTERVAL` 20 tick）在玩家身边 **7 格**（`AURA_RADIUS`）内：

- 地上滚一圈本系粒子（16 颗，纯粒子、不生成实体 ⇒ 便宜）
- 范围内**所有敌人**掉 **1 点**魔法伤害（`AURA_DAMAGE`）
- 每两秒再染一次本系状态：

| 系 | 光环状态 | 效果 |
| --- | --- | --- |
| 雷 | 麻 | 移速 −1 档，0.6 秒 |
| 暗 | 黑雾遮眼 | 黑暗 2 秒 |
| 火 | 一直烧 | 每秒点燃 1 秒（= 持续着火） |
| 风 | 往外飘 | 每秒轻推 0.06 格（不击退，只是站不稳） |
| 水 | 潮湿 | 移速 −1 档，1.2 秒 |
| 土 | 沉重 | 移速 −2 档，0.6 秒 |
| 光 | 圣光标记 | 发光 2 秒 + **范围内所有玩家（含自己）每秒回 0.5 血** |

> 光环**不碰玩家**（`hittable` 一律排除 `Player`）—— PVP 时不会莫名掉血；
> 光领域是唯一的例外，它是**给**玩家回血的 ✓。

---

## 2. 一次点三个落点（`pickVictims`）

原来 `pickVictim` 只取排序后的第一个；现在 `pickVictims`：

1. 候选池 = 半径 16 格内、非友军、非玩家、活着的生物；
2. 优先「最近被玩家/队友打过的」（8 秒记忆），没有就取最近的；
3. 按"最近挨打"排序后依次取，**新落点必须离已选落点 ≥ 2 格**（`TARGET_SPACING`），最多 **3** 个（`MAX_TARGETS`）；
4. 每个落点各自铺警示圈、各自预警、各自结算 ⇒ 玩家看到的是**一片同时亮起来的地面**，而不是一个点 ✓。

七个落点同时亮起时，因为每个都有 3~4 格半径，重叠区域会吃到多次伤害 —— 这正是"范围"该有的手感 ✓。

---

## 3. ⚠️ 必须清无敌帧（这一轮抓到的真 bug）

原版受击后有 20 tick 无敌帧（`invulnerableTime`）：期间再受伤害，若伤害不高于上一次就**完全无效**。

光环是**每秒 1 点**的小伤害 —— 不清无敌帧的话：

```
t=0   光环打 1 点      → 目标获得 20 tick 无敌
t=5   玩家砍出 12 点   → 落在无敌帧里 ⇒ 被吞掉，只结算 0 点（还查不出原因）
```

所以领域的所有伤害都走 `applyMagic()`：**先 `target.invulnerableTime = 0` 再 `hurt`**，
等于"领域伤害不占玩家的受击窗口" ✓。这一条写进了闸门（源码里必须有 `invulnerableTime = 0`）。

---

## 4. 数值汇总（全部在 `DomainSpells` 顶部）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `AURA_RADIUS` | 7.0 格 | 光环半径 |
| `AURA_INTERVAL` | 20 tick（1 秒） | 光环节拍 |
| `AURA_DAMAGE` | 1.0 点 | 光环每跳伤害 |
| `AURA_HEAL` | 0.5 点 | 光领域每秒给玩家回血 |
| `MAX_TARGETS` | 3 | 一次最多几个落点 |
| `TARGET_SPACING` | 2.0 格 | 落点最小间距 |
| 单次半径 | 3.0~4.0 格 | 见下表 |

| 系 | 出手 | 间隔 | 预警 | 伤害 | 半径 |
| --- | --- | --- | --- | --- | --- |
| 雷 | 落雷 | 6.0 s | 1.1 s | 14 | **3.2** |
| 暗 | 黑雾 + 手 | 8.0 s | 1.1 s | — | **3.0** |
| 火 | 火柱 | 5.5 s | 1.0 s | 12 | **4.0** |
| 风 | 风刃 | 5.0 s | 0.7 s | 9 | **3.6** |
| 水 | 水浪 | 6.5 s | 0.9 s | 11 | **4.0** |
| 土 | 岩刺 | 7.0 s | 1.2 s | 13 | **3.6** |
| 光 | 圣光 | 7.5 s | 1.0 s | 10 | **4.0** |

粗算一个领域 30 秒的理论输出（单个敌人一直贴身）：
光环 30 点 + 5~6 次出手 × 单次伤害 ≈ **90~110 点**，对一群怪则按落点重叠翻倍。
90 秒冷却 ⇒ 平均每秒不到 1.3 点，属于"架势技"而不是"爆发技" ✓。

## 5. 闸门

`DomainSpellTest` **8 → 9 条**，新增 `domainsHaveAnAreaNotJustSinglePointHits`：

- 源码里必须有 `AURA_RADIUS` / `AURA_INTERVAL` / `AURA_DAMAGE`，且 `aura(player, domain)` 真的被调用（不然光环是死代码 ✗）
- 必须有 `MAX_TARGETS` / `TARGET_SPACING`（多落点 + 不叠圈）
- 必须有 `invulnerableTime = 0`（光环不许吞玩家的刀）
- 数值自检：光环半径 ≥ 6、光环伤害 > 0、节拍 ≥ 0.5 秒、落点 ≥ 2 个
- 七系的单次半径必须 **≥ 3 格**，且**小于**光环半径（不然光环没意义）

回归：`magic.*` + `warrior.*` 全量见 §6。

## 8. 线上崩溃修复（2026-11-08 04:35 作者报「学领域就报错了」）

**现象**：在魔法石「独立」页把鼠标移到领域法术上（或点它解锁），客户端直接崩，报告写 `Description: Rendering screen`。

**崩溃栈**（`crash-2026-11-08_04.35.39-client.txt`）：

```
java.lang.NullPointerException: Cannot invoke "com.tnc.tnc.magic.Element.cn()"
        because the return value of "SpellCatalog$Entry.element()" is null
  at com.tnc.tnc.client.MagicStoneScreen.effectSummary(MagicStoneScreen.java:495)
  at com.tnc.tnc.client.MagicStoneScreen.renderPanel(MagicStoneScreen.java:403)
```

**根因**：领域法术是「独立法术」——`element == null`（这样它们只出现在「独立」页、不进七元素 NBT 数组），
但 `effectSummary()` 在**没有手写介绍**时无条件 `entry.element().cn()`。
前两轮只做了雷/暗，它们的介绍键当时也还没写 ⇒ 鼠标一划就 NPE ✗。

**修了四处**（都是"空元素"这一类）：

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| `MagicStoneScreen.effectSummary` | 无条件 `entry.element().cn()` | 三支：有元素→「火系」；是领域→「焚天领域」；其它→「独立魔法」 |
| `MagicStoneLearning.describe` | `AFFINITY_TOO_LOW` / `OUT_OF_ORDER` 直接 `.element().cn()` + `maxTierFor(null)` | 新增 `elementName(entry)`（领域→该系名），这两支的空元素分支不再碰 `maxTierFor` |
| `ChantRules.words` 默认句 | `entry.element().cn()` | 空元素 → 「领域」 |
| `SpellCatalog.Entry.fullName` | 独立法术一律显示「独立魔法 · 无元素」 | 领域显示「**领域魔法 · 火**」（它是有元素的，只是不进七元素数组） |

**顺带补的文案**：`zh_cn` / `en_us` 各补 7 条 `spell.tnc.<domain>.description`，
把「只能选一个 / 需要该系亲和力 / 30 秒 / 90 秒 / 光环 / 每隔几秒 / 战士附伤与刀光」写进悬停说明 ——
以后即使某条介绍漏了，`effectSummary` 也不会再崩 ✓。

**闸门**（`DomainSpellTest` 9 → **11 条**）：

- `everyLineShownForADomainIsNullSafe`：七个 `Result` 全在领域法术上跑 `describe`，**任何一句出现 NPE 或字面 null 都判红**；
  另外钉住 `effectSummary` 必须有空元素分支、`fullName()` 必须写「领域魔法」而不能写「无元素」
- `everyDomainHasTooltipText`：`zh_cn` / `en_us` 都必须有 7 条领域介绍

**回归**：`magic.*` + `warrior.*` + `light.*` **382 用例 / 95 套件全绿**（04:44）。

**装机**：`mods/tnc-1.0.0.jar` = **200,647,178 B、SHA `C4AC55D9…9154E25`**（04:44:44 构建 / 04:44:55 装入，
装前 0 个 java 进程，回读逐字节一致，备份 `…jar.bak-20261108-044454`）；从实例包内确认
`assets/tnc/lang/zh_cn.json` 有 7 条领域介绍、`DomainService.aura` 在。

> 教训：**element 为 null 是独立法术的正常状态**，任何"给玩家看一句话"的地方都必须先判空。
> 这一轮把这条写成了测试，而不是再靠记忆。
