## 零、一句话

风系现在**没有身份**：15 个法术里 **10 个是"给自己挂 buff"**，5 个是"换个数值的风刃"（模型还借的是**雷球**）。它既不像雷那样"一瞬间"，也不像暗那样"夺取"，玩家体验是"喝药水 + 扔个球"。

本文给风系一个身份 —— **七元素里唯一的「反制系」**：它不跟你比伤害，它**决定谁站在哪、谁动得了、谁听得见**。

## 三、设计目标（四条不变量）

1. **位置 > 数值**：风的强度必须来自"站在哪、在不在动"，而不是堆属性；
2. **取消 > 制造**：风不产生新东西，它**带走**别人的东西（位置、动作、声音、锁定）；
3. **看得见**：风必须有画面 —— 现在 10/15 没图标、风球是看不见的粒子（现状是"没有画面"）；
4. **不撞车**：与上表六系的生态位不重叠；**尤其**别做成第二个雷系。

## 四、贯穿全系的机制：「风压」

**风系的伤害不看你在哪、打谁，看"谁在动"。**

| 条件 | 加成（建议起点，全部可调） | 为什么这么做 |
|---|---|---|
| 目标**在空中**（离地 > 1.5 格） | 风伤 **+40%** | ★ 作者自己的引擎家族里**就有这个机制**：`elemental_wizards_rpg:wind_updraft`「上升气流 —— **目标在空中时伤害更高**」✓ ⇒ **已被证明能在这个引擎里做** ✓，不是新范式 |
| 目标**本 tick 正在被推开**（`getDeltaMovement()` 非零且朝外） | 再 **+20%** | 风打的是"被吹着的人" |
| **施法者在移动 / 飞行中** | 风伤 **+20%**、风场半径 **+20%** | 站着不动放风 = 最弱；这正是「没人抓得住风」 |

**上限**：建议加算、封顶 **+80%**，避免"飞起来 + 被推 + 跑动"叠出离谱数值。
**落地**：一个 Java 机制，在 `impact` 结算**之前**读 `target.onGround()` / `target.getDeltaMovement()` / 施法者位移 —— 属本项目做过很多次的那类轻机制（同 `TNDarkHandMechanics` / `TNDarkAimMechanics` 的量级）。

> ⚠️ `PlayerTickEvent` 死活的记录在本仓**存在矛盾**（`黑夜之手_重做设计.md` §九-2 已记）。
> 落地时先用**一行日志**确认自己那条 tick 跑没跑，**别无脑照抄** ✗。

## 五、逐链设计

### 5.1 链 1「风速」→ 把"加移速"换成"**真位移**"

**现状**：5 档是"飞行时长 + 速度% + 风伤%"的数值阶梯 —— 机制正确（t4 起"解锁即永久飞行"是好设计，**别动**），但读感是**喝药水**。

| 档 | 法术（**id 不改**） | 现在 | 改成 | 理由 |
|---|---|---|---|---|
| t1 | `wind_field` 风场 | SELF + 起飞 5s | 不变（cd 15 → **10**） | "轻"的入门，够了 |
| t2 | `wind_speed` 风速 | 起飞 5s + 速 100% | **一步踏空**：朝视线方向**瞬移 8 格** + 起飞 5s | 风的位移应该是**位移**，不是 speed 属性 |
| t3 | `greater_wind_speed` 顶级风速 | 起飞 15s + 速 150% + 风伤 50% | 瞬移 **14 格** + 上述全部 | 同上 |
| t4 | `super_wind_speed` 超级风速 | 永久飞行 + 速 300% + 风伤 100% | 瞬移 **20 格** + 上述全部 | 同上 |
| t5 | `wind_god_descent` 风神降临 | 上述 + 无冷却 + 蓝耗减半 | 上述 + **飞行冲锋**：飞行中穿过敌人造成风伤 | 神级的爽点 = "**我飞过去，路就断了**" |

**★ 瞬移不需要任何新东西** —— 引擎 `TELEPORT` action 的字段，本项目**已经在跑通的闪现链里用过** ✓（`archive/blink-spell/blink_1.json`，`PROJECT-STATE.md` §4.5 记"已跑通，已归档"）：

```json
"action": {
  "type": "TELEPORT",
  "teleport": {
    "mode": "FORWARD",
    "required_clearance_block_y": 2,
    "forward": { "distance": 8.0 },
    "depart_particles":  [ { "particle_id": "minecraft:portal",         "shape": "SPHERE", ... } ],
    "arrive_particles":  [ { "particle_id": "minecraft:reverse_portal", "shape": "SPHERE", ... } ]
  }
}
```

⇒ 直接照抄字段，把 `depart/arrive_particles` 换成 `cloud` / `sweep_attack` 即可 ✓（`minecraft:portal` 那种末影感要换成风的颗粒）。

**风神降临现有的独占性**（不要弄丢）：无冷却（`TnSpellMechanics.java:916-924` 用 `WIND_GOD` 标记判，注释里写明"只有 5 级发它"）＋ 蓝耗减半（`SpellEngineManaHook.java:170-171`）✓。

### 5.2 链 2「风球 / 风灵」→ **真召唤物** ＋ **风灵是债主**

**先修硬伤**（见 §七-1），再换内核。

**(a) 实体化**
照两条**已验证**的路做真 `tnc:wind_spirit` 实体（能被看见、能被攻击、会自己飞过去打人）：
- `TNThunderOrbEntity`（真·绕身实体，已实机跑过，`当前状态.md` §二）；
- `TNDarkSummonEntity` + `TNDarkSummonChain`（暗系召唤真实体 + 就地铺法阵，五档五实体）。

**(b) ⚠️ 一条硬约束：`tickOrbs` 现在被暗系共用**
`TNWindMechanics.tickOrbs` 里有一段 `dark = has(player, DARK_ORB)` ⇒ 换 `SOUL_FIRE_FLAME` 粒子（`TNWindMechanics.java:185-189`）。

⇒ **动 `tickOrbs` 之前先确认 `dark_orb` 这条路还有没有活的调用方**：没有就整段退休，有就一起搬。
**别把暗系的召唤链带崩** ✗。

**(c) ★ 创意内核：风灵不完全听你的**
设定是「轻、散、**说话不算话**」—— 那机制上就该这样：

- 召唤时你**许诺**（例：t3「替我把这 30 秒打完」）；
- 风灵**自己去找最近的敌人**打，**不跟你的准星**；
- **到期结算**：没做到 ⇒ **反噬** —— 收走你的移速几秒（`gale_slow` 的自身版），然后散掉。
- 实现 = 一个计数器 + 到期判断（很轻）。

| t2 | `wind_orb_swarm` 召唤五个风球 | 5 个风球（绕身） | 25s | 5 | **无** |

### 5.5 领域魔法「无处」

**剧情提案**：领域内无法被固定 / 被围；加成 = 移速与击退抗性、风伤。
**落地（强推荐，因为它和刚做完的暗系「抓」形成漂亮对位）**：

1. **领域内所有"束缚类"状态快速衰减**（每 tick 扣时长）：水缚、蛛网、土环、各类减速，
   **以及我们自己的黑夜之手抓取（`tnc:night_grip`）**。
   ⇒ 「无处」= **没有"这里"，所以你抓不住我** ✓ —— 暗系刚学会"抓"，风系天生"抓不住"，这是设定级的对仗。
2. 自己**免疫击退与抓取**；
3. **领域不该有可见边界**（只有一圈很淡、不断流动的云 ＋ 进出时一声风）—— "没有这里"**不该有墙** ✓；
4. 可选（**神级奇遇奖励，慎用**）：领域内每 N tick 记录一次位置，**致死时回到最近记录点一次** ——
   "我不是在这里死的"。这条很强，建议只做奇遇奖励 + 长冷却。

**现状**：`TNSpecialMagic` 只做到"亲和力 × 5% → 学派属性"（`BONUS_PER_POINT = 0.05D`，5 秒刷新一次，用 transient 修饰符）⇒ 领域**本体**还没做，正是 `当前状态.md` 里"领域魔法 4.5/5"缺的那 0.5 ✓。

### 7.0 ⚠️ 动手前必须先做：**范围风那两个脚本是过期的，直接跑会退步**

这是我在核对时挖出来的**新问题**，比上面那些硬伤更危险 —— 因为铁律 §7.3 说"生成出来的文件要改就改生成器"，**而这两个生成器现在跑一遍会让情况变坏** ✗：

| 脚本 | 现状 | 跑它会发生什么 |
|---|---|---|
| **`tools/gen_tnc_wind_gale_spells.ps1`** | ① 写入目标是 `modpack\<包>\kubejs\data\tnc\spells`；② 模板里的模型号是 `"model_id": "tnc:projectile/sun_ray"` | ① 发货的五个 gale 文件其实住在 **jar 的 `src\main\resources\data\tnc\spells`**（`6b29d3af` 搬进去的）⇒ 跑它会在 kubejs 里造出**五个同名副本，按铁律 ③ 直接盖掉 jar 版本** ✗；② `assets/tnc/models/projectile/` 现有 12 个模型里**没有 `sun_ray`** ⇒ 跑出来的五个法术**全部紫黑** ✗ |
| **`tools/gen_tnc_wind_icons.ps1`** | 写入 `config\openloader\resources\TN-C\assets\tnc\textures\spell` | 这条路径**本项目已弃用**（`docs\法术专题_交接.md:56`），且 `:793` 记着"**`config/` 不在 sync 范围 ⇒ 图标没进实例**"的坑 ⇒ 很可能"生成了但游戏里没变" ✗ |

**证据**：`git log` 显示 `56a77813`（"**收工 —— 所有用模型的法术统一指向已验证可显示的 `lightingball`**"）与 `6b29d3af`（"把所有引用 tnc 投射物模型的法术从 kubejs 搬进 mod jar 的 `data/`"）—— **发货文件是后来被"统一指向 + 搬进 jar"两次收工改过的，而生成器没跟着改** ✗。
⇒ 这就是铁律 §7.3 的另一面：**产物被绕过生成器直接改过之后，生成器就成了陷阱** ✓。

**所以正确的动手顺序是**：先把这两个脚本**对齐现状**（目标路径改到 `src\...`、模型号改成实际发货值/新号、图标目标改到 `src\main\resources\assets\tnc\textures\spell\<法术id>.png`），**再**按 §7.1 重新生成 ✓。
