# 土法紫黑模型注册修复与实体龙卷风确认

用户反馈土法施法模型呈紫黑方块，并要求确认龙卷风恢复旧实体模型。读取当前 PCL 实例 `logs/latest.log`，发现 ModernFix 5.27.66 对八个 `tnc:projectile/earth_*#standalone` 模型报 `ModelMissingException`：它们被当作方块状态变体去读取不存在的 `blockstates/projectile/*.json`。上一版 `ModifyBakingResult` 的别名逻辑进一步将该缺失模型绑定到普通渲染 ID。此前仅验证注册清单与资产存在，未验证此动态加载兼容性，因此未能发现实机故障。

## 修复

- 新增 `TNDirectSpellModels`，将八个土法模型、`wind_tornado` 和 `windblade` 以普通 `ResourceLocation` 注册到 Forge `ModelEvent.RegisterAdditional`。模型从 `models/projectile/*.json` 直接加载。
- `TNModelBaking` 对上述十项跳过旧 `#standalone` 注册。其他既有模型的路径维持当前版本。
- 去掉土法 `#standalone` 别名写入，避免缺失模型污染普通 ID。
- 模型烘焙阶段记录实际普通 ID 与粒子材质是否缺失，输出 `TN-C/solid-models: Solid earth and original wind model bake validation: 10/10` 表示十个目标均通过。该记录需要重新启动客户端后确认，本次未将预期日志当作实测结果。

## 旧龙卷风确认

对实际安装底包与上一轮优化前底包，逐字节核对 `TNTornadoEntity.class`、`TNTornadoRenderer.class`、`wind_tornado.json` 和对应 PNG，全数一致。该模型包含 32 个实体方块元素，当前渲染器调用旧模型路径，没有调用程序生成的龙卷风曲面。本次补齐其普通模型 ID 的直接加载入口。

## 验证

四项测试通过，包括直接调用实际 Forge 注册事件，验证十个 key 均为普通资源 ID、无模型变体，并有对应资产；另外三项核对土法布局与粒子预算。发布包只覆盖三项模型注册类；所有其他条目保持底包内容一致，并再次核对旧龙卷风四项资源。
