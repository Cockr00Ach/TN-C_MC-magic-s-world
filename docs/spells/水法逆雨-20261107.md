# 水法读条前戏：逆雨（2026-11-07）

> 一句话：读条的时候，地上的水被**抽回天上**——雨是倒着下的。
> 之前那套「地面潮汐阵 + 四系法阵」整段保留在 `WaterCastFx.ritual()` 里，
> 由 `WaterReverseRain.ENABLED` 一个开关切换（现在是 `true`，即逆雨接管）。

## 1. 为什么这么做

水法原来读条时是"脚下亮起法阵、头顶聚一颗水球"。问题在于它和雷法、土法一样都是
**在地上画圆**，水只是换了个颜色，读条期间看不出"水"这个字。

逆雨能一眼立住水：

| 逆雨给的 | 它说明的事 |
| --- | --- |
| 水从地面往上走 | 水在**被收集**，不是被召唤出来 |
| 地面越来越干、水纹往里收 | 水是从脚底这片地里抽的 |
| 头顶越聚越厚的一片云 | 抽上去的水有去处，读条是在**攒** |
| 末尾那颗珠子往下压 | 攒满了，要放出去了；和出手那一下接得上 |

而且它是"雨"——玩家一秒就认识的东西，只把方向反过来。**认识的形状 + 反过来的方向**，
比重新设计一个别人没见过的水纹符号省力得多。

## 2. 时间轴：一滴水的一生

整个效果只有一条时间轴，没有第二套状态机：

```
cycle = frac(time × 0.045 × speed + 相位)       // 每滴水自己的 0→1
y     = cycle × 水柱高                          // ← 往上，不是往下
alpha = (1 - cycle)^0.55                        // 越低越实，越高越淡（被云吸掉）
半径  = 基础半径 × (1 - 0.28 × cycle)            // 越高越往中间收
```

`cycle = 0` 在地面，`cycle = 1` 在云里。**这正是它和普通下雨唯一的不同**：
`y` 随 `cycle` 涨。`WaterReverseRainTest.dropletsTravelUpwardsInsteadOfFalling`
就是钉这一条的——它把 0→1 采样 21 个点，要求严格单调上涨。

## 3. 四层结构（`WaterReverseRain.draw`）

| 层 | 内容 | 数字 |
| --- | --- | --- |
| 地面 | 一片暗蓝湿痕 + 一圈青边 | 半径 `R×1.15`，湿痕 α `.26` |
| 起点 | 6 处水纹**倒着收** + 一颗离地水珠 + 5 根离地小水冠 | 半径随 `cycle` 从 `.95` 收到 `.55` |
| 主体 | `110 + 34×档` 条水线，每条两片交叉四边形 + 一截亮"头" | t5 共 280 条 |
| 终点 | 10 团软水堆出来的云 + 亮芯 + 3 条旋臂 + 6 缕下垂水 | 云高 `4.6 + 1.05×档` 格 |

## 4. 让它"读得出方向"的三个细节

静止画面里，竖直的水线和普通下雨**长得一模一样**（这是画预览图时发现的）。
所以加了三样只有逆雨才有的东西：

1. **亮头**：每条水线最上面 30% 那一截单独加亮（α×1.85、宽×1.35）。
   雨滴"头在下面"，逆雨的"头在上面"——一眼就能分。
2. **离地水冠**：每处起水点有 5 根朝上的短刺。水是被"拔"起来的，不是溅起来的。
3. **云**：普通下雨的雨来自看不见的天；逆雨的水来自头顶**你看着它长出来**的那团云。

## 5. 实现位置

- `src/main/java/com/tnc/tnc/client/WaterReverseRain.java`（新，约 260 行）：纯几何，无状态、无实体。
  入口 `draw(out, pose, tier, ratio, radius, time)`，读条进度只决定亮度和云的大小。
- `WaterCastFx.ritual()` 开头新增一个分支：`ENABLED` 时画逆雨 + 侧边门，然后 `return`；
  旧的地面潮汐阵和四系法阵整段留在下面（改一个常量就能退回）。
- `WaterCastFx.tickParticles()`：`water_rain` 那条链原来的「从天上下落」粒子改成**从地面向上**
  （`vy = +0.30~0.65`），否则粒子和几何会对冲。
- 渲染阶段、缓冲类型、颜色常量和 `WaterCastFx` 完全一致（`AFTER_WEATHER` + `RenderType.lightning()`），
  不额外 `endBatch`，不新增渲染层。

## 6. 没动的

- 侧边的门 / 回声门 / 蓝金水渊兽残影：它们和"水往上走"不冲突，保留。
- BOSS（水渊兽）的读条：`bossRitual()` 里先调 `ritual()`，所以 BOSS 也会用逆雨，
  半径按 BOSS 的 `info.radius()` 放大；嘴前那圈竖法阵保留。
- 读条时长、伤害、服务端逻辑：一行没改。

## 7. 验证

- `WaterReverseRainTest` 4/4：向上、档位越高越高越密、往上越淡越收、进度越高越亮。
- 预览图 `docs/spells/水法逆雨-model.png`：`tools/reverse_rain_model.py` 按同一份几何在 CPU 上重画
  （t5，读条 25% / 60% / 95%，同一台相机）。
- **这不是游戏截图**。真正的判断标准是动起来那 20 帧：水线往上走、云在头顶长大。
