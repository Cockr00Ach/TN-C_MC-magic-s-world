# 水法海神剑：法阵先行 → 水渊兽沿曲线升空 → 化作发光虚影消失 → 巨剑落下（2026-11-07）

作者原话（附手绘航线图：玩家在右，红线先向外弧形冲出、再折向上方 `top`，线上画了几段蓝色线圈）：

> **「他是这么个行走路线，头是要对着方向的不是单纯平移，然后要飞到很高的天空再消失，
> 然后要先出现一个法阵，再出现巨剑，那我觉得这个boss的虚影也可以发着光因为巨剑是发着光的」**

补充确认（本轮开工前问过）：

- 升空方式：**本体沿曲线飞上去，到高空化作发光虚影消失，再落巨剑**；
- 法阵：**起飞点地面一个阵 ＋ 高空落剑阵提前亮**；
- 虚影：**一直发光**（不是一闪一闪，也不是只在淡出那一瞬亮）。

本轮**只动海神剑（`sea_god_crypt`）这一条链的表现**：伤害 60、26 格领域、64 格巨剑、
64 格落程、140 tick 命中、8 把连发（Boss 只 1 把）、200 tick Boss 仪式时长**全部没动**。
玩家自己放 t5 冥穴时天阵也会提前 2.4 秒亮（同一个 `SeaGodSwordVisuals`），但没有升空虚影那一段。

## 一、需求拆成五件事

| # | 作者要的 | 落地位置 |
|---|---|---|
| 1 | 走的是画里那条“先外冲、再拔高”的曲线，不是直线平移 | `TNWaterLeviathanEntity.beginAscent/climbAscent`（二次贝塞尔） |
| 2 | **头要对着飞行方向**，不是单纯平移 | 曲线切线 → `yaw`（水平）＋ `xRot`（俯仰）逐 tick 写回实体 |
| 3 | 飞到很高的天空再**消失** | 到站后 `CAST_GHOST` 0→40，客户端整具模型自发光淡出 |
| 4 | **先出现法阵，再出现巨剑** | 起飞点地面阵（Boss 渲染器）＋ `SeaGodSwordRules.SEAL_TICK=52`（比剑早 48 tick） |
| 5 | Boss 虚影**一直发光**，因为巨剑是发光的 | 虚影期换 `entityTranslucentEmissive` ＋ `FULL_BRIGHT` ＋ 符文层同亮 |

## 二、服务端航线：二次贝塞尔，先平飞后拔高

旧代码是 `moveRitualToward(channelPosition)`：每 tick 朝终点做一次速度插值，
**从原地直接斜着平移上去**，而且 `setXRot(90F)` 让它整段爬升都保持“低头 90°”——
这正是作者说的“单纯平移、头没对着方向”。

新代码在 `beginChannel`（只对 `TNWaterFieldEntity` 的仪式，即海神剑）里建一条二次贝塞尔：

```
P0 = 起飞位置（beginChannel 时的 position）
P1 = P0 + dir × out + (0, rise, 0)      // dir = 朝目标的水平单位向量
P2 = 天阵站点（skySealCenter + 嘴部偏移，与旧版完全一致）
out  = clamp(水平距离 × 0.45, 9, 26)
rise = clamp(|Δy| × 0.025, 1.5, 6)     // 只抬一点点：起点切线≈水平，终点切线≈竖直
```

- 采样：`ascentPoint(t) = (1-t)²P0 + 2(1-t)t·P1 + t²P2`，`ascentTangent(t)` 是导数；
- 节奏：`ascentStep = 1 / clamp(路径长/3.4, 26, 40)` ⇒ 整段 **34~40 tick** 爬完 100~150 格；
- **起飞前 10 tick 不走**（`ASCENT_DELAY`）：法阵先亮、巨兽已经抬头瞄准天空，然后才离地；
- 位移仍走 `move(MoverType.SELF, delta)`，巨兽碰撞体照旧参与，只换目的地；
- 到站判定：`t>=1` 或与站点距离 < 0.6 格，随后 `setPos(站点)` 对齐。

## 三、朝向：切线 → yaw / xRot / 渲染俯仰

`climbAscent()` 每 tick：

```
n     = tangent.normalize()
yaw   = atan2(-n.x, n.z)                 // 与 MC 的 yaw 约定一致
pitch = -degrees(asin(n.y))              // 正数=低头；爬升 n.y>0 ⇒ 负值=抬头
setYRot/setYHeadRot/setYBodyRot(yaw); setXRot(pitch);
entityData.set(CAST_PITCH, pitch)        // 客户端渲染读这一份
```

- `castingPitch(partial)` 新增 `castPose()==2` 分支：**升空段用 `CAST_PITCH`**（跟着切线），
  不再返回 `90×castTilt`；到站 `castPose()==3` 仍是 `90×castTilt`（低头吐剑）；
- `tick()` 里 `castTilt` 的爬升条件从 `pose==2 || pose==3` 收紧成 **只有 `pose==3`**，
  否则升空段会被它按成低头；
- 到站那一下把切线末端的俯仰**直接灌进 `castTilt`**（`castTilt = endPitch/90`）：
  模型从“仰头 70° 爬升”平滑翻成“低头 90°”，不会一帧瞬移；
- `applyRotations` 不变（`-pitch` 绕 X），所以渲染出来的头就是朝航向的。

## 四、到站化虚影：一直发光，然后消失

服务端只同步一个 int：`CAST_GHOST`（0 = 本体，40 = 完全不可见）。

- 到站瞬间置 1，之后每 tick +1 到 `GHOST_TICKS=40`（2 秒），正好在 `APPEAR_TICK=100` 的巨剑前收干净；
- 实体**仍然留在天阵上**（碰撞、站位、`mouthOpen()`、`aperturePosition` 全部不变，
  原有“嘴对着天印”的断言照旧成立），只是客户端不再画实体本体；
- 虚影表现（`boss/client/TNWaterLeviathanRenderer`）：
  - `getRenderColor` → `Color.ofRGBA(1,1,1,ghostAlpha)`，逐顶点 alpha 淡出；
  - `getRenderType` → **`RenderType.entityTranslucentEmissive`**：自发光着色器，不吃环境光 ⇒
    “一直在发光”，洞里/夜里都一样亮；
  - `actuallyRender` → 光照强制 `LightTexture.FULL_BRIGHT`，颜色压成偏冷蓝（R×0.72 / G×0.94 / B×1.12）；
  - `TNWaterLeviathanEmissiveLayer`（额冠/眼/鳞缝那层）alpha 乘同一个 `ghostAlpha`，跟着一起淡；
  - `render()` 在 `ghostAlpha<=0.01` 时直接 return，省掉一次 76 格巨兽的骨骼遍历。
- **回程反向淡入**：仪式结束（200 tick）后本体从天上飞回玩家身边，`tickSkyReturn` 按
  “剩余路程 / 起始路程”把 `CAST_GHOST` 从 40 线性降到 0 —— 不是落地那一帧“啪”地出现。
  存档恢复时若正处于回程，也保持虚影直到落地（`readAdditionalSaveData`）。

## 五、法阵先行

### 5.1 起飞点地面阵（Boss 专用）

`TNWaterLeviathanRenderer.drawLaunchSeal`：第一次进入 `castPose()==2` 时锁定当时的
`position()` 作为起飞点，之后在**那个点**（不是跟着兽跑）画一张半径 **11 格**的水法阵，
8 tick 淡入、70 tick 内淡出。几何不另写：新增 `client/WaterRitualSeal.launch(...)`
这个唯一的公开入口，内部就是玩家读条脚下那套 `WaterGeometry.richCircle(..., 2, 3)`
（主阵 ＋ 2 个卫星子阵），所以 Boss 阵和玩家阵是同一套画法。

### 5.2 高空落剑阵提前亮

`SeaGodSwordRules` 新增：

```java
SEAL_TICK   = APPEAR_TICK - 48;   // 52 tick：比巨剑早 2.4 秒
sealVisible(age) = 52 <= age < END_TICK + 8;
sealOpacity(age) = min(1, min((age-52)/14, (END_TICK+8-age)/22));
```

`SeaGodSwordVisuals` 的两座天印（半径 36 / 24）改用 `sealOpacity`，
**巨剑仍按 `visible(age)`（100 tick）出现**——于是读起来是“阵先铺开 → 兽升空消失 → 剑才出现”。
Boss 那 5 道 12 格一道的落剑路径印（`pathSealOpacity`）仍从 100 tick 起，它们属于剑的下落轨迹。

## 九、未实机验证（重要）

本轮**没有做客户端画面验收**（没有启动游戏、没有截图）。以下必须在实际整合包里看：

1. 升空曲线是否真是“先外冲再拔高”，还是看起来仍然像斜线（控制点 `out/rise` 在
   `beginAscent` 里，两个数就能调）；
2. 头是否真的朝航向：如果出现“侧着飞/倒着飞”，先查 `pitchFor/yawFor` 的符号，
   再看 `applyRotations` 是否被别的东西二次旋转；
3. 虚影是否**一直亮**：如果只是一层半透明蓝、不发光，说明 `entityTranslucentEmissive`
   在这个整合包（Oculus/Embeddium）里被替换了着色器，退路是把虚影改走
   `WaterRenderTypes.glow()` 的加色自绘；
4. 虚影消失得是否干净：`GHOST_TICKS=40`，若在 100 tick 还能看到残影就调小；
5. 起飞点那张 11 格阵是否被地形/水面挡住、是否与脚下主阵打架；
6. 回程淡入是否自然（按剩余路程比例，若觉得太早出现就把 `returnStartDistance` 的基准改成固定值）。

**改这些只需要动表现参数**：`ASCENT_DELAY`、`beginAscent` 里的 `out/rise/3.4`、
`GHOST_TICKS`、`LAUNCH_SEAL_RADIUS/TICKS`、`SeaGodSwordRules.SEAL_TICK`。
伤害、半径、落剑高度、命中 tick 一律不要碰。
