# 光法：施法前戏 ＋ 光污染（2026-11-05）

> 作者原话：
> 「我想你来改改光魔法，关于光魔法的东西，先从特效入手……学习他们那种光效制作和法阵的光效制作，
> 让我感受到光污染，然后我们的内容不是每次就一个法阵吗，我希望有更多的小法阵和更久的施法前戏，
> 让我能感受到暴风雨的前夕的感觉」
> 追加：「这些特效在游戏里的体积一定要和现在的大小差不多，甚至更大，只要你有足够细节」

本轮**只改光系的视觉与读条时长**：治疗量、减伤、范围、冷却、天使数量/血量/伤害、飞行规则一律没动。
涉及三条链：**光耀 `light_grace`**、**召唤天使 `light_summon`**、**光线 `light_beam`**。
光镜链（`light_mirror`）没有接这套前戏，避免影响它原本的 0.4 秒节奏。
光线链 t4/t5 本来就有 1.2/1.6 秒读条，这次接上阵；t1~t3 是瞬发前射，**保持 0 秒**
（`LightMirrorRulesTest` 钉死了“前射光线不能有读条”这条不变量，否则光镜反射的脉冲节奏会被打断）。

> 光系所有阵样的统一规范（地面 / 竖立 / 天阵 / 小阵 / 光龙 / Apollo）见
> [光法阵规范](光法阵规范-20261105.md)；守门测试 `LightSealStyleTest`。

## 1. 观感目标：从「一个阵」到「一场仪式」

旧版流程只有两步：读条 1~1.4 秒 → 脚下突然出现**一张**阵。
新版把读条本身做成仪式，分三层：

| 阶段 | 读条比例 | 玩家看到什么 |
|---|---|---|
| **压云** | 0% ~ 45% | 屏幕上下 + 左右收暗（`darkVignette`），主阵的辅助环先出现，外环从 0° 开始“描” |
| **点灯** | 6% ~ 75% | 小阵按档位 2~8 颗依次点亮（t1 只有 2 颗、无伴生环；t3 起每颗头顶升起竖立伴生环，竖环开始绕身转） |
| **过曝** | 30% ~ 100% | 天空落下 10 道“光雨”，暖白光晕从四周溢进屏幕，核心/光柱/8 向光芒加速增亮，心跳式震屏越来越密 |
| **释放** | 100% | 白闪 + 震屏 + 几何爆发环/迟到余波/光柱 + 服务端主阵/小阵/粒子一起炸开 |

“暴风雨的前夕”靠的是**先暗、再一点点亮、最后爆**，而不是全程都很亮。

### 但低阶不是缩小版高阶（2026-11-05 追加）

作者看完第一版后说：「法阵要是每个都是一样的施法方式就不好看了，低级和高级应该是有区别的」。
所以上表描述的是 **t4/t5 的“天穹降临”**；t1/t2 的“铭刻”没有压云、没有光雨、没有竖环：

| 档位 | 读条时看到什么 | 释放 |
|---|---|---|
| **t1/t2 铭刻** | 一张干净的地面符（6/8 道符文、6/8 道光芒）＋ 2/3 颗贴地小阵；没有竖环、没有光柱、屏幕不暗 | 阵亮一下、6 道星芒、很小的一簇粒子；不震屏 |
| **t3 圣所** | 主阵满配 ＋ 4 颗小阵（各带一枚竖立伴生环）＋ 2 道绕身门环；轻微暗角、一次心跳、细光柱 | 白闪 0.42、轻震 1.4°、金色烟花 |
| **t4/t5 天穹** | 6/8 颗小阵、4/6 道门环、满档暗角/心跳/光柱/盘旋光带/脉冲环/光雨 | 白闪 0.58/0.70、震屏 2.6/3.8°、光柱与粒子全开 |

读条/释放**手部动画**也按档位换了：t1 单手托光、t2 单手聚球、t3 单手举天、
t4 双手引导、t5 双手旋转 —— 不再六个法术都用同一个 `one_handed_area_charge`。

## 2. 尺寸：只大不小

| 元素 | 旧版 | 新版 |
|---|---|---|
| 主阵半径 | 法术范围（8 / 10 / 12 / 14 / 16 格） | **不变**，仍是法术范围 |
| 主阵外沿 | 贴图半径 = R | 几何外环到 **1.16R**（日冕光芒到 **1.02~1.24R**） |
| 小阵 | 无 | **2~8 颗**（t1 2、t5 8），半径 1.0~2.8 格，分 0.42R / 0.66R 两圈 |
| 竖环 | 无 | 读条时 **0/0/2/4/6 枚**（t1/t2 没有）；t3 起释放后背后再留 **1/2/3 枚** 2.4~2.8 格光环 |
| 光柱 | 无 | 主阵中心高 **1.6 + 0.30R**，封顶 7 格；前 1.5 秒最亮 |
| 召唤链 | 无阵 | 主阵 3.5~4.6 格 ＋ **每只天使脚下 1.2~1.6 格小阵** ＋ 落地时一根 **~11 格高粒子光柱** |
| 光线链 | 无阵、无枪口光 | 起手也有主阵/小阵；玩家射出的光线在眼前炸一簇枪口光；光系撞墙散的是**光**（END_ROD/FIREWORK/ELECTRIC_SPARK），不再冒火 |

所以不会出现“为了细节把阵缩小”的情况：所有新细节都叠在原有半径之上。

## 3. 代码结构

| 文件 | 作用 |
|---|---|
| `light/LightRitualSequence.java` | **纯算术规则**：小阵数量、点亮顺序、成形曲线、过曝/暗角、心跳、释放强度。不引用 Minecraft，可直接 JUnit |
| `client/LightCastFx.java` | **读条渲染 + 粒子 + 屏幕效果 + 释放爆发**；检测所有玩家的 `SpellCast.Process`，不额外发网络包 |
| `client/ElementSealRenderer.java` | 释放后持久法阵的几何：日冕、三层环、24 符文、8 小阵、八角星、中心核、光柱；支持竖阵 |
| `light/TNLightChainMechanics.java` | 释放瞬间铺 **主阵 ＋ 3~7 小阵 ＋ t3 背后光环**；召唤链每只天使脚下一枚小阵；服务端粒子 |
| `client/TNSpellClientVisuals.java` | 新增 `pulseFlash()` / `pulseShake()`，光系白闪/震屏复用爆炸那套衰减 |
| `data/tnc/spells/*.json` | 10 个光系法术的 `cast.duration` 拉长 |

### 为什么读条特效放客户端

SpellEngine 会把 `SpellCast.Process`（施法者、法术、进度）同步给附近客户端，所以：
- 不需要新增实体，也不需要 `SimpleChannel` 包；
- 附近玩家也能看到你的读条仪式（不是只有自己）；
- 释放后的持久法阵仍由服务端生成，**所有人都能看见**。

### 兼容

- 引擎类型只出现在 `LightCastFx#scanUnsafe`，外层有 `ModList.isLoaded("spell_engine")` 与
  `try/catch Throwable` 兜底；开发环境没有 SpellEngine 时整类静默闲置。
- 世界空间几何用 `RenderLevelStageEvent.AFTER_WEATHER` ＋ 独立 immediate `BufferSource` ＋
  `RenderType.lightning()`，与 `PortalRitualRenderer` 相同 —— 不受 Oculus 的 `endBatch` 影响。
- 风系 `WindSolidModels` 分支原样保留。

## 5. 可调旋钮

### 读条节奏

`LightRitualSequence`：
- `satelliteSeals(tier)`：小阵数量（现在 `2 + tier`，t1=3、t5=7）
- `gateRings(tier)`：竖环数量（2/2/3/4/5）
- `satelliteIgnition(tier, index, progress)`：第 i 颗从 `0.06 + 0.50*i/(n-1)` 开始，用 0.18 的读条淡入
- `formation(progress)`：主阵描边曲线（smoothstep）
- `chargeGlow(progress)`：`p^1.7`，想更早亮就改成 `p^1.3`
- `darkVignette(progress)`：前 55% 的压暗，想更压抑把 `0.85` 调大
- `heartbeatTicks/Shake`：后期心跳震屏的密度与强度

### 几何

`LightCastFx`：
- `LIGHT_GROUPS`：哪些法术组接前戏（现在 `light_grace`、`light_summon`、`light_beam`）
- 调色板 `W_R/W_G/W_B`（暖白）、`G_R/G_G/G_B`（金）、`C_R/C_G/C_B`（冷白）
- `ritual()` 里 `range` 直接取 `spell.range`，**不要**写死半径
- 顶点预算：单个施法者读条约 3.6k quads；主阵约 1.9k、小阵约 120

`ElementSealRenderer`：
- 外圈光芒 `rays = 20`，长度 `1.08~1.24R`
- 主环 `r`、`0.962r`、`0.895r`，晕环 `1.16r`、`1.03r`
- 符文 24 道、内嵌小阵 8 颗、辐条 8 根
- 光柱高度 `min(7, 1.6 + 0.30r)`，`age < 90` 后淡出

### 屏幕

`LightCastFx#onRenderGui`：
- 暗角 `alpha = darkVignette * 58`，上下渐变 + 左右各五级竖条收边
- 整屏暖白 `alpha = lightWash * 24`，上下渐变 `* 26`，左右四级暖白溢光 `* 18`
- 如果觉得晃眼，优先降这两个系数；`pulseFlash` 的白闪强度在 `LightRitualSequence.releaseFlash`

### 读条后段的两处“雨”

- `core()` 里的 `光雨`：10 道交叉光丝从 5.4 格高落下，`p > 0.30` 开始；
- `burst()` 里的“迟到余波”：主环散掉前 0.2 秒再推一圈冷白环（`age > 4`），听起来像雷声滚过去。
- 嫌多就把 `streaks = 10` 降到 6，或把余波的 `0.35F` 降到 `0.2F`。

## 6. 验证

### 离线

```powershell
cd D:\ModTest
.\gradlew.bat test --tests "com.tnc.tnc.light.LightRitualSequenceTest"
.\gradlew.bat build
```

`LightRitualSequenceTest` 钉死这些不变量：
- 小阵数量按档位严格增加：t1=2、t2=3、t3=4、t4=6、t5=8（低阶故意不铺满一圈）；
- 成形/点亮/过曝都是时间单调；
- 暗角在 55% 归零，避免和过曝打架；
- 心跳周期只减不增、强度只增不减；
- 白闪 0.38~0.70、震屏 1.5~4.3 度；
- 小阵角度不重叠、轨道不跑出主阵。

### 游戏内

1. 创造模式拿光系法杖/法术书，先放 t1 看：读条时脚下只有主阵 + 2 颗贴地小阵、
   **没有竖环/光柱/屏幕压暗**；再放 t5 对比：应有 8 颗小阵 + 6 道门环 + 满档光雨；
2. 再放 t5（3.8 秒）：应能看到 7 颗小阵依次点亮、头顶核心/光柱、屏幕先暗后亮；
3. 释放瞬间：白闪、震屏、地面主阵（半径 16）＋ 7 颗小阵 ＋ 背后光环；
4. 召唤链 t4（15 只天使）：主阵 + 15 个落点小阵，注意帧数；
5. 用另一名玩家/旁观视角确认**别人施法也能看到读条仪式**。

> 如果只看到释放后的阵、看不到读条仪式：先确认 `spell_engine` 已加载、法术组名是
> `light_grace` / `light_summon`，再看日志有没有 `TN-C/lightfx: cast scan failed`。

## 7. 性能

- 单个读条施法者约 **3.6k quads**（≈ 14k 顶点），主阵释放约 **1.9k quads**；
- `LightCastFx` 只画 96 格内的施法者，每帧共用一个 1 MB `BufferBuilder`；
- 粒子每 tick 每人 6~14 个，粒子设置 `MINIMAL` 时砍半；
- 召唤链 t4 的 15 个小阵是最重的一次（≈ 1.8k quads），仍在可控范围；
- 若低配机器掉帧，优先把 `ElementSealRenderer` 里 `miniSeal` 的 8 颗降到 6 颗，
  或把 `LightCastFx` 的 `motes` 系数从 2 降到 1。
