## 一、范围风五档换模型（`lightingball` → `windblade`）

**改前**：五个 gale 法术的 `model_id` 全是 `tnc:projectile/lightingball` ——
**"风刃"看起来是一个黄色雷球** ✗，最终尺寸只有 **0.19 ~ 0.53 格**（比一只鸡还小 ✗）。

**新模型**：**作者自己的龙卷风** ——
`<整合包>\config\openloader\resources\Elemental Awakening\assets\elemental_wizards_rpg\models\effect\tornado.json`。

| 我核过的合规项 | 结果 |
|---|---|
| 方块数 | 14 ✓ 轻量 |
| 旋转角 | **全是 0** ⇒ 没有非法角 ✓ |
| `from/to` 范围 | x −1.5..17.5 · y **−2.5..32** · z −1.5..17.5 ⇒ **在加载窗口 −16..32 之内** ✓（y 顶到 32 的上边界，**别再整体上移** ✗）|
| 实际尺寸 | **1.19 × 2.16 × 1.19 格**（比 `lightingball` 的 0.375 格大 **5.76 倍**）|
| x/z 包围盒中心 | (8, 8) 单位 —— **正好是本项目的对外约定**（`CustomModels.render` 会 `translate(-0.5,-0.5,-0.5)`，`dark_fog` 用的也是这个基准 ✓）|
| UV | 0..16 ✓（导入脚本会自动验，>16 直接报错）|

**导入**：`tools/import_author_model.ps1` —— 本次给它加了**多贴图模式**（见第 2 节），命令：

```powershell
powershell -ExecutionPolicy Bypass -Command "& 'tools\import_author_model.ps1' `
  -Json '<...>\tornado.json' -Name windblade `
  -Textures @('<...>\storm_layer_1.png','<...>\storm_layer_2.png','<...>\storm_layer_3.png',`
              '<...>\storm_layer_4.png','<...>\storm_layer_5.png')"
```
> ⚠️ 必须用 `-Command "& '…'"` 形式：`powershell -File` 会把**逗号列表当成一个字符串** ✗
> （本次实测踩到：`-Textures a,b,c` 被当成单个路径）。**中文路径也别走嵌套 powershell** ✗（代码页会改字）——
> 本次是先把源文件拷到 ASCII 暂存目录再导入的 ✓。

**落地**：
1. `TNProjectileModels.PROJECTILE_MODELS` 加 `WINDBLADE`（唯一的模型清单 ✓，`TNModelBaking` 直接读它）；
2. `tools/gen_tnc_wind_gale_spells.ps1` 的模板模型号改成 `tnc:projectile/windblade` → 重新生成（**铁律 §7.3**）✓。

**尺寸**：五档的 `scale` **故意沿用原值**（0.5 / 0.7 / 0.9 / 1.2 / 1.4）——
模型大了 5.76 倍 ⇒ 风刃从 **0.19~0.53 格** 变成 **1.08~3.02 格**高 ✓
（"**巨型**风刃风暴"终于真的巨大了 ✓）。要调就改生成器最后那张表的 scale 一列 ✓（那里写了换算公式）。

**朝向**：沿用 `"orientation": "TOWARDS_MOTION"`。**反编译核实过**（`SpellProjectileRenderer`）：
枚举只有 `TOWARDS_CAMERA` / `TOWARDS_MOTION` / `ALONG_MOTION`，而后两者走的是**同一段代码** ——
只施加 **yaw（`atan2(dx,dz)`）＋ pitch（`asin(dy)`）**，两者只差 **90° yaw**
⇒ 这个**竖直柱体在水平飞行时保持立着** ✓（俯冲/上抛才跟着倾），
而且 90° 的差别对这种旋转对称的柱体**没有可见差别** ✓ ⇒ 沿用现值最稳。

## 二、`import_author_model.ps1` 新增多贴图模式

**为什么要加**：这个模型用了 **5 个贴图槽**（`storm_layer_1..5`），而脚本原来把
**所有裸贴图槽都指向同一张** ✗ ⇒ 直接跑会 5 个槽全指向一张图，模型必然画错。

**改了什么**（**只在传 `-Textures` 时走新路，旧行为一字不改** ✓）：
- `-Textures <每槽一张的数组>`：槽 `"0"` → `<名字>_1`、`"1"` → `<名字>_2` …（`particle` 槽 → `_1`）；
- **多贴图模式下每个槽都重写**（含**已经带命名空间**的值 —— 作者的龙卷风指向的是
  `elemental_wizards_rpg:spell_effect/storm_layer_N`，旧逻辑只认"裸名字"⇒ 会直接报
  `no bare-name texture slot found` ✗，本次实测踩到 ✓）；
- **`.mcmeta` 自动一起拷** ✗ 关键：这 5 张是 **16×128 = 8 帧竖排的动画贴图**
  （`frametime: 5`），少了 `.mcmeta` 动画就没了；
- 打印里加了 `texture mode` 一行，一眼能看出走的是哪条路 ✓。

**验证**：导入输出确认 14 个方块、`bbox blocks 1.1875 x 2.15625 x 1.1875`、
`uv range 0..16`、5 张全部 `(+ .mcmeta, animated)` ✓；jar 内 5 张 PNG ＋ 5 个 `.mcmeta` 都在 ✓。

## 四、★ 闸门覆盖缺口：拆开两张清单（并在负向测试里证明堵上了）

**原来**：`verify_mod_jar.ps1` 里 `$spellIds` **一个数组干两件事** ——
① 逐法术的资产检查（json / 图标 / 效果 id / SPAWN 实体 / area 硬规则），
② 要求 `data/tnc/spell_assignments/magic_wand.json` **必须列全**。

而那个数组里风系**只到链 1**，注释写着"其余 10 个等 json 存在再加" ✗ ——
**它们的 json 早就存在了**，于是那 10 个法术**落在所有检查之外**：
这就是"**10 个法术没有图标**"能一直绿灯的原因 ✓（我上一批是**手动**发现并修的 ✗）。

**为什么我没有顺手把它们加进 `magic_wand.json`**（那会立刻让闸门变红）——
我先把"那张表到底管不管施法"查清了：

| 证据 | 结论 |
|---|---|
| `SpellEngineBridge.orderedSpellIds()` 是**运行时**按 `SpellCatalog` ＋ 已解锁 ＋ 引擎注册表算槽位，写容器时 `is_proxy = false`（源码注释："容器的 spell_ids 就是权威，快捷栏直接读它"）| 快捷栏读的是**运行时算出来的那份** ✓ |
| `magic_wand.json` 里**只有 58 个** tnc 法术：雷15＋火15＋**风5**＋光13＋暗10 | **水 20 ＋ 土 20 也不在里面**，而这两系文档写着"✅ 4/4 全部可玩" ✓ |
| ⇒ 那张表**显然不决定能不能施法** | 它是**法杖物品的默认（proxy）容器内容**，不是"我们的法术登记表" ✓ |

⇒ 所以**正确做法不是往那张表里塞 10 个 id**（那是改一个我证明不了语义的运行时数据文件 ✗），
而是**把闸门那两件事拆开** ✓：

- `$spellIds` = **资产覆盖清单**（在原有基础上**加进风系链 2/3 的 10 个**）；
- `$wandListedIds` = **`magic_wand.json` 期望列出的那份**（保持原样，注释写明为什么它与上面不同）；
- 顺手修掉那句过期的 `Ok "… lists all 15 spells"`（现在按实际条数打印）。

**★ 负向测试**（证明"堵上了"，而不是"看起来绿" ✓）：

```

  [PROBLEM] pack is missing spell icon: wind_orb        ← ★ 以前这一条**不会**出现 ✗

```
