# 法术平衡：什么该瞬发、什么该蓄力，以及冷却

> 作者 2026-11-07：**「然后我现在希望你开始调平衡吧数值冷却时间这块，什么技能该瞬发，什么技能该蓄力，你考虑一下」**
>
> 这一轮动的是 140 个法术 JSON 里的两个数：`cast.duration`（读条秒数）和
> `cost.cooldown_duration`（冷却秒数），外加把引擎的 `cost.exhaust` 全部清零。
> **伤害系数、动画、音效、粒子一个都没碰** —— 手感和节奏可以再调，伤害要动的话是另一件事。

---

## 0. 先说结论（三句话）

1. **瞬发是特权，只给"晚 0.1 秒就没意义"的两个位置**：闪现/位移、以及光线链的前三级。
   其余 133 个法术一律 ≥0.35 秒，顶档大招 2.0~2.5 秒。
2. **同一条链必须逐级变重**。旧数据里火/暗/水/地/风是"一档到底"——t1 和 t5 都是 0.6~0.8 秒、
   冷却还只差几秒 ⇒ 高级招纯粹是"伤害数字变大"，手感完全一样 ✗。
3. **冷却按"这一招值多少"给，不按"作者当时想写多少"给**。基础攻击 0.5 秒（蓝耗才是闸门），
   越高级越久，召唤/大招 20~140 秒；光系是"一锤定音"，长冷却保留。

## 1. 四条原则

| # | 原则 | 反面（这一轮修掉的） |
| --- | --- | --- |
| 1 | 瞬发=反应类：位移、逃命、指哪打哪的射线 | `lightning_field`（雷场）1.0 秒读条没问题，但**冷却 0.5 秒**等于常驻 ✗ |
| 2 | 同链逐级变重 | `dark_fog` 五档全是 0.8 秒；`earth_ring` 五档全是 0.6 秒 |
| 3 | 高级招的冷却必须比低级长 | `heavenly_thunder`（t5 大招）冷却 **0.5 秒**，`spark`（t1 基础攻击）也是 0.5 秒 ✗ |
| 4 | 蓝耗只有一个来源 | 引擎 `exhaust` 0~1.0 与魔法石的 `Config.manaCostForTier` **同时扣费** ✗ |

### 1.1 为什么"瞬发"不能滥用

引擎的规则是：非瞬发法术**必须按住到读条满**才放得出来（`ManaGate` 里那段"哑火"注释就是
踩过这个坑记下来的）。所以读条时长 = **给对手的反应窗口**。全给瞬发，战斗就退化成比手速；
全给长读条，战斗就变成站桩。**只有"我不该被骗到"的招才配瞬发。**

## 4. 前后对照（挑最明显的）

### 4.1 主链（基础雷法）：读条本来就对，冷却全是 0.5 ✗

| 档 | 法术 | 读条 | 冷却（旧 → 新） |
| --- | --- | --- | --- |
| t1 | 小闪电 | 0.5 | 0.5 → **0.5**（基础攻击，不罚） |
| t2 | 雷场 | 1.0 | 0.5 → **2** |
| t3 | 雷击 | 1.5 | 0.5 → **3.5** |
| t4 | 雷暴 | 2.0 | 0.5 → **6** |
| t5 | 天打五雷轰 | 2.5 | 0.5 → **10** |

> 这就是"天打五雷轰怎么想放就放"的根因：2.5 秒读条 + 0.5 秒冷却，只要蓝够就是连发。
> 现在 10 秒冷却，蓝耗（t5 = 100 点，见 `Config.manaCostForTier`）还是主要闸门。

### 4.2 暗/地/水/风：一档到底 → 有坡度

| --- | --- | --- | --- | --- |
| 黑雾 `dark_fog` | 0.8 ×5 | 0.55 → 1.25 | 2.5/4/6/9/13 | 不变 |
| 暗手 `dark_hand` | 0.6 ×5 | 0.45 → 1.15 | 2/3/4.5/7/11 | 不变 |
| 暗召唤 `dark_summon` | 0.7 ×5 | 1.0 → 2.2 | 12/16/25/35/60 | 不变 |
| 换命 `dark_sacrifice` | 0.7 ×5 | 0.5 → 0.7 | 15/20/30/45/90 | 不变 |
| 地刺 `earth_move` | 0.7 ×5 | 0.5 → 1.2 | 3/4.5/6.5/9/14 | 不变 |
| 泥沼 `earth_mud` | 0.8 ×5 | 0.5 → 1.2 | 3/4.5/6/8/12 | 不变 |
| 地环 `earth_ring` | 0.6 ×5 | 0.5 → 1.2 | 12/16/22/30/40 | 不变 |
| 地弹 `earth_shot` | 0.6 ×5 | 0.45 → 1.1 | 1.5/2.5/4/6/10 | 不变 |

> **越高级越快**。现在 t5 = 1.2 秒。

### 4.3 光系：读条太长（3.8 秒）→ 收到 2.4 秒以内

| 链 | 旧读条 | 新读条 | 冷却 |
| --- | --- | --- | --- |
| 治疗/祝福 `light_grace` | 1.8 / 2.2 / 2.7 / 3.2 / 3.8 | 1.2 / 1.5 / 1.8 / 2.1 / 2.4 | 8/10/14/18/24 不变 |
| 召唤天使 `light_summon` | 1.8 / 2.0 / 2.4 / 2.8 / 3.2 | 1.2 / 1.5 / 1.8 / 2.1 / 2.4 | 30/40/60/90/140 不变 |

> 3.8 秒读条在实战里等于"打不出来"—— 读条越长越容易被打断/被躲。
> 光系的"一锤定音"由**冷却**（最高 160 秒）体现，不需要靠读条来拖。

### 4.4 引擎扣费清零

`cost.exhaust` 从 0~1.0 全部改成 **0**：引擎那套 exhaustion 与魔法石的蓝耗是两套系统，
同时生效会让人"莫名其妙就饿了/放不出来"，而且数值互相对不上。现在**唯一的蓝耗**是
`Config.manaCostForTier(tier, maxMana)`（按上限等比放大，见那个方法的注释）。

## 5. 刻意**不动**的链（附理由）

| 链 | 现状 | 理由 |
| --- | --- | --- |
| 雷锲 `thunder_seal` | 0.45→1.6，5→22 | 上一轮刚调过，坡度已经是对的 |
| 雷球 `orb` / 火球 `ball` / 射线 `ray` | 0.5→2.5 | 老链的基准曲线 |
| 风球 `wind_ball` / 风刃 `wind_weapon` | 0.72→1.2，4→20 | 同上 |
| 光线 `light_beam` | 0 / 0 / 0 / 1.2 / 1.6，16/36/60/100/160 | 前三级**就是**瞬发射线；长冷却是设计 |
| 光镜 `light_mirror` | 五档全 0.4 / 4 | 兑换的是"效果"不是"节奏"，五档同参数是有意的 |
| 飞行 `flight` | 0.4 ×5，15→90 | 起飞要"点了就走"，读条长了没法用 |
| 燃烧 `burn` | 0.6 ×5，20→120 | 是姿态（切换），不是攻击 |
| 雷速 `speed` | 0.4 / 0 / 0.6 / 0.5 / 1.0 | 链里混了"加速"和"瞬移"两种定位，读条本来就不该单调 |
| 闪现 `blink_1..3` | 0 / 0 / 0，6/9/12 | 位移本来就该瞬发 |
| 隐匿 `concealment` / 乱魔 `chaos_magic` | 0.6/90、0.3/10 | 独立魔法，不参与元素平衡 |

## 6. 闸门：`SpellBalanceTest`（7 条，全过）

文件：`src/test/java/com/tnc/tnc/magic/SpellBalanceTest.java`

| 测试 | 钉住什么 |
| --- | --- |
| `theWholeSpellBookLoads` | 140 个法术都能解析；档位 1~5；冷却 0.5~180 |
| `onlyEscapeSpellsAreInstant` | 读条 0 秒 ⇒ 必须在白名单（位移/光线）里；白名单里的必须真的 0 秒 |
| `castingWeightDoesNotGoBackwardsWithTier` | 同链读条不得倒退（`speed` 例外） |
| `cooldownsGrowWithTier` | 同链冷却严格变长（`speed`/`light_mirror` 例外） |
| `topTierAttacksActuallyChargeUp` | 攻击类 t5 读条 ≥ 1.1 秒 |
| `theEngineNoLongerChargesItsOwnExhaustion` | `cost.exhaust` 全 0 |
| `eachChainHasOneSpellPerTier` | 同链同档恰好一个（学习/替换规则依赖） |

**变异验证**（闸门真的会红，不是摆设）：把 `heavenly_thunder` 临时改回 `duration: 0` +
`cooldown_duration: 0.5`，重跑后 **4 条红**：

```
cooldownsGrowWithTier:      primary：t4「lightning_storm」冷却 6.0 秒，t5「heavenly_thunder」只有 0.5 秒
castingWeightDoesNot...:    primary：t4「lightning_storm」读条 2.0 秒，t5「heavenly_thunder」却只要 0.0 秒
topTierAttacksActually...:  t5 攻击「heavenly_thunder」（primary）读条只有 0.0 秒
onlyEscapeSpellsAreInstant: 「heavenly_thunder」是瞬发，但它是攻击/场/召唤
```

**顺手修掉一个静默跳过**：只改 JSON 不动 java 时，Gradle 会把 `test` 判成 `UP-TO-DATE`，
这些读数据文件的闸门根本不会跑 ✗。已在 `build.gradle` 的 `test` 任务里登记两个法术目录为
`inputs.dir`（见那次改动旁边的注释）。

## 7. 怎么改 / 怎么验

数值表就在 **`tools/spell_balance.py`** 顶部（`CAST` / `CD` / `GROUP` / `OVERRIDE`），
它就是设计稿；改完跑：

```bash
python tools/spell_balance.py --report   # 打印整张表（每条链 t1..t5）
python tools/spell_balance.py --check    # 只报告差异，不落盘
python tools/spell_balance.py --apply    # 三个目录同时改（jar 资源 / 数据包镜像 / 实机数据包）
```

工具只改 `cast.duration`、`cost.cooldown_duration`、`cost.exhaust` 这三个数，
**其余字节原样保留**（包括每个文件各自的 CRLF/LF 混排 —— 写回时按原样，不做换行归一）。
