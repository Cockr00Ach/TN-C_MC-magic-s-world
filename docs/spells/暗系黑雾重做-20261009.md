### 2.2 表现：四层粒子 + 一个穹顶 + 一圈边界

**粒子**（每档都从包里的**真·黑雾**粒子取，不再是原版烟）：

| 层 | 粒子 | 形状 / 位置 | 干什么 |
|---|---|---|---|
| 底（贴地沼泽） | `block_factorys_bosses:ink_fog` | `CIRCLE` / `FEET`，`extent = 半径`，速度 **0.005~0.05** | 墨黑雾摊在地上 —— "雾是液体"的那一层 |
| 体（中段） | `block_factorys_bosses:fog_1` | `SPHERE` / `CENTER`，`extent = 0.75×半径` | 柔化穹顶的方块边 |
| 点（魂火） | `minecraft:soul`、`block_factorys_bosses:soul`（t3 起） | `SPHERE` / `CENTER` | 往上飘的青色余烬（三层里唯一的亮点） |
| 壁（边界） | `ink_fog` | `CIRCLE` / `CENTER`，`extent = 1.05×半径` | 一圈薄雾墙，就算不看地面法阵也看得出边 |
| 火（t2/t4 起） | `soulsweapons:black_flame`、`minecraft:soul_fire_flame` | `CIRCLE` / `FEET` | 贴地鬼火 |

> ★ **`extent` 的真实语义（这次从字节码里确认的）**：对 `CIRCLE / CONE / SPHERE`
> 三种形状，`ParticleHelper.offset` 都是 `dirVector × (distance + radius)`，
> 也就是 **`extent` 是"离中心的距离倍率"**，不是别的 ✗ —— 所以"环半径 = 半径"
> 就是写 `extent = radius` ✓。（老文档里"`extent` 单位是不是格"那个存疑点，这条解决了 ✓）

**穹顶**（`tnc:projectile/dark_fog`）：引擎的 `CLOUD` 自带一个**模型渲染槽**
`release.target.cloud.client_data.model` —— `SpellCloudRenderer` 会把它喂给
`CustomModels.render(...)`，**和投射物渲染器同一个函数** ⇒ 走的是本项目**已验证**的
模型通道 ✓。**在这条链之前，全项目 108 个法术一个都没用过这个槽** ✓。
模型由 `tools/gen_dark_fog_model.py` 程序化生成：三层抖动方块环（外薄里厚）＋ 顶盖
＋ 十几块"余烬"，85 个方块，贴图 64×64 程序画 ✓。

- **几何约定（最容易做错的一处）**：`CustomModels.render` 先 `translate(-0.5,-0.5,-0.5)`
  ⇒ **模型底边正好落在实体位置上**。所以这个模型 **x/z 以 (8,8) 单位为中心、
  底边压在 y=8**，而且**故意不做**投射物那种"居中到原点" ✗（雾是贴地一层，不能悬空）。
- **尺寸**：模型宽 2.25 格 / 高 0.73 格（scale 1 时）⇒ 法术里写
  `scale = 0.4 × 半径` ⇒ 穹顶占地 ≈ 0.9×半径、高 ≈ 0.3×半径 ✓。
  ⚠️ **第一版写了 `scale = 半径`**（按"模型半宽 16 单位"算的 ✗）⇒ 实测预览里
  方块把**整个领域盖满**、还把边界法阵挡掉了 ✗ ⇒ 改成 0.4×半径（穹顶是**核心**，不是领域本身）。
  想更大/更小**只改这一个数** ✓（`tools/gen_dark_fog_spells.py` 的 `DOME_SCALE`）。
- **`rotate_degrees_per_tick: 0.25`** ⇒ 慢慢自转，雾看起来在翻涌 ✓。
- **不设 `light_emission`** ⇒ 保持暗（要发光就加 `"light_emission": "RADIATE"` ✓）。

**边界法阵**（`tnc:magic_circle` 新样式 `STYLE_DARK = 2`，贴图
`assets/tnc/textures/entity/dark_circle.png`，由同一个生成器画出：外圈亮紫 = 
"你正在离开雾"那条线，内圈暗紫符文 ＋ 24 个刻度 ✓）：

- 半径 = **雾的真实半径**、时长 = 雾时长 + 1 秒 ✓ ——
  半径取的是 `volume.combinedRadius(...)`，**和引擎结算伤害用的是同一个算法** ✓
  （所以"看到的圈"和"吃伤害的范围"永远一致）；
- 位置：施法那一刻铺在脚下（往下找一层非空气方块 ✓），之后**每 tick 跟着雾走** ✓。

### 2.3 机制（Java 侧两处 + 一个自己的减益）

| 项 | 位置 | 说明 |
|---|---|---|
| **雾跟着施法者走**（t3 起） | `magic/DarkFogCloudEntity`（**引擎 `SpellCloud` 的子类**）| 法术 JSON 写 `"entity_type_id": "tnc:fog"` ⇒ `SpellHelper.placeCloud` 用 `create(level)` 造出**我们的**类（再强转成 `SpellCloud` ✓）。t1/t2 原地（当控制/封路），t3 起跟随，t5 再绕着自己慢慢转 ✓。生成后先**定住 10 tick**再开始跟（让 `force_onto_ground` 那步修正生效、也让"铺开"看得出来）✓ |
| **边界法阵的生成与托管** | `magic/DarkFogMechanics` | **引擎的事件不是 Forge 总线** ✗ —— `CombatEvents.SPELL_CAST` 是 `net.spell_engine.api.event.Event`，要 `SPELL_CAST.register(listener)` ✓（挂 `@SubscribeEvent` 编译不报错、运行时静默不触发 ✗）。只在 `RELEASE` 铺阵（`CHANNEL` 每 tick 都发事件，会在蓄力里铺一堆 ✗）。判据是 `spell.group == "dark_fog"`，**不写死五个 id** ✓ |
| **`tnc:dark_veil` 暗雾侵蚀** | `magic/TNEffects` | 换掉借来的风系 `gale_slow` ✓：**减速 15% ＋ 虚弱 10%**，颜色暗紫 `0x4A2C6E`（同时决定 HUD 图标底色与身上粒子色 ✓）。amplifier 0/1 两档（t1~t3 用 0，t4/t5 用 1）✓ |
| **站在自己雾里的增益** | 五档 `impact`（`apply_to_caster: true`）| t2 加速 5 秒 / t4 加速 8 秒 / t5 再加力量 —— 原设计里"2、4 级自己加速"这次真的做出来了 ✓ |

> ⚠️ **1.20.1 的一个 API 坑**：`MobEffect(MobEffectCategory, int)` 是 **protected**、
> 而且**没有** `setCategory` ✗ ⇒ "减益"只能从构造器传进去。所以
> `TNEffects.AttributeBuff` 加了一个带 category 的构造器 ✓。
