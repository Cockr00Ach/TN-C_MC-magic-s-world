# 风系前戏（法阵 + 风灵入体）与风灵 / 风球模型重做 — 2026-11-07

作者原话：

> 来改改风，改改法阵，加上前戏和优化一下风灵风球模型

风系是最后一个没有"施法前摇"的元素：水（倒抽雨水）、光（日轮阵）、雷（三张小阵）、暗（墨线阵）、土（地裂缝合）
读条时脚下都有东西，只有风系读条时**什么都没有** —— 法阵只在技能已经打出去、`WindEarthVisualEntity`
生成之后才出现 ✗。这一轮补上前戏，同时把风系最旧的两份美术（120 元素的方块 `wind/seal` 阵、
"纸扇风灵"、'乱铁丝'风球）重画。

本轮**只动客户端表现**：伤害、半径、档位、`WindChainRules` / `WindEarthVisualRules` / `WindArsenalRules`
一行没改；队友的 `WindArsenal*` / `WindChain*` / `WindEarth*`（除几何文件本身）一个文件没碰。

## 1. 法阵：从"两个同心圆"到"风涡阵"

### 1.1 旧版的问题

`WindEarthGeometry.spell()` 的风系分支（kind 0/1/2）只有三样东西：两道 `ring()` + 一圈 `feathers()`。
俯视就是一个**双环 + 花瓣**，和土系的裂环、水系的漩涡放在一起，"风"完全读不出来 ✗；
而且风系释放后的实体阵（`WindSolidModels.seal`）走的是 `models/wind/seal.json` 那个
**120 元素的方块模型** —— 一块一块小方块贴出来的阵，边缘是台阶状的，和程序化几何放在同一屏里格格不入。

### 1.2 新版：`WindEarthGeometry.windSeal(...)`

新增一个统一入口（`spell()` 的风系分支和 `WindSolidModels.seal()` 都调它，前戏也调它 —— 见 §2）：

```java
static void windSeal(VertexConsumer body, VertexConsumer glow, Matrix4f m,
                     double r, double time, float alpha, int tier, Ground ground)
```

七层结构，全部程序化（`N = 48`，按角度分段）：

| 层 | 内容 | 读感 |
| --- | --- | --- |
| 1 | 3 段**断口外弧**，半径 `.985~1.012r`，宽 `.030→.004` | 外圈不是死圆，有风蚀的缺口 |
| 2 | 3 条**顺时针主螺旋臂**（每臂 18 段，半径 `.14→.99r`，宽 `.085→.008`，扫 `.78π`） | 主要形状：向内收的旋风 |
| 3 | 3 条**逆时针细臂**（14 段，扫 `-.62π`） | 与主臂对撞，产生"双向涡" |
| 4 | 12（tier<4）/ 16 条**羽状刻痕**（4 段，从 `.50/.58r` 到 `.95/.84r`，`-.16` 弧度卷曲） | 羽毛 / 风纹 |
| 5 | 3 段反向**眼弧**（`.30/.225/.15r`，扫 `1.25π`） | 阵心不是空洞，是一颗转动的眼 |
| 6 | 8 段中心扇点（`.08r`，抬高 `y+.052`）+ 8 段虚线内环（`.46r`） | 中心亮点 + 刻度感 |
| 7 | `tier>=3` 额外一圈**低语环**（`1.075r`） | 高阶阵往外再扩一层 |

配色沿用风系既有三色：薄荷 `(147,226,222)`、珠白 `(199,235,229)`、淡青 `(198,240,238)`；
`body` 走普通混合、`glow` 走加色层。

单阵顶点数（`WindEarthGeometryTest` 实跑）：

| 档位 | 释放阵（kind=2 gale） | 前戏 / 场地阵（kind=1 summon，含旋风） |
| --- | --- | --- |
| t1 | 1 448 | 1 960 |
| t3 | 1 512 | 2 280 |
| t5 | 1 576 | 2 664 |

测试上限 6 500，余量充足。图：`docs/previews/wind-seal-20261107.png`（上排 = kind 0 飞行风场，
下排 = kind 2 疾风阵，三列 = t1/t3/t5；这是顶点 dump 的离线俯视图，不是游戏截图）。

### 1.3 `WindSolidModels.seal()` 改走同一份几何

```java
p.pushPose();
var m = p.last().pose();
float grow = (float) Math.min(1D, alpha * 3D);
WindEarthVisualBuffers.draw(b, (body, glow) ->
        WindEarthGeometry.windSeal(body, glow, m, radius * grow, age, alpha, 3, WindEarthGeometry.FLAT));
p.popPose();
```

调用点两个：`ElementSealRenderer`（`STYLE_WIND` 的圆形阵）和 `WindChainRenderers`（风球链的瞄准阵，
半径 `tier==5 ? 34 : 5+tier`）。`models/wind/seal.json` 与 `draw("seal", …)` 注册**保留**
（`world/wind/client/CanglanWarlordRenderer` 还在用），只是不再用于玩家法术阵。

> 关键约束：**前戏的阵、释放后的阵、链的瞄准阵，三者是同一份几何**。这样读条时看到的花纹
> 在技能打出去之后是"接着长"，而不是"换成另一个法术"。

## 2. 前戏：`client/WindCastFx.java`（新文件，约 620 行）

和水/光/雷/暗/土同一套骨架：`@Mod.EventBusSubscriber(modid = TNMod.MODID, value = Dist.CLIENT)`，
静态 `@SubscribeEvent` 挂在 `TickEvent.ClientTickEvent`（END）、`RenderLevelStageEvent`
（`Stage.AFTER_WEATHER`）、`RenderGuiEvent.Post` 上，只画 immediate 几何，
**绝不生成实体**（服务端不同步、会留在存档里、会被清除指令带走）。

### 2.1 状态与读取

- `WIND_GROUPS = {"wind_ball", "wind_weapon"}` —— 只认这两组的法术（t1~t5 全含）。
- 每个玩家一个 `CastState`：档位、`Family`（BALL / WEAPON）、`ratio`、`maxRatio`、位置、`lastSeen`、`nextBeat`。
- 进度只从 `SpellCasterEntity#getSpellCastProcess()` 的 `SpellCast.Process.progress(now).ratio()` 读，
  不做任何服务端交互；`scan` 整体包在 try/catch 里，出错一次就 `scanBroken = true` 关掉这套前戏并写
  `TN-C/windfx` 日志，绝不把客户端带崩。

### 2.2 画面（按读条比例生长）

| 阶段 | 内容 |
| --- | --- |
| 全程 | 脚下 `windSeal`，半径 `(2.4 + tier×0.48) × (0.45 + 0.55×charge)` —— **从半个阵长到满阵**，t5 满尺寸约 4.8 格 |
| 全程 | 3 条上升气流（`WaterGeometry.spiral`，从 `0.62r` 起，高 `1.15+tier×0.30`） |
| 全程 | `8 + tier×2` 条风羽沿螺旋线往胸口收（`.30 → 1.05+tier×0.06` 格高） |
| 全程 | 胸口 `y = 1.12` 一圈风环（吸气感） |
| BALL 家族 | 2~3 颗绕阵的小球（tier≥4 多一颗），各自带一层珠白光环 |
| WEAPON 家族 | `3 + tier` 道扫刃光，从 `1.25r` 扫到 `0.90r` 再收起 |
| 后段 | 1~3 只**风灵**（`ratio ≥ .30 / .20`）从侧后方沿贝塞尔飞进胸口，`p > .90` 淡出 |
| 释放瞬间 | `Dive` 爆发：地面 3 圈扩散环 + 4 段上升风柱 |

低档不压屏、不震屏；t4/t5 才有心跳推镜（`TNSpellClientVisuals.pulseShake`）和一层极淡的屏幕青雾
（`fill` alpha ≤ 12/255 + 两条渐变带），和雷系白闪、暗系压暗、水系压蓝区分开。

### 2.3 风灵虚影：`client/WindSpiritGhost.java`（新文件）

借**真模型**渲染，不手搓四边形：从 `TNOrbEntities.WIND_SPIRIT` 造一个 dummy（`create(level)`，
不进世界）、`setSilent/setInvulnerable`、`previewTier(5)` 固定成高阶形态（t1/t2 的风灵在游戏里
渲染成一颗风球，前戏要的是"风灵本体"），取 `mc.getEntityRenderDispatcher().getRenderer(dummy)`
强转 `GeoRenderer<T>`，对 `model.topLevelBones()` 调 `renderRecursively(...)`，
`RenderType.entityTranslucentEmissive` + `LightTexture.FULL_BRIGHT`，整体带 `.88, 1, .97` 的薄荷偏色，
尺寸 `.45~1.8` 格按档位与进度缩放。

模型/渲染器不可用时（装了别的模组、GeckoLib 改了 API）走 `spiritWisp` 兜底并在 `TN-C/windghost`
写一次日志后永久关闭，不会每帧刷屏。

配套：`TNWindSpiritEntity.previewTier(int)`（新的 public 方法，**只在客户端虚影/预览用**，
服务端实体绝不能调）。

## 3. 风灵模型重做（`assets/tnc/geo/entity/wind_sprite.geo.json` + 贴图）

生成器：`tools/rework_wind_spirit.py`（新的权威生成器，写完直接覆盖 geo 与 64×64 贴图；
`gen_wind_sprite_model.py` / `refine_wind_models.py` 是前两版，不要再跑它们覆盖这一版）。

### 3.1 旧版的问题

- 7 片翅膀**全在同一个竖直平面**里、只绕 Z 转 ⇒ 正面一把纸扇、侧面一块板（没有后掠、没有分层）；
- 头是一个 4.5³ 方块，没有口鼻、没有眼神；冠是 3 根竖直小棒；尾巴是 3 片往下掉的小板；
- "光环"是两根金条；
- 翅膀骨挂在 `root` 上，身体悬停时翅膀不跟着上下（现在挂 `body`）。

### 3.2 新版结构（15 根骨骼 / 49 个方块，骨骼名全部保留）

保留 `idle` 动画引用的 `body / wing_left / wing_right / crest / tail / tail_left / tail_right`，
一个都没删（删了 GeckoLib 静默不动或直接崩），新增的只是方块位置与旋转。

- **翅膀**（每侧 10 块 + 2 根末端小羽）：1 块肩羽 + 6 根**初级飞羽**（长 `7.6→3.5`，
  yaw `-9°→-51°` 后掠，roll `17°→12°` 上反）+ 4 根**覆羽**（更短、更高、盖住羽根），
  每根都绕自己的羽根 pivot 转 ⇒ 扇动时是整只翅膀张合；
  末端 2 根小羽挂在 `wing_left_lower` / `wing_right_lower` 上，随翅膀骨一起摆。
- **头**：3.8×3.4×3.8 头骨 + 口鼻 + 眉脊 + 两只独立"眼"材质（前脸才会画到眼，其余面用身体色）。
- **胸**：一颗风精核心（`gem` 材质），配 `entityTranslucentEmissive` 会自己发亮。
- **冠**：3 根往后上方掠（`-42°/-38°`）的羽。**尾**：3 根往后下方拖的流苏（`-50°/-46°`）。
- **飘带**：原来的两根金条换成 4 段镀金飘带（肩后拖出去），和风系法阵的金线同一个色系。

### 3.3 贴图

仍是 64×64，但改成"**材质色板 + 逐面 UV**"：7 个小色板（feather / body / crest / gold / eye / gem / shadow）
各画一条竖向渐变（feather 还带 5 px 一道的羽枝横纹、gem/eye 有中心辉光），
每个方块的 6 个面直接指向对应色板 —— 任意尺寸的方块都不会出现"没画到的透明像素"。

### 3.4 离线自检图

- `docs/previews/wind-sprite-20261107.png` —— 3/4 视角、正面、侧面（`idle t=0.10`）；
- `docs/previews/wind-sprite-flap-20261107.png` —— 正面/侧面 × `t = 0.10 / 0.25 / 0.40 / 0.60`，
  确认扇翅在 `t=0.25` 摊平、`t=0.10/0.40` 上举，没有翻面、没有互相穿插。

这两张是 `tools/preview_geo_anim.py` 的离线渲染（这个工具本轮补了"逐面 UV"支持），
**不是游戏内截图**。

## 4. 风球重做（`client/WindConstructModels.java#orb`）

旧版：内核 + **3 层随机倾角（35°/85°/135°）的 cage**（互相都不垂直 ⇒ 一团乱铁丝）+ 2 道同角度的收缩环
+ 一圈**平躺在同一个水平面**的月牙刃（远看是一条扁扁的旋转木马）。

新版（绘制次数几乎不变）：

1. **内核两层反向自转**（一层 α=.90，一层缩到 .82、α=.34）⇒ 球心自己在搅；
2. **三条大圆经线**互成 60°、**全部立起来**（X 90°），交替正反转 ⇒ 才读成"球"；
3. **赤道环**反向转，与经线十字交叉；
4. **两道收缩碎环**一上一下（±82°）对称收进来；
5. **月牙刃**分到 3 个倾角（0°/38°/76°）的轨道面 ⇒ 包住整颗球；
6. 整体 **±2% 呼吸缩放**，静止时也不像一块死模型。

## 6. 还没做的 / 最可能需要微调的三处

1. **没进客户端实看**。以上全部是离线渲染 + 编译 + 单测 + 装机校验；前戏在真游戏里的亮度、
   风灵入体的时机、t5 满阵 4.8 格会不会太大，都要试玩才知道。
2. **风灵的头仍偏"机器人"**：它是方块低模，眼睛是一条横带。如果作者觉得还是太机械，
   下一版可以把头压扁 15%、眼睛换成两颗更小的竖点。
3. **风球**：三条经线 + 赤道环在 `t1` 时方块模型本身很小（`scale .80`），可能读成"一颗带环的小球"，
   如果不够"风"，可以给 `arsenal/core.json` 换一张更亮的贴图。
