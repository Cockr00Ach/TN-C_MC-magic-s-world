# 土法石化武器：把现成武器模型重绘成土/石材质

日期：2026-11-05（第四轮土法表现，21:08 修复紫黑方块后重装）

## 思路

不新做模型，直接把项目里现成的 17 把 3D 武器模型复制一份，重绘成石/土材质，作为土神的枪的飞行体、爆点小岩柱，以及巨柱升天时柱身外侧插出来的兵器。这样一套土法里能看到剑、刀、戟、镰、锤、长柄、锏等一整套“石化兵器”，体积也比原来的细土柱更大。

## 生成方式

`tools/gen_earth_weapons.py`：

1. 从 `block/earth_amber_stone.png` 下采样出 16×16 石板，按武器调色（暖棕/灰白/青灰/玄武/土褐/赭红/银灰）。
2. 把武器原贴图缩到 16×16 取亮度，乘到石板上，保留原模型的明暗分区（刃亮、柄暗）。
3. **丢掉 faces 为空的 cube**（见下方踩坑），模型坐标统一缩放/平移：长轴（原 +Z）归一到 0..16，X/Y 居中，长轴正好 1 格；去掉 `display`/`tnc_grip`/`texture_size`/`parent`，所有面改成单一贴图 `#0`。
4. 逐元素做一次和原版反序列化器同规则的校验（1~6 个面、uv、贴图引用、坐标范围、from ≤ to），不通过直接失败。
5. 输出 `models/projectile/earth_wpn_*.json` 与 `textures/block/earth_weapon/*.png`。

飞行体不需要额外旋转：这些持握模型本来就是沿 +Z 建模，正好是弹道方向；只有把它们竖起来当岩柱时才绕 X 轴 -90°。

## 用在哪

- **土神的枪（tier 5）**：每次施法从 17 把里随机一把射出，长 **5.2 格**（原细土柱 3.4 格，+53%），宽/厚按 **2.8 倍**缩放；命中后仍然是 96 格巨柱把目标顶上天。
- **巨柱升天**：柱子往上长的时候，柱身外侧会插出 6 把石化武器（随 top 升高、跟着柱子一起升），让“岩柱换武器”这件事在土神之枪里也看得见。
- **爆点小岩柱**：每 3 根里换 1 根石化武器，高度 **2.6 格**（巨型 3.4 格），原小柱只有 0.95/1.7 格。
- 巨柱本体、破土岩柱、碎石仍用原 `earth_pillar` / `earth_spike_sharp` / `earth_clod`。

## 土刺换巨剑（23:26 实装）

土刺（kind 4）原本是在身前一条线上依次破土 3 / 6 / 36 根岩刺。现在**隔一根换成巨型石化武器**，直接从地里捅出来：

| 档位 | 岩刺总数 | 其中武器 | 武器尺寸 |
|---|---|---|---|
| tier 2 | 3 | 2（第 1、3 根） | 宽 2.8~3.6，高 **11 格** |
| tier 3 | 6 | 3 | 宽 2.8~3.6，高 **13 格** |
| tier 4 | 36（环形） | 6 | 高 **18 格** |
| 其余岩刺 | — | 不变 | tier 2 提到 1.1 宽/2.6 高起，tier 3 2.2 宽/5 高起 |

- 每根武器的朝向随机（`facing` 只用来定 yaw），落地后静止 12 格、向外倾 12°；渲染时先绕 X 轴 -90° 站起来，再按 `高度/2` 抬升，所以**剑尖朝上、剑柄插在地里**，不会半截埋进土里。
- 每根武器落地时：地面裂纹环（16 tick）、10 块飞溅碎石、原有 `drawChips` 碎屑、`STONE_BREAK`（1.6 音量、0.5 音高）＋武器额外的 `GENERIC_EXPLODE`。
- 镜头：高 ≥7 格的武器破土时给 `EarthTremorClient` 加 **3.4 级震屏**（普通岩刺只有 0.4×），前 5 tick 还会触发 `launchKick`（FOV 内收 + 全屏尘幕），所以三根巨剑连续破土时画面是“一震、一暗、再震”。
- 伤害判定沿用 mode 1：第 8 tick 在 `宽度+1` 半径内结算一次，武器越大命中圈越大。

## 踩坑：紫黑方块

第一次装机后游戏里出现紫黑方块、柱子上也没有武器。`logs/debug.log` 里是：

```
Couldn't load model tnc:models/projectile/earth_wpn_dragon_sword.json, substituting missing
com.google.gson.JsonParseException: Expected between 1 and 6 unique faces, got 0
```

原因：原武器模型里有 125 个 **faces 为空**的 cube（原版渲染时它们本来就不显示）。原版 `BlockElement.Deserializer` 要求每个元素 1~6 个面，0 个面直接抛异常 → 整个模型被替换成 missing model（就是紫黑方块）。生成脚本现在会丢掉这些元素，并加了 `EarthWeaponModelsTest`：用**原版 `BlockModel.fromStream`** 真解析 17 个模型，任何面数/uv/坐标问题都会在 `gradlew test` 里直接失败，不会再靠进游戏才发现。

## 注册与成本

- `TNDirectSpellModels.PATHS` 从 13 条增到 30 条（17 把武器全部注册），`TNDirectSpellModelsTest` 同步断言 30。
- 17 个模型共 16,895 个 cube。原版解析 17 个 JSON 在测试里约 2.5 秒；烘焙是加载时一次性开销，渲染每把只是一次模型绘制。
- `EarthWeaponModels` 持有模型名、飞行尺寸与随机选型，服务端只传名字。

## 限制

- 石化贴图是 16×16 的“石块 + 原模型亮度”，远看是石制兵器，近看纹理偏粗；要精修得逐把画。
- 剑/刀/细剑偏薄，侧对镜头时像一条石片；嫌薄可以调 `FLIGHT_WIDTH`。
- 17 把共用同一套行为（飞行、插柱），没有各自技能差异。
