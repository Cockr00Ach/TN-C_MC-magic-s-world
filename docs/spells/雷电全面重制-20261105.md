## 1. 雷球链透明与发光修复

### 根因（反编译实际装的那份 spell_engine-0.15.12 得到）

```text
SpellModelHelper.LAYERS.get(LightEmission.RADIATE)
  → CustomLayers.spellObject(LightEmission)
  → spellObject(atlas, light, /* translucent = */ false)
  → CompositeState.setTransparencyState(f_110134_)
```

`f_110134_` 就是 `RenderStateShard.NO_TRANSPARENCY` ✗ —— **混合被关掉**，
贴图里 alpha=0 的地方照样当作不透明画 ⇒ 神 / 大雷球 / 环绕雷球全部变实心 ✗。

（`f_110139_` 才是 `TRANSLUCENT_TRANSPARENCY`，`spellObject(..., true)` 才用它 ✓。）

### 改法

- 新增 `LightningRenderTypes.SPELL_MODEL`：
  `entity_translucent_emissive` 着色器 ＋ `TRANSLUCENT_TRANSPARENCY` ＋ `NO_CULL`
  ＋ `COLOR_WRITE`（不写深度，半透明实体层的标准做法 ✓）＋ 方块图集 ＋ 主目标。
- `TNLightningStrikeRenderer`（神 / 大雷球 / 黑暗衍暗色版）与
  `TNThunderOrbRenderer`（环绕雷球）改走这一层 ✓。
- **发光**：模型下面先垫一圈主题色相机朝向光斑（加色），模型再盖上去 ✓
  - 神：半径 `0.34 × 尺寸`、贴在模型高度一半；
  - 球：半径 `0.62 × 尺寸`、球心；
  - 环绕雷球：半径 2.1 格、透明度 0.22。

### 验收

- [x] 三尊神重新是「半透明的雷神」✓（能看到背后的东西）
- [x] 大雷球半透明 ＋ 外圈辉光 ✓
- [x] 环绕雷球半透明 ＋ 辉光 ✓

## 2. t1 / t3 终于有电了

### 为什么原来「像没特效」

- **t1「电花」**：JSON 是 `release.target.type = CURSOR` —— 直接瞬间结算，**连投射物都没有** ✗，
  只有 8 颗 `electric_arc_a` 粒子；
- **t3「雷击」**：`bigStrike` 确实劈了落雷，但
  ① 起手 → 落点是**空的**（看不出雷从哪来）；
  ② 对着天空/远处放时，`player.pick` 的落点在**半空** ⇒ 整道雷挂在云里、地上什么都没有 ✗。

### 改法

1. 新实体 `TNLightningArcEntity`（`tnc:lightning_arc`）＋ `TNLightningArcRenderer`：

   - 每 2 tick 换一次种子 ⇒ 电一直在抖 ✓；
   - 落点可选补一圈地网 ＋ 地光 ＋ 爆闪。
2. `castArc(player, to, width, life, impact, extra)`：左手 → 落点，可附带 1~3 条侧向散开的副电弧。
3. t1：`castArc(..., 0.10F, 8, true, 2)` ⇒ 一道细电 ＋ 落点小雷网 ✓。
4. t3：落点先 **按到地面**（`groundBelow`，最多往下 26 格）再劈 14.4× 大雷，
   并补一条 `0.30` 粗的起手电弧 ⇒ 看得见是谁放的、打到哪 ✓。

## 8. 踩坑记录

1. **引擎那层是 `NO_TRANSPARENCY`** —— 别再直接拿 `SpellModelHelper.LAYERS` 画作者模型 ✗，
   一律走 `LightningRenderTypes.SPELL_MODEL` ✓。
2. `spellObject(LightEmission)` 的 `translucent` 参数是**硬编码 false**（反编译 bytecode 里的
   `iconst_0`）—— 所以「模型不透明」不是我们传错了参数，而是那层本身就没有混合。
3. `RenderType.entityTranslucentEmissive(texture)` 的贴图必须和几何 UV 对得上；
   作者模型是方块模型 ⇒ UV 全在**方块图集**，自建层时 `TextureStateShard` 必须给
   `TextureAtlas.LOCATION_BLOCKS` ✓（给错了就是紫黑）。
4. 半透明层**不要写深度**（`COLOR_WRITE`）：写了会挡后面的东西、自己也会打架 ✗。
5. 粒子削减只动 `count`，**不动** `min_speed/max_speed/shape` —— 速度是"炸开"的形状，
   砍了就不像爆炸了 ✗。
6. 构建时如果队友正在改别的文件，`compileJava` 可能因为**他那一秒的中间状态**失败 ✗
   （这次是 `EarthLaunchLayout` 的 import 还没加上）；等一两分钟重跑即可，不要动别人的文件 ✓。
7. **两个构建同时写 `build/libs/tnc-1.0.0.jar` 会写出半截 zip** ⇒ `reobfJar` 报
   `zip END header not found` ✗。做法：先确认没有 java 进程，删掉那半截 jar，再重新 build ✓。
8. PowerShell 里改这种中文文档**不要** `Get-Content -Raw | Set-Content` ✗（PS 5.1 会按 ANSI
   读、再按 UTF-8 写 ⇒ 二次乱码）。要么用编辑器工具写，要么 `[System.IO.File]::ReadAllText
   (path, [Text.Encoding]::UTF8)` 读 ✓。
9. **两个构建同时跑必然炸** ✗：这次 `processResources` 连炸两次，报
   `Copying to a directory which contains unreadable content` /
   `Failed to create MD5 hash for file ... as it does not exist` ——
   队友在同一 checkout 上每几分钟 build 一次，`build/resources/main` 与
   `build/libs/tnc-1.0.0.jar` 被两边同时写。做法：用 `-I work/ln-isolated-build.init.gradle`
   把 `buildDir` 指到 `work/ln-isolated-build-20261105`（队友用的是同一招，
   `work/push-isolated-build.init.gradle`）＋ 自己的 `--project-cache-dir` ⇒ 互不干扰 ✓。

### 9.1 雷速链的雷龙：分档 ＋ 缠紧

**症状**：0.55 体型下半径 `2.85×0.55 ≈ 1.57` 格、跨度 4.6 格、只绕 2 圈 ⇒
像一条大蛇在人身外兜圈，没有"缠"的感觉 ✗；而且只有 t5 有龙。

**改法**：

- `LightningDragonGeometry.coil(...)` 去掉 `turns` 参数，**圈数由几何反算**：
  `turns = √(L² − h²) / (2πr)`，其中 `L = 22 节 × SEGMENT_SPACING × 体型` 是脊线总长 ⇒
  任何体型都不会把骨节挤扁/拉长 ✓（0.55 体型 ⇒ ≈3.4 圈）。
- 渲染器：`radius = 0.80 + 0.55×体型`、`height = 1.15 + 3.45×体型`（t5 ⇒ 1.10 / 3.05 格，
  头顶略高于人）；呼吸幅度 0.22→0.14、底部 0.45→0.25（原来整条龙悬在半空 ✗）；
  脚下雷网 `3.2×体型` → `1.15 + 1.5×体型`，白闪同步缩小 ✓。
- 分档（`TnSpellMechanics`）：

| 档位 | 法术 | 体型 | 半径 | 跨度 | 龙存在时长 |
| --- | --- | --- | --- | --- | --- |
| t3 | `lightning_wind` 雷风 | 0.30 | 0.97 格 | 2.19 格 | 300 tick（15 s） |

  > 为什么不用 buff 判断：t1「电光」和 t4「雷充」挂的是**同一个** `tnc:lightning_haste` ✗，
  > 按效果分不出档位。

### 9.2 雷神"还是不透"（AlphaFadeBuffer）

反编译 `net.spell_engine.api.render.CustomModels#render` 确认了两件事：

1. 它**确实**用调用方传进去的 `RenderType`（`getBuffer(aload_0)`）⇒ 上一版换
   `LightningRenderTypes.SPELL_MODEL` 是生效的 ✓；
2. 但它走 `SpellEngine_renderBakedItemModel(...)`，也就是**物品模型**那条路，
   顶点颜色 alpha 写死 1.0（`putBulkData(..., 1,1,1,1, ...)`）。

⇒ 唯一的透明度来源只剩**贴图 alpha**：实测 `lightning_god.png` 63% 像素 alpha=0（镂空），
剩下 37% 是 **alpha=255 的实心**。所以模型永远是一尊"实心雕像"，
而跟随神就贴在人背后、离相机最近、层数叠得最多 ⇒ 最明显 ✗。

**改法**：新增 `client/lightning/AlphaFadeBuffer`（`MultiBufferSource` 包装器），
逐顶点转发、只把 alpha 乘系数：神 0.60 ／ 跟随神 0.52 ／ 雷球 0.85 ⇒ 真半透明 ✓。
它只包 `getBuffer` 那一层，闪电几何与辉光仍走原 buffer，互不影响 ✓。

### 9.3 雷锲链重做（雷牢 ＋ 落雷）

旧版"一般"的原因：19 根立柱 ＋ 3 条扁带 ＋ 顶冠**全是扁片子**，落雷是 `beacon_beam`
贴图的一根细线 ✗。新版 `ThunderSealRenderer` 整份重写，全部用 `LightningBoltGeometry` 真雷：

| 阶段 | 画什么 |

| 开阵 `0 → charge` | 两层**反向旋转**雷网 ＋ 贴地雷光，半径随 charge 长满（`growth`） |
| 雷牢 `charge → finish` | `min(18, count*2+4)` 根**竖雷**从地面环往上收拢（收到 `0.40R` 并扭半个身位）；两道横箍各 12 段**短雷**首尾相接，一顺转一逆转；顶上 8 道雷向中心汇聚 ＋ 白闪 |
| 脉冲 | `(age-charge)%12 < 4` 时整笼变亮 —— 和实体每 12 tick 打一次伤害**同拍** ✓ |
| 立顶 `finish → +16` | 中心 **40 格大雷**（t5 粗 0.62、4 条分叉）＋ 每个雷楔一根天雷（"九霄"＝九根）＋ 12 道径向爆雷 ＋ 扩散冲击环 ＋ 地面白光 ＋ 高空白闪 |

- 档位参数（`ThunderSealRules`）：t1..t5 = 1/2/3/6/9 个雷楔、半径 2.5/4/6/9/13 格、
  高 3.7/4.6/5.5/6.4/7.3 格、立顶在 37/52/67/82/97 tick。
- 配色：1 金 ／ 2 蓝 ／ 3 紫 ／ 4 蓝 ／ 5 暗紫（`LightningTheme`）。
- 性能：单帧最多 ≈18 竖雷 ＋ 24 段横箍 ＋ 8 冠 ＋ 12 爆雷 ＋ 节点雷，全走同一个 1 MB

### 10.2 雷牢：击中的敌人**不能动**（4 格以内）

`ThunderSealEntity` 新增"钉住"字段 `rooted`（UUID → 解除 tick）＋ 三个方法：

- `root(e, ticks)`：只要在**距封印中心 ≤ min(4, radius) 格**内（每轮脉冲都判，**不依赖 `hurt` 是否成功**——
  免疫伤害的怪也得站住 ✓），就 `Mob#setNoAi(true)` ＋ 挂 8 秒级 `MOVEMENT_SLOWDOWN`（amp 6）＋ 水平速度清零；
- `tickRooted()`：每 tick 把还冻着的敌人的水平 `deltaMovement` 清零、`navigation().stop()`，到点解冻；
- `releaseRooted()`：封印被移除（`remove(RemovalReason)` 覆写）或施法者死亡时**全部松开**，
  不会出现"被永久罚站的怪" ✗；
- 视觉：每次脉冲给前 4 个被钉住的敌人拉一条**雷索**（`tnc:lightning_arc`，从笼顶到敌人胸口），
  一眼能看出"电在拉着他" ✓。伤害仍然只由脉冲结算（视觉不结算伤害 ✓）。

> 4 格的取值：作者原话"4 格以下吧" ⇒ 取 `min(ThunderSealRules.radius(tier), 4.0)`：
> t1/t2 半径本来就 <4 格（2.5/4），t3 起笼子更大，但**只有内圈 4 格**钉人，
> 外圈照旧只吃伤害 ⇒ "进笼才被锁住" ✓。

### 10.3 照光法做的"施法前戏 ＋ 法阵"

照的是 `LightRitualSequence` ＋ `ElementSealRenderer` 那只猫，材料换成真雷：

| 新东西 | 文件 | 作用 |
| --- | --- | --- |
| `STYLE_LIGHTNING_MINOR = 11` | `TNMagicCircleEntity` | 低阶雷阵：一圈电环 ＋ 6 辐条 ＋ 小亮核，无外环/刻痕/雷网 |
| `STYLE_LIGHTNING_GRAND = 12` | 同上 | 高阶雷阵：`1.12R` 外环 ＋ 24 道外侧刻痕 ＋ 12 道抬起的电须 ＋ 12 辐条 |
| `LightningSealRenderer` | `client/` | 按上面两种样式，用 `LightningBoltGeometry` 现画环/辐条/刻痕/电须/亮核（每 2 tick 换种子 ⇒ 阵在爬 ✓） |
| `ThunderRitualSequence` | `magic/thunderseal/` | 纯数值规则，和 `LightRitualSequence` 同构：`Rite` = `BRAND`(t1/2) / `CAGE`(t3) / `TRIBUNAL`(t4/5)、小阵 2/3/4/6/8、门环 0/0/2/4/6、点燃/立环 tick、屏幕强度、白闪与震屏 |

落楔（`ThunderSealSpells.cast`）后立刻 `beginRitual(...)`：

1. **主阵**马上出现（t1/2 → 11 号、t3 → 7 号带网、t4/5 → 12 号），半径 `0.95 × 封印半径`；
2. **小阵**按蓄雷进度一颗颗点亮：第一颗 6%、最后一颗约 56%（`ignitionTick`），
   两圈轨道（0.42R / 0.66R）、半径 0.98~1.5 格；
3. **门环**中段一道道立起来（45%~90% 蓄雷），面朝阵心，2.4~3.0 格外、环半径 2.2 格；
4. 蓄雷后半段（55%/70%/85%）从环上向阵心**收 3 道电**（`lightning_arc`）——"暴风雨的前夕" ✓。

排程用 `ThunderSealSpells` 自己的 `PENDING` 队列 ＋ `ServerTickEvent`，到点前若封印已被打掉就跳过 ✓。

### 10.4 雷球链 t4/t5：一条龙从天扎进地里，身后跟着巨大雷球
