## 1. 旧翅膀为什么丑

旧的 `light_wings.geo.json`（2026-10-01 那版）四个硬伤：

| 症状 | 旧模型的写法 |
| --- | --- |
| 像"一排针" | 每根羽毛是 **1×6×1** 的细条 |
| 像"扇子骨架" | 只有 4 块大平板（8~11 长），25°~62.5° 硬扇开 |
| 侧看是一条线 | 两翼各是 **1 单位厚** 的纸，还分别贴在 z=0 / z=1 两个平面（右手那侧差了一个单位深 ✗） |
| 比玩家还矮 | 只铺到 x −19..−10、y −2..17 ⇒ 总跨度约 1.3 格，像背了个风筝 |

生成器也乱过：`tools/gen_light_wings.py`（2799 B）和 `tools/gen_light_wings_model.py`（4875 B）
是 10-01 的两份，跑任何一个都会把这版覆盖回去 ✗。**现在是 `tools/rework_light_wings.py`**（权威 ✓，
顶部 docstring 写着"旧的别跑"）。

## 2. 新翅膀：9 骨 / 118 块 / 708 面

```text
bones  : 9
cubes  : 118 visible（+2 个 uv:[-4,-1] 参考块，渲染器跳过不画 ✓）
x      : −28.45 .. 4.20 单位（单翼 1.64 格，两翼总跨度约 3.6 格）
y      : 0.28 .. 30.18（约 1.88 格高，翼尖高过头）
z      : −0.80 .. 2.80（必须 ≤ 3.2，翅膀才落在后背外侧 ✓）
```

结构（单翼 58 块：肩 9 + 肘 22 + 腕 21 + 内侧 6，另一侧镜像 ✓）：

- **前缘骨条 4 段**：`SHOULDER(−2.2, 9.0) → ELBOW(−9.2, 15.4) → WRIST(−12.6, 18.6) → HAND(−15.6, 19.4)`，
  宽 2.6→2.0、厚 1.6→1.3 的锥形柱。羽毛的根一律压在骨条**下面 1.6~1.8 单位** ⇒ 上缘永远是骨条 ✓
  （旧版羽毛尖比骨条高，边缘成锯齿 ✗）。
- **初级飞羽 7**：从腕/掌往外扫（**−6° → −44°**），长 17 → 11，宽 3.5 → 2.8。
- **次级飞羽 6**：从肘往下挂（**−60° → −81°**），长 16.5 → 14 ⇒ 垂到胯的那道下缘。
- **覆羽 4 + 腕覆羽 2 + 拇指羽 1 + 肩块 1**：更短更白，贴在最前一层（z 1.4~1.5）盖住所有羽根接缝。
- **上翘小羽 4**：肩/腕往上（+52/+38/+24/+16°）⇒ 鸟翼那个"尖"。

每根羽毛是 **base + tip 两块**（`blade()`：tip 取 0.58 宽、0.34 长 ⇒ 尖端是尖的，不是锯子 ✓），
厚度 0.8~0.9，沿 z 交错 0 / 0.28 / 0.56 三层 ⇒ 有厚度、不闪面、侧看也有东西 ✓。

**约束（不能动）**：9 根骨头名字/pivot 全保留（作者的 `waving` 动画和渲染器的 flap 兜底都按名字找 ✓）；
两个 `uv:[-4,-1]` 参考块**逐字节保留**（`LightWingsPlacement` 的放置数学拿它们当尺子 ✓）；
`z ≤ 3.2`（`LightWingsPreviewTest` 里钉着 ✓）。

## 3. 动画：`waving` 重写成"真的会扇"

### 3.1 旧动画为什么不能用

旧的 `light_wings.animation.json` 是 **2 秒、只绕 Y 摆 ±7.5°/±10°** —— 那是给"旧的一排针"
写的**左右晃**（像鱼尾巴），新翅膀需要的是**上下扇**。而且旧文件的总长 2.0 秒、峰值 0.75 秒，
`LightWingsProjectionTest` 里两条断言（0.75 秒要有位移、2.0 秒要回到原位）也是照它写的。

### 3.2 新动画

`animation_length: 1.0`（每秒一次扇动 ✓），峰值在 0.25（下压）/ 0.75（上扬），
六根骨头：肩 `±12°`、肘 `∓4°`、腕 `∓7°`（**肘/腕反向** = 翅膀不折成一朵花 ✓，第一次写成同向叠加 39°，
上扬相位整对翅膀缩成一朵蝴蝶结 ✗，预览图上直接就能看出来 ✗）。

### 3.3 ★ 镜像手性是"扫"出来的，不是推出来的

右翼不是简单的 x 反射：几何是「z 镜像 + 绕 (0,0,1) 转 180°」✗，所以
**`wingright` 自己那根骨头**和**它下面的 `*2` 骨头**手性规则**不一样**：

| 骨头 | Y | Z |
| --- | --- | --- |
| `wingright`（自带 `[0,180,0]`） | **同号** | **反号** |
| `wingLeftMid2` / `wingLeftTip2`（在它下面） | 同号 | **同号** |

这套是**扫出来的**：16 种符号组合，每种都用"右半边上每个点到左半边镜像点集的最近距离"
当尺子（`LightWingsFlapScanTest`，跑完已删），最好的一组误差 **0.121 格** ≈ 静止姿势本身的
**0.125 格**（手工镜像的零头 ✓）；推公式时我按"全部取反"写，实测左右差 2.6 倍 ✗。

同一个尺子留成了回归测试 `LightWingsAnimationTest`（4 条）：

1. `animationIsWiredToTheBones`：动画名 `waving`、长度 `1.0s`、**六根骨头**有轨道；
2. `bothWingsBeatTogether`：两个相位的**镜像误差 ≤ 静止基线 + 0.08 格**、两侧**同向**扇、
   平均抬高 0.15 格量级、不超过 1.9 格；
3. `rendersFlapFrames`：把两个相位画成 `build/light_wings_flap_down|up.png`（同一份渲染数学 ✓）。

> 教训：**动画手性别推，扫一遍用几何误差当尺子**。推错的表现是"一只上一只下"或"一侧动得多"，
> 在游戏里只在飞行那几秒能看出来，试玩很难发现 ✗。

## 4. 永久翅膀（光耀 t5）

新增 `light/LightWingOwners`：

```java
public static final int PERMANENT_TIER = 5;                 // 光耀链 t5 = "天使的悲悯"
private static final SpellCatalog.Chain[] PERMANENT_CHAINS = { SpellCatalog.Chain.LIGHT_GRACE };
public static boolean hasPermanentWings(Player player);      // 走 MagicStone.getOrNull
public static boolean hasPermanentWings(MagicStoneData data);// 纯逻辑版（单测用）
```

`TNLightWingsRenderer` 的门槛从"身上必须有 `tnc:light_wings` buff"改成：

```java
boolean buffed = TNEffects.LIGHT_WINGS.isPresent() && player.hasEffect(TNEffects.LIGHT_WINGS.get());
if (!buffed && !LightWingOwners.hasPermanentWings(player)) { FLIGHT_START.remove(...); return; }
```

于是：**光耀 t4 起施法范围内的玩家限时带翅膀**（原有 ✓），**光耀 t5 毕业的玩家永久带翅膀**（新增 ✓）。

只认**光耀**链：翅膀本来就是这条链给的（t4「天使降临」起就有 ✓），
把光线/光镜/召唤点满不该白送 ✗。要放宽只改 `PERMANENT_CHAINS` 一处 ✓。

**飞行没给成永久**：`mayfly` 挂在 buff 上，永久翅膀只是"看得见"。
作者说的是"永久有这个翅膀"⇒ 我按字面做（不额外送无限飞行，那是改数值 ✗）；
真要永久飞，把 `tickGraceFlight` 里加一条同判据即可（此处已留注释 ✓）。

`LightWingOwnersTest`（4 条）钉住：空石头没有 ✓ / t5 有 ✓ / **t4 没有**（否则 t5 没意义 ✗）/
光线·召唤·光镜 t5 **都不算** ✓。
