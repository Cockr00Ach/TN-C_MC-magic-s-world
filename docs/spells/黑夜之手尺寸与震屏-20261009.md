## 一、为什么"我调整过，怎么没变化"—— **两个原因叠在一起**

### 原因 1：我把"倍率"当成了**体积**倍率（这是我的错 ✗）

上一版 `tools/gen_dark_hand_scales.py` 是这样算的：

```
new_scale = 0.85 × 倍率^(1/3)        # 把作者说的"放大 N 倍"理解成体积 N 倍
=> 1.07 / 1.45 / 1.83 / 2.31         # 每一维只大了 1.26 ~ 2.71 倍
```

⇒ 肉眼几乎看不出来，而且**不是作者的意思** ✗（"放大两倍"就是大一倍边长 ✓）。
**现在按字面来**：`new_scale = 0.85 × 倍率` ✓

| 档 | 法术 | 倍率 | 旧 scale | **新 scale** | 长度（模型 scale 1 时 1.88 格）|
|---|---|---|---|---|---|
| t1 | 黑夜之手 | ×1 | 0.85 | **0.85** | 1.6 格 |
| t2 | 黑夜之袭 | **×2** | 1.07 | **1.70** | 3.2 格 |
| t3 | 黑夜之拥 | **×5** | 1.45 | **4.25** | 8.0 格 |
| t4 | 黑之破灭 | **×10** | 1.83 | **8.50** | 16.0 格 |
| t5 | 戮光 | **×20** | 2.31 | **17.00** | 32.0 格 |

### 原因 2（★ 更关键）：**这五个法术住在 mod jar 里，不在 kubejs** ✗

- 提交 `6b29d3af` 把它们搬进了 `src/main/resources/data/tnc/spells/` ——
  因为**同 id 的 kubejs 副本会静默盖掉 jar 的定义** ✗（当初就是这么丢过一次 `model_id` 的）；
- 所以：
  - **在游戏实例里改那份 JSON ⇒ 没用** ✗（改的不是被加载的那一份）；
  - `sync.cmd push` **也够不到它们** ✗（它只管 `modpack/` 那一侧的 kubejs/data）；
  - **唯一的生效路径**是：`python tools/gen_dark_hand_scales.py` → `gradlew build` →
    `tools/install-to-pack.ps1` ✓ —— 也就是**必须重编译 + 重装机 + 重启游戏** ✓。

> ★ **写进铁律（第十六条）**：**"改了这个文件却看不到变化"时，第一步不是继续改，而是先确认
> "游戏到底在加载哪一份"** ✗ —— 具体到本项目：`jar 内 data/` 与 `modpack/*/kubejs/data/`
> 是**两份不同的来源**，同 id 时 kubejs 胜；而 `config/` 又不在 sync 范围 ✓。
> 判据一条就够：**改完必须重新编译 + 装机 + 重启**，然后 `verify_mod_jar.ps1` 会告诉你
> "装机的那份是不是构建产物" ✓。

## 二、t3 起震屏（作者："t3 开始增加震动"）

**为什么不用"侦测附近的手投射物"** ✗：引擎的投射物是**通用类型** `SpellProjectile` ——
客户端只看得到"附近有个投射物"，认不出是不是这条链 ✓（不像我们的环绕雷球/落雷有自己的类型）。

**所以改成"施法时记一笔"** ✓：客户端也收得到引擎的 `SPELL_CAST`（我们在
`TNSpellClientVisuals` 的静态块里挂了监听 ✓），判据是**法术的 group == `dark_hand`**
＋ `learn.tier` ✓ —— 不写死五个 id，以后加档/改名都不用动 ✓。

| 档 | 震动强度 | 持续 |
|---|---|---|
| t1 / t2 | **0**（作者："t3 开始"）| — |
| t3 | 5.0 | 12 tick |
| t4 | 9.0 | 18 tick |
| t5 | **14.0** | 26 tick |

- 和已有的爆炸/落雷震屏**共用同一个镜头接口**（`ViewportEvent.ComputeCameraAngles`）✓：
  两种抖动**取较大值**叠加，不翻倍 ✗（翻倍会晕）；
- 强度按 0.94/tick 衰减 ⇒ 是"砸下去一震、慢慢停"，不是持续抖 ✓；
- 旋钮：`TNSpellClientVisuals` 顶部的 `HAND_SHAKE_STRENGTH` / `HAND_SHAKE_TICKS`
  两个数组（索引 = tier - 1）✓；
- ⚠️ 这是**屏幕**效果 ⇒ 旁边的队友也会一起晃 ✓（对"这一记很猛"的传达反而更好 ✓）。

## 三、⚠️ 一个要盯的风险（t5 = 32 格）

引擎用**原版渲染器**画投射物，而原版按**包围盒**做视锥剔除 ✗ ——
t5 的手有 **32 格长**，当它的**中心**转出屏幕时，整只手可能会**突然消失** ✗
（本项目在"10 格高的天使"身上踩过同一类坑：抬头发现在头顶的天使没了 ✗，
当时的修法是给实体补 `getBoundingBoxForCulling`）。

**如果作者看到"飞到一半就没了"**，两个修法（都是一行级）：
1. 给我们自己的投射物补一个放大过的 `getBoundingBoxForCulling`（要写实体，成本中等 ✓）；
2. 把 t4/t5 的 scale 往回收（改生成器字典里的一个数 ✓）。

**先别猜** ✗ —— 等作者实机看一眼再定，这条写在这里是为了"下次不用重新推一遍" ✓。
