## 一、先说要紧的：引擎**做不到**这件事的两半

| 作者要的 | 引擎能力 | 结论 |
|---|---|---|
| 「对敌人释放」 | `release.target.type` 只有 `SELF / PROJECTILE / BEAM / METEOR / CLOUD / AREA / CURSOR / SHOOT_ARROW` —— **没有"选中敌人"** ✗ | 用**投掷物**（血爪飞出去咬住谁就算谁）✓ |
| 「扣除敌人**百分比**生命」 | `Impact$Action` 只有 `DAMAGE / HEAL / STATUS_EFFECT / FIRE / SPAWN / TELEPORT` ✗，**没有一种能按目标最大生命百分比扣血** | 自己写 ✓ |
| 「收益给**我自己**」 | `STATUS_EFFECT` 只会给**被命中的目标** ✗ | 自己写 ✓ |
| 「回魔力」 | 没有 MANA 动作 ✗（魔力本来就是我们自己管的 ✓） | 自己写 ✓ |

**但引擎留了一个干净的钩子** ✓（反编译 `SpellHelper.performImpact` 确认）：

```java
interface SpellSpawnedEntity {
    void onCreatedFromSpell(LivingEntity caster, ResourceLocation spellId,
                            Spell$Impact$Action$Spawn spawn);
}
```

法术 JSON 的 `impact` 里加一条 `SPAWN`（`entity_type_id: "tnc:drain"`）⇒
**命中那一刻**引擎会造出这个实体，并**把施法者一起交给我们** ✓。
于是上面那三件引擎做不到的事，全都落在 `TNDarkDrainEntity.onCreatedFromSpell` 里 ✓。

## 二、现在每一档是什么

| 档 | 法术 | 扣敌人多少血 | 回多少魔力 | 血上限 |
|---|---|---|---|---|
| t1 | 以伤换伤 `trade_wounds` | **固定 4.0 点** | 伤害 × 1.5 | **+4** |
| t2 | 燃血 `blood_burn` | **固定 6.0 点** | 伤害 × 1.5 | **+6** |
| t3 | 献祭 `sacrifice` | 固定 2.0 ＋ **最大生命 4%** | 伤害 × 2 | **+9** |
| t4 | 夺舍 `possess` | 固定 2.0 ＋ **最大生命 5%** | 伤害 × 2 | **+14** |
| t5 | 我为神 `i_am_god` | 固定 3.0 ＋ **最大生命 6%** | 伤害 × 2 | **+20** |

（"伤害"= 真正抽到的血量，因为对方可能只剩一点点血，所以按**实抽**折算 ✓）

- **扣血前会夹住**：最多把对方打到剩 **4 点血** ⇒ 这一下**永远打不死人** ✓
  （想让它能致死就把 `TNDarkDrainEntity.MIN_HEALTH_LEFT` 改成 0 ✓）；
- **血上限是"可叠加的临时增益"**：挂的是 `tnc:blood_pool`，**每层 +2 秒**、最多 **5 层** ✓
  ⇒ 连着抽能把血池越堆越高，但不会刷成无限血 ✓；
- **扣的是魔法伤害**（穿过护甲，"从体内抽走"的手感 ✓），
  并把对方的受伤窗口清零 ⇒ 这一下**一定**生效 ✓；
- **自身扣血照旧** ✓（作者明确要求保留）：t2/t3/t4 燃血 1/2/3% 每秒、
  t5 血锁 1 ＋ 无敌、t1 不烧 —— 这条链仍然是"以伤换伤" ✓，
  但现在**从敌人身上抽得回来**（回魔 ＋ 抬血上限 ＋ 原有的 HEAL 回血 ✓）。

> ⚠️ **"对敌人释放"用的是投掷物**：法术的 `release.target` 仍是 `PROJECTILE`，
> 所以它是"放出去一条血爪打中谁就抽谁"✓ —— 想让它在**视觉上**更像"抓取"，
> 改 `tools/gen_tnc_dark_sacrifice_spells.py` 里那五档的 `model.scale`／
> `orientation`（`TOWARDS_MOTION` 会让模型朝着目标伸过去 ✓）。

## 四、顺手加的一道闸门

`verify_mod_jar.ps1` 新增：**法术里每一条 `SPAWN` 的 `entity_type_id`，
只要是我们自己的命名空间（`tnc:`），就必须真的被 `TNOrbEntities` / `TNNpcs` 注册过** ✓。

为什么值得单加一条：**`SPAWN` 写错 id 时引擎不会报错** ✗ ——
它查不到就静默什么都不生成，于是"吸血"变成一发空动作，**游戏里看不出任何异常**，
只能靠读代码猜 ✓。现在装机前就会红：
```
[ok] every SPAWN references an entity type we register (25 known ids)
```

## 五、★★ 2026-10-09 追加：**夸张猎奇 + 一直喷血**（作者："可以一直喷血粒子，我想要夸张猎奇一点的"）

第一版只在**命中那一瞬**炸一团血雾 ✗ —— 作者要的是"咬住不放、血一直往外喷"。
所以 `TNDarkDrainEntity` 从"活 5 tick 一次结算"改成了**持续喷血源** ✓：

| 项 | 现在 |
|---|---|
| 寿命 | **60 tick（3 秒）**，期间**每 tick 把实体贴到受害者身上** ⇒ 它被推走/打飞时血柱跟着走 ✓ |
| 扣血 | 整口量**分摊成 4 次**扣 ⇒ 血是"慢慢流光"而不是一刀 ✓（总量与上一版一致 ✓）|
| 喷血 | **每 tick 一轮**；前 **20 tick 是"动脉"量级**，之后收细到 45% ⇒ 像血在流光 ✓ |
| 结算 | 结束时给施法者报一次总账（共吸多少血 / 多少魔力）✓ |

**这是"喷"，不是"炸"** —— 每一轮五路一起上（全原版粒子 ✓）：

| 路 | 粒子 | 干什么 |
|---|---|---|
| ① 动脉 | `crimson_spore`（46×）＋ `dripping_dripstone_lava`（14×），速度 **1.1~2.4** | 往上往外的高速血柱，喷出去再受重力落下 ✓ |
| ② 血渣 | `falling_dust` ＋ **红石块**（26×，从**头顶上方**生成） | 殷红血粒像血雨一样落下来 ✓ |
| ③ 血泊 | 同上的红石血粒（18×，贴地、几乎不扩散） | 脚下一圈慢慢扩的暗红 ✓ |
| ④ 猎奇 | `damage_indicator`（前 20 tick 每轮 5×） | 原版那个"被打爆"的黑红十字混在血里 ⇒ 不体面、正合"猎奇" ✓ |
| ⑤ 暗底 | `squid_ink`（8×） | 一层黑雾压底，和暗系一条线 ✓ |
| ⑥ 回吸 | `crimson_spore`（10×，**朝施法者方向**的速度） | 「血被吸过来」的方向感 ✓ |

- 每 tick 约 **120 颗 × 60 tick ≈ 7000 颗/次** ✗ —— 比"天雷 30 道"更重。
  **卡的话按这个顺序砍**：`SPRAY_INTERVAL`（1→2 就腰斩）、`SPRAY_HEAVY_TICKS`（20→10）、
  ⑥ 回吸那一路（直接删）、`CHANNEL_TICKS`（60→40）✓；
- **全部原版粒子** ✓ —— 不碰任何第三方 id（`block_factorys_bosses` 那套是 Bedrock 粒子，
  用了会让客户端**闪退** ✗，见 `tools/gen_dark_fog_spells.py` 的 PARTICLE SAFETY 说明）；
- `falling_dust` 需要 `BlockParticleOption`，所以用**红石块**当它的"材质"⇒ 一粒粒殷红血渣 ✓。
