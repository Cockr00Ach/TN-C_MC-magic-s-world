## 三、★ 朝向约定（最容易做错的一处）

模型里**手指指向 +Z（＝飞行方向）**，手腕在 −Z。这是刻意的：

- 如果按"站着的人"的习惯把手指朝 **+Y** 做，投射物飞起来时手会**侧着**、甚至成一条薄片 ✗；
- 手指朝 +Z 之后，不管是默认朝向镜头还是沿弹道对齐，剪影都还是"一只手" ✓。

**包围盒居中到原点**同样是必须的：引擎让投射物模型**绕实体位置**转，
原来这只手的几何重心在 +4 单位（爪尖那一头），不居中就会变成"绕着前方一点翻滚"，
看起来像在自转手腕 ✗。生成脚本里有 `recenter()` 做这件事 ✓。

### ⚠️ 一个留给你挑的开关：要不要让它"伸着手抓过去"

引擎的 `Spell.ProjectileModel` 有三个朝向枚举：
`TOWARDS_CAMERA`（默认）/ `TOWARDS_MOTION` / `ALONG_MOTION`。

**现在是"不设"＝跟着包里其它投射物用默认行为**（朝向镜头/翻滚）。
理由：**手里没有游戏画面可看**，而 `TOWARDS_MOTION` 有真实风险 ——
手是**扁的**，正对着飞时可能变成一个薄片 ✗；默认行为则保证它总有一面朝着你 ✓。

想试就改法术 JSON 的 model 块，一个字段：

```json
"model": { "model_id": "tnc:projectile/dark_hand", "scale": 1.05, "orientation": "TOWARDS_MOTION" }
```

看着不对就把这个字段删掉即可回退 ✓。

## 四、五档的大小

**最终大小 = 模型自身尺寸 × 法术 JSON 里的 `scale`**（配方见 `投射物模型_配方.md`）。
原来那五档用的是直径 0.375 格的小球，现在换成了长 1.88 格的手 ⇒ **scale 全部重算**：

| 档 | 法术 | 旧（球） | 新（手） | 实际长度 |
|---|---|---|---|---|
| t1 | `night_hand` 黑夜之手 | `lightingball` 0.7 | **`dark_hand` 0.85** | ≈1.6 格 |
| t2 | `night_raid` 黑夜之袭 | 0.9 | **1.05** | ≈2.0 格 |
| t3 | `night_embrace` 黑夜之拥 | 1.2 | **1.3** | ≈2.4 格 |
| t4 | `black_ruin` 黑之破灭 | 1.5 | **1.55** | ≈2.9 格 |
| t5 | `slay_light` 戮光 | 1.8 | **1.8** | ≈3.4 格 |

> 嫌大/嫌小**只改这 5 个数** ✓，不要改模型本身 —— 模型尺寸是所有档共用的。

## 五、怎么改（改生成器，不要手改产物）

```powershell
python tools\gen_dark_hand_model.py
```

一次跑完输出三样：模型 JSON + 贴图 PNG + 预览 PNG ✓（和 `gen_light_wings_model.py`、
`gen_angel_model.py` 同一套做法）。脚本自带两道自检，坏了会当场报错而不是发货：

1. **每个面的 UV 必须落在图集内**且不退化（`u1>u0 && v1>v0`）；
2. **每个方块的三轴尺寸必须为正** —— 原版模型加载器会**静默丢掉**零尺寸的方块 ✗
   （写这个脚本时真踩过：爪尖的第二段 y 从 `ya+0.5` 到 `yb-0.5` 正好为 0）。

改造型就改 `build_boxes()`；改配色就改 `ATLAS`（每个材质一块矩形 + 基色/边色/暗色）。

## 六、装机后怎么验（游戏内）

```
/give @s tnc:magic_wand        （或用你自己那把）
/tnc learn tnc:night_hand      （或走魔法石界面学，暗系亲和力要够）
```

对着空气放一发，**应该飞出一只手**（紫黑、五指、洋红爪尖），不再是黄色雷球。

命令行旁证（日志里能看到模型真的被引擎取用）：

```powershell
Select-String -Path logs\latest.log -Pattern 'tnc:projectile/dark_hand'
```

- **有 `Missing textures in model tnc:projectile/dark_hand`** → 贴图路径写错 ✗
  （必须落在 `textures/spell_projectile/`，**不是** `projectile/`）；
- **完全没有这行** → 模型没被烘焙 ✗ → 检查 `TNProjectileModels.PROJECTILE_MODELS`
  里有没有 `projectile/dark_hand`（**只有这一份名单** ✓）。

`tools/verify_mod_jar.ps1` 现在已经会在装机前替你把这条查一遍 ✓
（输出行：`every projectile model referenced by a spell exists and is in the baked list`）。
