# 法杖 / 魔法石：法术到底存在哪（2026-11-09）

> 作者原话：「学习了的魔法是绑定到魔法杖上而不是魔法石上，拿别的法杖就没有学习着的魔法，
> 同样的遗忘魔法好像也有这个问题」
> 拍板：**取消元素限制，但同元素法术有伤害和能力加强**。

## 1. 查到的三个原因

### ① 元素杖只承载"本元素"的法术（设计问题，但没人会去读提示）

`ElementWands.supported()` 原来的过滤条件是
`e.element()==design.element || e.chain()==INDEPENDENT`，`ManaGate.hasWandFor()`
同样要求元素一致。所以**暗杖永远不显示风系法术**。

实机存档实证（`saves\新的世界 (3)\playerdata\…dat`）：

| 项 | 内容 |
| --- | --- |
| 魔法石 `Learned` | 10 个**风系**法术（`gale` … `wind_ball_5`） |
| 手上拿着 | `tnc:dark_wand_3`（暗系三阶杖） |
| 这根杖的 NBT | **空的**，连 `spell_container` 都没有 |

⇒ 玩家看到的就是"我学的法术绑在那根杖上"。

### ② 法杖内容只在特定事件才同步（真 bug）

`SpellEngineBridge.ensureWand()` 只在 **登录 / 学习 / 遗忘 / 铸杖 / 命令** 时跑，
而且它只写"**当时在背包里**"的杖。于是：

- 从箱子拿出来、别人给的、创造模式拿的、从别的维度带回来的杖 —— 从来没写过 container ⇒ 空的；
- 遗忘之后如果那根杖不在背包里，杖上还留着已经忘掉的法术。

### ③ 引擎那 8 个槽位 vs 一阶 28 条法术

不分元素之后，只看阶位的话一阶能凑出 `7 系 × 4 链 = 28` 条，
而引擎的法杖容器只有 8 格（`SpellEngineBridge.WAND_CAPACITY`）⇒ 必须截断，
否则后写的槽位会丢。

## 2. 改了什么

| 位置 | 改动 |
| --- | --- |
| `ElementWands.supported()` | **不再按元素过滤**，只按阶位（`e.tier() <= design.tier()`）。排序：**本元素优先 → 高阶优先 → 目录顺序**，截断到 8 条（稳定，槽位不乱跳） |
| `ManaGate.hasWandFor()` | 同上：只看阶位。提示语改成"需要手持能承载 N 阶法术的法杖" |
| `WandSync`（新） | 服务端每 **1 秒**把背包里的杖对齐一次魔法石（`refreshWands`）。**不补发法杖**（补发仍只在 `ensureWand` 里，否则创造模式会每秒多一根），**读条中跳过**（拔法术会让引擎的施法进程指向不存在的东西） |
| `WandResonance`（新） | 同元素**共鸣**：用本系法杖放本系法术，**伤害 +25%**（窗口 3 秒，覆盖读条+飞行+命中） |
| 法杖 tooltip | "承载 1~N 阶已学法术（不分元素）；共鸣：用它放X系法术，伤害 +25%" |

### 共鸣是怎么判定的

`SpellEngine` 的伤害走 `spell_power` 命名空间的 `DamageType`。所以
`LivingHurtEvent` 里看**伤害类型的命名空间**即可，不需要追踪法术 id：

```
施放放行（ManaGate ALLOW）→ 若手持杖元素 == 法术元素 → 打一个 3 秒窗口
窗口内、来源是 player、伤害类型命名空间 == spell_power → 伤害 ×1.25
```

近战、弓、其他 mod 的伤害都不会被放大 ✓。第一次见到某个伤害类型时会打一行
`TN-C: resonance saw damage type …` 日志，方便实机核对判定有没有踩对。

## 3. 怎么验（进游戏）

1. **换杖**：拿着暗杖去看魔法石里的 10 个风系法术 —— 1 秒内杖里就该有它们（不再为空）。
2. **新杖**：从箱子里翻出一根没用过的杖，拿在手上 —— 1 秒内同步。
3. **遗忘**：`/tnc forgetall` 之后，手上和背包里的杖 1 秒内清空。
4. **共鸣**：拿火杖放火法打木桩，和拿水杖放同样的火法对比 —— 前者伤害应高 25%。
   日志里搜 `resonance saw damage type` 能看到判定用的是哪个伤害类型。

## 4. 已知取舍

- **8 格上限**：一阶能学的法术超过 8 条时，杖里只放得下 8 条（本元素优先）。
  这是引擎容器的硬限制，不是这次新加的。
- **深渊塔赞助**（`ArcanaBeacon.eligible`）仍然要求"本元素三阶以上杖"，
  这是另一个系统（塔替你付魔力），按元素保留；拿错元素的杖会退化成自己付魔力。
- 共鸣目前只加伤害，没有加"法术时长/范围"—— 引擎不给这些数值开后门，
  真要加得逐个法术 hook，收益不值。
