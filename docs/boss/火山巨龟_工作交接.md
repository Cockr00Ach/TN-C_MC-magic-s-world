### 5.3 无伤害环境小喷发（2026-10-22，同一分支）

纯客户端表现，不改模型、不改动画、不生成攻击实体、不爆炸/不点燃/不改方块、不碰血量与阶段阈值。实现同样在 `VolcanicTortoiseAmbientFx`，参数集中在 `Tuning` 的“无伤害环境小喷发”段。

一次喷发的节奏（总计 22–30 tick，约 1.1–1.5 秒）：

1. **蓄势 8–10 tick**：火山口内部亮区由小到大、由暗橙过渡到浅黄，半径 0.10→0.48 格、尺寸 0.55→2.15、整体略微上抬 0.20 格；每 tick 生成 2→7 颗短命 `FLAME`（寿命 4–7 tick），后半段中心再加一颗更亮的芯。只作用于口内，岩石身体明暗不变。
2. **喷出 6–8 tick**：同时出两层——
   - 主要火焰簇：根部宽、上方收拢的 `FLAME` 柱，一阶段最高 1.55 格、二阶段 2.25 格（相对火山口中心，约在口沿上方 1.2 / 2.0 格），根部 0.46/0.56 格收拢到 0.14 格，根部尺寸 1.75 收到顶部 0.55；
   - 额外火星：前强后弱，第 i tick 权重 `(burst-i)^1.6`，前 2–3 tick 释放约一半，最后一 tick 放完余数。
3. **收尾 8–12 tick**：前 3 tick 火焰簇降到 30% 后消失，剩余轻烟每 3 tick 补一个；粒子按自身寿命自然消失，不在结束那一 tick 清场。

为什么火焰簇用粒子而不是渲染面：`GeoEntityRenderer` 的 render layer 拿到的是**绕骨骼 pivot 的相机相对矩阵**，上一轮的坐标错位正是这么来的；要在火山口贴一张随喷发进度变化的亮面，还得额外做贴图、每帧朝向相机的四边形和进度控制，风险和收益不成比例。这里复用已经验证过的火山口坐标，用分层 `FLAME`（自带宽高、根部密、顶部疏）拼出火焰簇，纹理本身带火焰像素轮廓，也不会在喷发结束后留下常驻亮面。

| 单次额外火星 | 28–36 个 | 44–56 个 |
| 单次额外烟 | 2–3 个 | 3–4 个 |
| 火星尺寸 | 0.45–0.85，16% 再 +0.55 | 同左 |
| 火星寿命 | 16–26 tick | 16–26 tick |
| 喷发烟寿命 | 10–18 tick | 10–18 tick |
| 喷发火星上速 | 0.26–0.42 | 0.30–0.48 |
| 向外散开 | 0.045–0.14 | 0.045–0.14 |
| 火焰簇最高点 | 1.55 格 | 2.25 格 |

- 喷发期间常规轻烟/火星降到 20%，喷发结束立即恢复，避免两套叠成浓烟。
- 触发：按 `gameTime` 倒计时，抽一次间隔用一个；同一实体同时只允许一次喷发；攻击时到点不触发、延后到空闲，且不累计多次；喷发中途攻击/转阶段立即停止后续生成，已生成的粒子自然消失（蓄势亮区寿命只有 4–7 tick，所以两三 tick 内就恢复）。
- 死亡/移除即刻停调度；切维度、重载、离开追踪范围再回来（gap > 40 tick）只重排间隔，不补发错过的喷发。
- 并发：按实体存在 `WeakHashMap` 里，多只 Boss 互不影响。
- **多人同步：没有做。** 调度是每个客户端各自按 `gameTime` 跑，同一时刻不同客户端看到的喷发相位可能不同；没有服务端事件、也没有逐粒子网络包。需要严格一致时，后续可改成服务端发一次开始事件、客户端只负责表现。

| 循环周期 | 4.0 s（80 tick），首尾同值 | 同左 |
| 身体上抬 | 0.55 单位（`body` 位置） | 同左 |
| 壳体上抬 | 0.55 单位（`shell` 位置，腿不在其下） | 同左 |
| 壳 pitch | 1.2° | 1.2° |
| 山体 | 只随壳起伏，`whorl` yaw 0→5→0，不单独摇晃 | 同左 |
| 颈/头 | 颈 4°→2°→4°，头 pitch −3°/1.5°、yaw ±3°，幅度低于身体 | 同左 |
| 岩甲 | 无此骨骼，跳过 | 在 ±22° 基础上 ±1°，左右相位差 0.4 s |

- 控制关系：`VolcanicTortoiseEntity.registerControllers()` 的 `move` 控制器过渡 8 tick，按 `isPhaseTwo()` 在 `idle` / `idle_p2` 间选择；`walk` 仍是同一控制器，起步即切换；攻击/转阶段/死亡走 `action` 控制器（过渡 2 tick），后注册因此覆盖同名骨骼，不与待机争抢。
- 岩甲基础角：转阶段结束把 `plate_l/plate_r` 落到 ∓22°，`idle_p2` 的关键帧就以该角度为基准叠加，不会重复应用或归零。
- 一阶段模型没有 `plate_l/plate_r`（也没有 `jaw`），所以一阶段用不含这些通道的 `idle`，避免每帧查找缺失骨骼。
- 呼吸只作用于 `body`/`shell`/`neck`/`head`/`tail`/`whorl`，腿骨位置未动；`body` 自身 0.55 单位的上抬在 1.2 倍渲染缩放下约 0.04 格，肉眼为轻微起伏，不会离地漂浮。
- 动画切换：起步/停步各 8 tick 混合；停步回到 `idle`/`idle_p2` 时所有通道都有显式关键帧，不会残留行走角度。

### 7.1 构建操作纪律（2026-10-23 事故后补，务必遵守）
