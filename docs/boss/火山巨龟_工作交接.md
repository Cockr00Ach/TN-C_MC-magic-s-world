### 5.3 无伤害环境小喷发（2026-10-22，同一分支）

纯客户端表现，不改模型、不改动画、不生成攻击实体、不爆炸/不点燃/不改方块、不碰血量与阶段阈值。实现同样在 `VolcanicTortoiseAmbientFx`，参数集中在 `Tuning` 的“无伤害环境小喷发”段。

一次喷发的节奏（总计 22–30 tick，约 1.1–1.5 秒）：

1. **蓄势 8–10 tick**：火山口内部亮区由小到大、由暗橙过渡到浅黄，半径 0.10→0.48 格、尺寸 0.55→2.15、整体略微上抬 0.20 格；每 tick 生成 2→7 颗短命 `FLAME`（寿命 4–7 tick），后半段中心再加一颗更亮的芯。只作用于口内，岩石身体明暗不变。
2. **喷出 6–8 tick**：同时出两层——
   - 主要火焰簇：根部宽、上方收拢的 `FLAME` 柱，一阶段最高 1.55 格、二阶段 2.25 格（相对火山口中心，约在口沿上方 1.2 / 2.0 格），根部 0.46/0.56 格收拢到 0.14 格，根部尺寸 1.75 收到顶部 0.55；
   - 额外火星：前强后弱，第 i tick 权重 `(burst-i)^1.6`，前 2–3 tick 释放约一半，最后一 tick 放完余数。
3. **收尾 8–12 tick**：前 3 tick 火焰簇降到 30% 后消失，剩余轻烟每 3 tick 补一个；粒子按自身寿命自然消失，不在结束那一 tick 清场。

为什么火焰簇用粒子而不是渲染面：`GeoEntityRenderer` 的 render layer 拿到的是**绕骨骼 pivot 的相机相对矩阵**，上一轮的坐标错位正是这么来的；要在火山口贴一张随喷发进度变化的亮面，还得额外做贴图、每帧朝向相机的四边形和进度控制，风险和收益不成比例。这里复用已经验证过的火山口坐标，用分层 `FLAME`（自带宽高、根部密、顶部疏）拼出火焰簇，纹理本身带火焰像素轮廓，也不会在喷发结束后留下常驻亮面。

| 随机间隔 | 12–20 秒 | 7–12 秒 |
| 单次额外火星 | 28–36 个 | 44–56 个 |
| 单次额外烟 | 2–3 个 | 3–4 个 |
| 火星尺寸 | 0.45–0.85，16% 再 +0.55 | 同左 |
| 火星寿命 | 16–26 tick | 16–26 tick |
| 喷发烟寿命 | 10–18 tick | 10–18 tick |
| 喷发火星上速 | 0.26–0.42 | 0.30–0.48 |
| 向外散开 | 0.045–0.14 | 0.045–0.14 |
| 火焰簇最高点 | 1.55 格 | 2.25 格 |

- 喷发期间常规轻烟/火星降到 20%，喷发结束立即恢复，避免两套叠成浓烟。
- 触发：按 `gameTime` 倒计时，抽一次间隔用一个；同一实体同时只允许一次喷发；攻击时到点不触发、延后到空闲，且不累计多次；喷发中途攻击/转阶段立即停止后续生成，已生成的粒子自然消失（蓄势亮区寿命只有 4–7 tick，所以两三 tick 内就恢复）。
- 死亡/移除即刻停调度；切维度、重载、离开追踪范围再回来（gap > 40 tick）只重排间隔，不补发错过的喷发。

### 5.8 重踏火环改为连续环带网格（2026-10-24，`feat/tortoise-slam-ring-20261024`）

**为什么之前看起来是"满地散火"**：旧实现每 2 tick 沿当前半径撒一圈 `FLAME`/`LAVA` 粒子，点间距约 2.4 格，而且粒子各自有寿命。于是同一时刻屏幕上同时存在半径不同的 3–5 圈点状火焰，圈与圈之间是空的，形成"散落火星"而不是一道连续火环。

**现在的做法**：新增客户端世界渲染器 `VolcanicTortoiseSlamRingRenderer`（`@Mod.EventBusSubscriber(..., value = Dist.CLIENT)` + `RenderLevelStageEvent` `AFTER_WEATHER`），用一张火焰环带贴图绘制 360° 闭合网格：

- 每帧只画**当前半径**这一道环（96 段，段与段共边，圆周闭合无缝隙）。
- 每段由三部分组成：外圈竖直火墙（主可见面）、内圈较矮的竖直火墙（做出向上翻卷的厚度）、贴地环带面（底部亮光）。竖直面保证地面视角也能看到火舌，而不是俯视才可见的平面圆圈。
- 火舌高度由三个不同频率的正弦叠加后量化到 1/16 格，避免光滑塑料圆筒；纹理沿圆周滚动（`UV_SCROLL`），有流动感。
- 纹理 `assets/tnc/textures/entity/volcanic_tortoise_slam_ring.png`（512×128，水平无缝）由 `tools/gen_slam_ring_texture.py` 生成；底部近黄白、中部橙黄、顶部橙红渐隐，向上一像素级火舌轮廓。
- 渲染类型 `RenderType.entityTranslucentEmissive`：不依赖光照，关光影同样明亮；自建 immediate `BufferSource`（与 `PortalRitualRenderer` 同因，兼容 Oculus）。
- 最大半径前 4 tick 开始淡出，`RING_TICKS + 2` 后彻底不再绘制，地面无残留。

**一次施法只有一道环**：服务端在砸地瞬间把中心与开始时刻写进实体同步数据（`DATA_SLAM_X/Y/Z` + `DATA_SLAM_START`），客户端只按 `level.getGameTime() - start` 重算半径。没有逐 tick 的环数据，也就不可能出现多圈残留；施法结束/被打断/转阶段/死亡时 `clearSlamRing()` 把 `DATA_SLAM_START` 置 -1。

**伤害与表现一致**：视觉半径 `22 × age / 30` 与服务端 `SLAM_RING_RADIUS × age / SLAM_RING_TICKS` 同一公式；客户端 `age` 额外减 0.5 tick，保证火环永远不会先于伤害到达。服务端仍按环带 `[r-1, r+1]` 结算并用 `castHits` 限制每人每次只吃一次。

**粒子只做补充**：`slamRingSparks` 每 2 tick 在推进边缘取 10 个点各放 1 颗短命 `FLAME`（每 5 点加 1 颗 `LAVA`），淡出阶段减到 5 个点；不再有 `END_ROD` 内缘与 `SMOKE` 残留。

**可调参数**（`VolcanicTortoiseSlamRingRenderer` 顶部）：`SEGMENTS = 96`、`BAND_WIDTH = 1.25`、`FLAME_HEIGHT = 1.0`、`UV_REPEAT = 6`、`UV_SCROLL = 0.010`、`ALPHA = 0.92`；服务端半径/时长仍在 `VolcanicTortoiseEntity` 的 `SLAM_RING_RADIUS` / `SLAM_RING_TICKS`。

### 5.9 重踏火环改为专用粒子环（2026-10-24，`feat/tortoise-slam-ring-20261024`）

**旧效果为什么是分离小火苗**：上一版用世界空间网格渲染器画一圈环带，但环带贴图是 512x128 上 5 团彼此分开的火焰重复 6 次；同时服务端每 2 tick 在当帧半径上撒 10 个原版 `FLAME`/`LAVA`。这些原版粒子有各自寿命、会停在旧半径继续上飘，所以画面上是 3–5 圈不同半径的点状火苗，没有连续圆环轮廓。

**现在的实现**：一道环 = 一个 `SlamRingFx.Ring` 实例 + 一批**专用粒子** `tnc:slam_flame`。

- 粒子类型：`src/main/java/com/tnc/tnc/boss/fire/TortoiseParticles.java`，`SimpleParticleType(true)`。`overrideLimiter=true`，把粒子设置调到「最少」也不会把主环裁成散点。
- 贴图：`assets/tnc/textures/particle/slam_flame_0..3.png`（4 帧 32x64 像素火焰：底部约 31% 是一条连续亮带，上方 2 束弯曲、分叉的火舌，芯近黄白 → 金黄 → 橙 → 少量橙红），由 `tools/gen_slam_flame_texture.py` 生成；`assets/tnc/particles/slam_flame.json` 列出 4 帧。贴图只负责翻卷闪烁，粒子高度不随动画增长。
- 环实例：`src/main/java/com/tnc/tnc/boss/fire/client/SlamRingFx.java`。`Ring` 保存固定中心、服务端开始时刻，以及每颗粒子的圆周角度、径向偏移、高度、宽度、外倾量、相位、镜像标记；`TICKS=30`、`MAX_RADIUS=22`、`SPACING=0.30`、`COUNT=ceil(2*pi*22/0.30)=461`、`EXTRA=200`、`BAND_HALF=0.34`。
- 半径：`R(t) = 22 * clamp(age/30)`，所有粒子共用同一个 R(t)；每颗粒子的实际位置是 `center + (R(t) + radialOffset) * (cos(angle), sin(angle))`，`y` 取该点地表高度。径向偏移只在 ±0.34 格内形成约 0.7 格宽的火带，所以同一时刻只有一条环。
- 朝向：粒子不再朝向相机，而是画成**沿半径法线的竖直贴片**（平面由切线 × 竖直方向组成），顶部沿半径向外倾倒 `lean` 格，从环外看是向外翻卷的火浪，不会随视角露出一排方片。每颗粒子额外画一块**贴地水平亮带**，保证从高处俯视也能看出完整圆环。
- 插值：渲染时直接用 `R(age + partialTick)` 计算位置，半径随帧平滑增长，不是每 tick 跳一次。
- 只有一道：每个 Boss 同时只保留一个 `Ring`；`boss.slamRingStart()` 变成新的非负值才新建实例，旧实例立即 `expired` 并移除其粒子；服务端 `clearSlamRing()`（重踏结束/被打断）后客户端整批清理。达到 22 格后粒子在 8 tick 内淡出并 `remove()`，不在旧半径留火圈。
- 伤害不变：仍是服务端 `tickSlamRing` 的环带判定（`[r-1, r+1]`）与 `castHits` 去重，与视觉共用 `SLAM_RING_RADIUS` / `SLAM_RING_TICKS`。本轮删除了 `slamRingSparks`（不再撒普通 FLAME/LAVA）。
- 旧的 `VolcanicTortoiseSlamRingRenderer`、`textures/entity/volcanic_tortoise_slam_ring.png`、`tools/gen_slam_ring_texture.py` 已删除，避免两套环叠加。

**可调参数位置**：`SlamRingFx` 顶部的 `SPACING`（主环密度，越小越密）、`EXTRA`（局部高火舌数量）、`BAND_HALF`（火带半宽）；`Ring` 构造里的主环高度波（`0.64 + 0.15*sin(3a) + 0.08*sin(7a)`，夹在 0.50–0.90）、额外火舌高度（0.98–1.30）、宽度（0.44–0.72）与 `lean` 外倾；`SlamFlameParticle` 的 `FRAMES`、贴地亮带的 `0.70` 起裁位置与 `0.34` 径向半宽；贴图颜色层次在 `tools/gen_slam_flame_texture.py`。

**5.9.4 地面波重写（同日，同一分支，待用户验证）**

用户实机反馈：只能看到火环，看不到地面起伏（测试点在负高度 Y≈-53）。

- **实际原因（两个叠加）**：
  1. 旧采样窗口以 `ring.centerY` 为锚，只向上 2 格、向下 3 格，且直接用 `Math.max(0, …)` 之类的下限思路；负高度场地、或地面在施法点下方超过 3 格时，整批采样为空 → 一块地砖都不画。
  2. 即使抬起，旧实现每块地砖也只画一个**水平顶面 quad**，没有侧面厚度；从玩家平视角度几乎看不出高度变化，又正好被 2 格宽的亮火带压住，视觉上等于没有。
- **采样修正**：以 `level.getHeight(MOTION_BLOCKING_NO_LEAVES)` 为世界实际上界，再与施法高度窗口取交集：`top = min(heightmapTop, floor(centerY + 8))`、`bottom = max(level.getMinBuildHeight(), floor(centerY - 4))`，从 top 向下找第一个 `isSolidRender` 且顶面有贴图的方块。既不会把 0 当下界，也不会跳到洞穴上方的屋顶；未加载区块直接丢弃。仍跳过流体、水面方块、方块实体。
- **渲染修正**：每块地砖改成**薄盒子**——1 个顶面 + 4 个侧面，顶面用 `Direction.UP` 的 sprite，侧面按方位取 `EAST/WEST/SOUTH/NORTH` 的 sprite（草方块会同时出现草皮顶面与泥土侧面），外侧一角抬得更高形成外倾坡面。抬升后能直接看到侧面厚度与明暗。
- **时间轴**：仍然共用火环的 `R(t)`，但地面按各自半径的到达时间提前 `LEAD = 2.4` tick（`arrive = radius / 22 * 30 - 2.4`），让坡面在火焰外沿前方先露出来；峰值抬升 `MAX_LIFT = 0.75` 格，`LIFE = 12` tick 正弦包络抬升→回落，单块边长 `PATCH = 1.75` 格。
- **预算**：采样 `96 × 11 = 1056` 点，单帧活跃地砖只限波前 `LIFE` 窗口内的部分，最多约 300 块 × 5 quad；相机水平距离 > `RENDER_DIST = 48` 格不画地面细节（火环与伤害照常）。
- **调试入口**：
  - `-Dtnc.tortoise.attack.debug=true` 时，建环会打印 `[TN-C SlamWave] cast=… patches=… centerY=… groundY=[…] lift=…`，绘制中每秒打印一次 `[TN-C SlamWave] cast=… active=… peakLift=…`。
  - 新客户端命令 `/tnc_ringhide`：在“隐藏火环 / 恢复火环”之间切换，用于单独观察地面波；不改变传播时间、伤害与击退，也不影响 Boss 的环境粒子。该命令不依赖调试属性，默认就可用。
- **安全**：纯客户端渲染，无碰撞、不放置/破坏方块、不加载区块、不写存档；技能取消/实体移除/区块卸载后不再绘制；渲染异常时整段地面波自动停用并记录一次 error，不影响服务端命中与击退。

**未验证**：地面起伏的可见度、草皮/泥土侧面观感、与火环的先后节奏、负高度场地贴合度均待用户实机确认；本轮未启动游戏。

**5.10 火环与地面波拆成两个独立技能（2026-10-24，同一分支，待用户验证）**

一次施法只放一个技能：技能 A 保留原火环，技能 B 只做地面震波，二者不再同时出现。

| | 技能 A：火环冲击 | 技能 B：大地震波 |
| --- | --- | --- |
| 动作 | `ACTION_SLAM`（沿用 `slam` 动画） | `ACTION_QUAKE`（复用同一段 `slam` 动画，不改名） |
| 施法编号 | `castId` + `DATA_SLAM_START` | 独立 `DATA_QUAKE_START`（值 = 服务端 gameTime） |
| 命中记录 | `castHits` | 独立 `quakeHits` |
| 冷却 | `slamCooldown`（130 / 90，结束时 40 / 60） | `quakeCooldown`（初始 240，施法后 280 / 200） |
| 视觉 | `SlamRingFx` 粒子环 | `SlamGroundWave` 地砖盒 |
| 伤害 | `0.75 × ATTACK_DAMAGE × damageScale()`，一次 | `tnc.tortoise.quake.damage`，默认 **0** |
| 击退 | `SLAM_KNOCKBACK = 0.6`，一次 | `tnc.tortoise.quake.knockback` 默认 0.85，一次 + 上抛 0.16 |
| 调试 | `/tnc_slam`（`/tnc_slam true` 画 22 格） | `/tnc_quake` |

- **真正拆开**：`startAction()` 每次都会 `clearSlamRing()` + `clearQuake()`，所以两个技能各自只有自己的一套状态；`SlamRingFx` 里原先的两处 `SlamGroundWave.begin(...)` 已删除，技能 A 不再触发任何地表隆起。
- **技能 B 的时间线**：`QUAKE_HIT_TICK = 24` 锁定中心并同步 `DATA_QUAKE_*`；`QUAKE_RING_TICKS = 40` 内半径从 0 推到 `QUAKE_RADIUS = 22`；命中带 `QUAKE_BAND = 3.5`（`[r-1.75, r+1.75]`）；总时长 `QUAKE_TICKS = 72`。
- **技能 B 的命中**：不调用 `hurt(0)`（原版会判无效），而是单独判 `canHarm` / `isInvulnerableTo` / 高差与视线，并用 `quakeHits` 去重；伤害为 0 时只做一次向外击退 + 轻微上抛，方向 = 圆心 → 目标水平方向，圆心重合时兜底 `(1,0)`。
- **AI 选招**：火环仍在 `slamCooldown <= 0 && distance < 7.1` 时优先；震波在 `quakeCooldown <= 0 && distance < 9.9` 时触发。震波结束时会把 `slamCooldown` 至少顶到 60 tick，避免两个技能紧接连放；两者都受 `attackCooldown` 与 `isBusy()` 限制，不提高总攻击频率。
- **地面波为什么之前看不见（两个原因）**：
  1. 旧采样窗口以施法高度为锚、只向上 2 格向下 3 格，负高度或地面低于施法点 4 格时整批采样为空；
  2. 旧渲染每块只有一个水平顶面 quad，没有厚度，平视几乎看不出抬升，又正好被宽火带盖住。
- **本轮修复**：采样改成“世界高度图 + 施法高度窗口（上 8 / 下 4 格）”；渲染改成 1 顶面 + 4 侧面的薄盒子（侧面用方块侧面贴图，草地能看到草皮与泥土）；`MAX_LIFT = 0.80`、`LIFE = 8` tick、`LEAD = 2.0` tick（地面略早于波心）、`PATCH = 2.05` 格（相邻重叠不露缝）、`RENDER_DIST = 64`。

## 5.19 嘴前蓄力与发射位置对齐（2026-10-25）

### 5.22 震波改为“真实地表抬起”（2026-10-25）

旧的发光波带（5.21）只能看到一圈带贴图的光带，没有真正的高度变化。
现在改为“临时地表副本”：每一块只在自己的 x/z 位置上抬起、回落，真正改变了视觉网格的高度。

**采样与材质**（`SlamGroundWave.sample`）
- 以施法高度为中心，上下 `SEARCH_UP = 6` / `SEARCH_DOWN = 8` 格内向下找第一个有碰撞体的方块，不取整列最高。
- 使用方块**真实模型**：顶面 `getQuads(state, UP)` 的 sprite 做顶面，四个侧面各取对应 sprite；无侧面时回退顶面贴图。
- 草方块的生物群系染色用 `mc.getBlockColors().getColor(...)`，不硬编码成统一绿色。
- 光照用 `LevelRenderer.getLightColor(level, pos.above())`，与周围地形一致。
- 跳过：空气、流体（水/岩浆）、带方块实体的方块、非 `MODEL` 渲染形式、没有顶面的模型（花/草类）。

**抬升曲线**
- `delta = R(t) - d`（d 为该块到炸心的水平距离），`lift = MAX_LIFT * exp(-(delta/SIGMA)^2) * fade`。
- `MAX_LIFT = 0.68` 格，`SIGMA = 0.95` 格（波峰前后各约 1 格包络），波峰过后回落到 0 并停止绘制（`lift < 0.03` 不画）。
- 每块顶面四角带 ±0.12×lift 的小高差，形成轻微倾斜；`lift < 0.04` 时不画侧壁，避免与原地面重叠闪烁。

**不外滑的保证**
- 每块的世界坐标固定为 `(floor(x), floor(z))`，只改 y；波过了就缓慢落回原地面并不再绘制。
- uv 直接用 sprite 的 `u0..u1 / v0..v1`，不按弧长重复、不随半径缩放，所以贴图永远是 1 格大小，不会被拉长。

**预算与清理**
- 每帧：128 个角度 × 3 个径向偏移，封顶 `MAX_PATCHES = 460` 块；单块 1 个顶面 + 最多 8 个侧面三角形。
- 每个波共享一张 `BlockPos → Patch` 缓存（贴图/染色/光照/支撑高度），波结束后整个缓存随 `Wave` 一起移除。
- 超过 64 格不绘制；区块未加载直接跳过（`getHeight` 不强制加载）。

**发光波带**
- `QuakeBandFx` 现在默认关闭（`GLOW_ENABLED = Boolean.getBoolean("tnc.tortoise.quake.glow")`）。
- 需要作为辅助亮线时加 `-Dtnc.tortoise.quake.glow=true`，不影响地表抬起。

**调试**
- `-Dtnc.tortoise.quake.debug=true`：每 20 tick 打一行 `[TN-C QuakeWave] radius=... patches=... cache=...`，用于判断采样是否为 0、实际画了多少块。

**2026-10-24 二次修正（装机后仍“看不出变化”的排查）**：

### 状态机

| --- | --- | --- |

| 攻击覆盖 | `action` 控制器过渡 2 tick，后注册覆盖同名骨骼；攻击期间呼吸不会把 head/jaw 拉回 |
| 默认闭嘴 | 所有动画的 jaw 通道在末帧归零；只有 `transition` 动 jaw |
| 喷吐 / 火柱 | 都不播攻击动画，本体保持待机/行走；喷吐的凝聚体与火柱均由独立 FX 绘制 |
| transition / death | `startAction` 清火环/震波/喷吐/柱位/落点状态；`die()` 清狂暴与 `megaEruption`，视觉按各自寿命自然过期 |
| 残留 | 火环 30 tick、震波 40 tick、柱位 36+4n、落点由弹道寿命决定；到期后列表移除，不常驻 |

#### 5.24.4 粒子与多人同步核查

- 所有粒子生成都在 `ClientTickEvent`（客户端 tick）里，没有在渲染阶段按帧生成。
- 每个客户端各自生成：`addAlwaysVisibleParticle` 绕开粒子设置裁剪，因此低画质仍能看见火球/火柱主体与预警轮廓（预警本身是几何，不是粒子）。
- 同一施法只处理一次：服务端 `castId` + `castHits/quakeHits/mortarLastHit/hitOnce` 去重，客户端按 `*Start` 同步字段的**变化**创建实例，不按帧创建。
- 多 Boss 隔离：所有状态挂在实体自身（`STATES`/`SEEN` 用实体 id 或 WeakHashMap 键），没有静态共享的中心或计时。
- 晚进入视野：火环/震波/柱位/落点都由服务端同步的开始时刻推导剩余时间，晚加入能看到剩余部分；已结束的不会补发。

#### 5.24.5 伤害与地形核查

- 每技能独立命中集合：`castHits`（咬/火环/柱）、`quakeHits`（震波）、`mortarLastHit`（弹幕）、`hitOnce`（火球爆炸）、`tryFieldHit`（燃烧区，同 Boss 10 tick 共享）。
- 狂暴倍率只在 `damageScale()` 乘一次；投射物在发射时把伤害写进实体，爆炸阶段不再乘。
- 预警与实际危险一致：火柱走廊 18×6 与 `PILLAR_DANGER_RADIUS/HEIGHT` 同源；弹幕落点用同一个 `pickLanding` 结果，客户端只读同步字段。
