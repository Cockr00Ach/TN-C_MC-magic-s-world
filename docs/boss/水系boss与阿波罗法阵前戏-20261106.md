# 水系 Boss 与阿波罗的法阵前戏（2026-11-06）

作者原话：**「那你记得连着水系boss和光系boss阿波罗也一起改了」**。

这一轮把 2026-11-06 的水系“潮汐印 + 读条前戏”和 2026-11-05 的光系“日轮仪式”接到了两个
自写施法循环的 Boss 上。**Boss 的血量、伤害、技能选择、动画时长、召唤数量一条没改**，
只加客户端可见的同步字段和视觉。

## 一、为什么需要单独接

玩家法术走 SpellEngine 的 `SpellCast.Process`，客户端能直接读读条比例；两个 Boss 不走：

| Boss | 原施法循环 | 缺什么 |
|---|---|---|
| 水系利维坦 `TNWaterLeviathanEntity` | 服务端 `actionTicks` 倒计时，到 0 才 `LeviathanSpells.cast` | 客户端不知道蓄力还剩几 tick、这一招是水球还是水缚 |
| 光系阿波罗 `TNApolloEntity` | 服务端 `pendingSpell` / `pendingTicks`，等 GeckoLib 动画播完才 `applySpell` | 客户端只知道动画在播，不知道法术索引/剩余时间 |

因此两边都只增加**实体同步 int**，不新增网络包、不新增服务端法阵实体。

## 二、利维坦

### 同步字段

| 字段 | 含义 |
|---|---|
| `CAST_REMAIN` | 当前前摇剩余 tick |
| `CAST_TOTAL` | 本次前摇总 tick（阶段二会少 4 tick） |
| `CAST_VISUAL_TIER` | 视觉档位：基础水球/龙吼 t3，龙毁/海神墓 t5 |
| `CAST_VISUAL_FAMILY` | 1 = 水球链 `ORB`，2 = 水缚链 `BIND` |

`beginVisualWindup` 在 `pendingAction` 开始时写入，`tickSpecialAttack` 每 tick 更新剩余，
施法完成/失败、死亡、打断都走 `clearVisualWindup`。原 `castPose` 嘴部姿态保留。

### 客户端画面

`WaterCastFx.scanBoss` → `bossRitual`：

- **脚下主阵**：`WaterGeometry.seal`，半径按档位 10.5–18，Boss 尺寸，不是把玩家阵放大一点；
- **嘴部竖阵**：用实体真实的 `MOUTH_FORWARD`（27.25 格）和 `MOUTH_HEIGHT`（5.4 格）定位，
  在嘴前立一张潮汐印 + 一圈外环，读作“口中聚水”；
- **水缚招**：走 `BIND` 分支，8 根水柱/3 道横环，柱高和厚度按 Boss 半径放大；
- **屏幕**：距离 48 格内按 `falloff` 加蓝色暗角和底部水线，t5 有低频心跳；
- **释放**：客户端三圈外扩水环淡出，随后由原有 `TNWaterFieldEntity` / `TNWaterSpellEntity`
  实体阵接管。

`sea_god_crypt` 的 64 格落剑路径印也从旧方块 `WaterSolidModels.seal` 换成
`WaterGeometry.staticSeal`，天印本来就已经是新几何。

## 三、阿波罗

### 同步字段

| 字段 | 含义 |
|---|---|
| `DATA_CAST_SPELL` | 当前法术索引 + 1，0 = 空闲；召唤信徒是 7 |
| `DATA_CAST_TICKS` | 剩余读条 tick |

`startCast` 写入，`aiStep` 每 tick 递减；`applySpell`、目标丢失取消、死亡都清除。
`castDuration()` 给客户端总时长：普通招 55/60 tick，召唤 60 tick。

### 客户端画面

`LightCastFx.scanApollo` → `apolloRitual`：

- 复用玩家光法的 `ritual`：地面日轮、卫星小阵、门环、中央光柱/日冕；
- Boss 范围 6.4–7.3 格，比玩家大一档；
- 头顶额外两圈金/冷白日冕环，明确是“日冕圣座”而不是普通祭司；
- 光线 t2/t3/t4/t5、光耀 t4/t5、召唤信徒三秒读条全部有前戏；
- 召唤开始时服务端仍生成旧 `TNMagicCircleEntity`，样式从 `STYLE_LIGHT` 提到
  `STYLE_LIGHT_GRAND`、半径 3.8→4.4，避免新主阵旁边出现低档小阵。

## 五、未验证/边界

- **没有进客户端实际看 Boss 前戏**。当前验证是服务端 GameTest、源码/字节码和单元预算；
  实际观感（嘴部阵是否穿模、阿波罗日冕是否挡视线、利维坦大阵在飞空中是否合适）需要试玩。
- 利维坦的嘴部阵使用实体常量定位；如果模型/动画改了口部偏移，要同步改
  `MOUTH_FORWARD`/`MOUTH_HEIGHT`，不要在两个客户端类里各写一份数字。
- 阿波罗的旧光阵仍在服务端生成；如果实际两层太厚，先调 `circle.configure` 的半径/寿命，
  不要为了“干净”直接删掉服务端阵，否则其他玩家会少一层可见仪式。
- 两个 Boss 的前戏都是**客户端本地几何**，不改变服务端伤害判定；网络延迟时法阵可能
  比实际出招早/晚一两 tick，这是读条同步的正常边界。
