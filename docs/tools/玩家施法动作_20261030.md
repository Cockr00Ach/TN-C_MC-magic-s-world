## 二、怎么在游戏里看（★ 这就是"方便观察"）

进游戏（操作员权限 2），第三人称（F5）对着自己的角色敲：

```
/tnc anim                      帮助
/tnc anim spawn                在你正前方 2.2 格放一个持杖演示角色（面朝你）
/tnc anim play wavingstaff     播一遍
/tnc anim loop magicsummon     循环播（反复对比姿态用这个）
/tnc anim kind summon          按"法术种类"播（summon / standard / powerful）
/tnc anim stop                 停下、回站姿
/tnc anim list                 动作表 + 种类映射
/tnc anim remove               删掉附近的演示角色
```

- 没有演示角色时 `play/loop/kind` 会**自己先放一个**，所以最短路径就是一条
  `/tnc anim loop wavingstaff`。
- 演示角色是 `tnc:self` 的**持杖变体**（同一个实体类型，开关是 `SelfBedrockNpcEntity#setWand`），
  `NoAI`、无敌、名牌"施法演示 / Cast Demo"；**右键不会弹剧情对话**（持杖版把 `mobInteract` 让过去了）。
- 演示角色换地方：再敲一次 `spawn` 会把它挪过去，不会越堆越多。

## 三、动作 ↔ 法术种类的约定

| 枚举 | JSON 动作名 | 用在哪 | 时长 |
|---|---|---|---|
| `SUMMON` | `magicsummon` | 召唤类法术 | 2.92 s |
| `STANDARD` | `wavingstaff` | **绝大多数法术**（"主要都用 waving"） | 2.46 s |
| `POWERFUL` | `playmagic_1` | 强力/大招 | 2.33 s |

这三条名字**只在这里写一次**（`PlayerCastAnimations`），实体、命令、以后的施法流程都从它取 ——
避免"改了一处、另一处静默不播"。以后接真正的施法流程就是一行：

```java
PlayerCastAnimations.SUMMON.play(target, false);   // 目标现在是持杖 Self，换成玩家只需改 SelfCastActorSupport
```

## 四、模型这边补了什么（诚实记账）

1. **`self_wand.geo.json` 原来没有根骨 `bone`**。`tools/gen_player_wand.py` 只搬了七根人形骨 + 两根杖骨，
   而动画里有 `bone` 的 `rotation` / `position` 关键帧（`playmagic_1` 结尾那 4 单位前冲、
   `magicsummon` 的 −2.5° 前倾、`wavingstaff` 的 −2.5° 转身）。GeckoLib **找不到骨头就静默跳过**，
   等于这几帧白录。现在补了 `bone` 根骨，六根人形骨挂上去（`hat` 仍挂 `head`，`wand` 仍挂 `armRight`）：
   `bone` 是单位变换、轴心在原点，**静止姿态一个像素都没变**，只是根位移/转身回来了。
2. **三条动作都加了 `"loop": false`**。本工程约定（见 `SelfBedrockNpcEntity` 头注释）：点播动画不写 `false`
   会被当成循环，`thenPlayXTimes` 的"次数"就没意义了。
3. **文件名保持你起的 `player_magic-animation.json`**（没有改名成 `<npc>.animation.json`）。
   代价是 `tools/check_npc_bone_contract.py` 按惯例找不到它 —— 所以那里加了一张显式映射表
   `ANIMATION_FILE`，`self_wand` 现在会被完整检查（骨骼是否都在模型里、`loop` 是否为 false）。
4. ~~**握法返工：握在杖尾**~~ —— **这条是错的，已回退**（2026-10-31）。当天夜里我看到
   *"法杖怎么能这么拿啊，你没见过人拿剑吗"*，把握点整体上移 7 单位（拳头挪到杖尾）。
   用户随后否掉：*"以前版本的法杖握法是正确的啊"*。现在 `HAND_SHIFT = 0.0`，
   杖恢复到 **y 3.35 → 42.93**、拳头在杖身中段 —— 和玩家手持物品时一模一样。
   **记一笔教训**：那句抱怨说的是"杖怎么跟着手臂横过来了"，是**手腕**的事，不是握点。
   别再把这条当成"握错了"。
5. **补了"手腕"：`wand` 骨的反向关键帧（这才是真正的问题）**。三条动作只录了 `armRight`，
   而杖挂在它下面 —— 手臂抬到 −102°（wavingstaff）杖身就横过来扫过胸口，−144°（playmagic_1）
   直接杵向地面。`tools/lock_staff_upright.py` 在每个 `armRight` 关键帧位置写一条 `wand` 关键帧，
   数值是那个旋转的**精确反解**（按 GeckoLib 的 Z→Y→X 骨骼顺序解矩阵，残差 < 0.5°），
   于是拳头跟着手臂走、杖身始终竖直，也不会再穿身体。
   以后再动 `armRight`，重跑一次 `python tools/lock_staff_upright.py`（带 `--check` 只验不改）。
   ⚠️ 这段 `wand` 通道是工具生成的：在 Blockbench 里重新导出动作会把它冲掉，导完记得重跑。
   **`magicsummon` 故意没上锁**：那条动作的右手会横摆过身体中线（拳头最终落在胸口里，
   x 从 −5 摆到 +1…+3），1.2 格宽的杖无论什么角度都会穿模 —— 这是**手臂本身**的问题，
   不是手腕能救的。工具对它只打一条 `[note]`，不改数据；要修就把 `armRight` 的 Z 分量改小、
   或者把手往外让开，改完重跑一次，note 会自己消失。`wavingstaff` / `playmagic_1` 两条
   已验：杖身全程竖直且不穿过头/帽/身/腿。
