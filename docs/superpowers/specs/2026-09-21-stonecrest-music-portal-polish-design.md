# Stonecrest、旅行音乐与天空岛传送阵修订设计

## 目标

本次修订同时解决三个相互独立但需要随同一份 TNC 模组发布的问题：

1. 玩家传送到 Stonecrest 城堡附近的新区块时，结构生成不得因 Conquest Reforged 植物方块更新而失败。
2. 旅行音乐不得在进入世界后立刻播放，曲目之间应保留约五分钟的安静时间。
3. 天空岛双向传送阵保留现有圆形建筑布局，但增加清晰、可取消的蓄能过程和粒子反馈。

## Stonecrest 崩溃修复

崩溃根因是结构模板放置后的邻居形状重算。Conquest Reforged 的 `Bush` 方块在其支撑条件发生变化时可能先由父类返回空气，随后仍向该空气状态写入 `layers` 属性，从而抛出 `IllegalArgumentException`。

Stonecrest 模板本身已经包含完整、确定的方块状态，因此其 `StructurePlaceSettings` 将启用 `knownShape`。这会跳过模板放置结束后的邻居形状重算，保留导出的植物层数和装饰状态，并避免触发 Conquest Reforged 的错误路径。不会删除城堡植物，也不会将所有植物替换为空气。

验收标准：

- TNC 模组可使用 Java 17 完成构建。
- Stonecrest 的模板设置明确启用 `setKnownShape(true)`。
- `/locate structure tnc:stonecrest_fortress` 后传送至新区块，不再出现 `layers ... minecraft:air` 的区块生成异常。

## 旅行音乐时序

音乐继续使用现有随机洗牌播放列表，不连续重复上一首。时序调整为：

- 每次进入世界后，第一首随机延迟 2–4 分钟播放。
- 每首自然结束后，下一首随机延迟 4.5–5.5 分钟播放。
- 离开世界时停止当前曲目并重置计时。
- 音乐音量为零或没有导入曲目时不开始播放。
- 继续压制原版背景音乐，避免与自定义旅行音乐叠加。

## 天空岛传送阵体验

现有地面与天空岛圆形传送阵的模板和坐标保持不变。玩家进入有效区域后开始约 2.5 秒（50 tick）的蓄能：

1. 蓄能开始时显示简短提示并播放低强度提示音。
2. 蓄能期间，传送阵维持常驻粒子，并在玩家周围生成逐渐增强的传送、附魔与末地烛风格粒子。
3. 玩家在蓄能结束前离开圆阵、死亡、切换维度或离线时，立即取消本次蓄能；再次进入需重新计时。
4. 蓄能完成时播放传送音效和集中闪光，然后执行现有双向传送。
5. 目的地播放一次向外扩散的到达粒子，现有首次抵达重生点逻辑保持不变。
6. 传送后继续使用冷却时间，防止玩家落地后立即被反向传送。

蓄能状态仅保存在服务器运行内存中，不写入世界存档；服务器重启后自动清空，避免遗留无效玩家状态。

## 验证与发布

- 增加针对音乐时间范围及传送蓄能状态转换的可测试逻辑，至少通过构建和现有测试。
- 检查退出世界、音乐静音、玩家离开圆阵和传送冷却等边界条件。
- 构建成功后，将同一份 `tnc-1.0.0.jar` 同步到仓库整合包与当前 PCL 实例，并核对 SHA-256 一致。
- 保留工作区内与本次任务无关的未提交文件。
