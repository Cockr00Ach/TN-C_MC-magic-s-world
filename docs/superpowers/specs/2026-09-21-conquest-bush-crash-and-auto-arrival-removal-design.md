# Conquest 植物崩溃兼容与自动到达逻辑清理设计

日期：2026-09-21

## 目标

1. 修复世界生成金合欢树等结构时，由 Conquest Reforged `Bush` 方块引发的服务器崩溃。
2. 清除 TN-C 遗留的“登录后自动前往新手村”代码与天空岛首次到达后强制修改重生点的行为。
3. 保留玩家主动进入天空岛传送阵、传送特效以及新手村坐标提示。

## 已确认的根因

崩溃报告中的当前放置特征是 `minecraft:trees_savanna`。原版结构边缘更新执行到 Conquest Reforged 1.6.0 的 `Bush#updateShape` 时，父类计算结果可能已经是 `minecraft:air`，但 Conquest 随后仍在这个返回状态上写入 `layers` 属性。空气方块没有该属性，因此抛出 `IllegalArgumentException`。

这不是 Stonecrest 城堡传送命令本身的错误。此前对城堡模板启用 `setKnownShape(true)` 只能跳过城堡模板自身的边缘更新，无法保护随后执行的原版树木或其他世界生成特征。

最新日志和世界数据同时表明，玩家登录时没有执行 TN-C 传送：玩家坐标与该世界的自然出生点相邻。当前“出生在村庄里”可能是自然出生点恰好落在高密度村庄生成区域。不过，项目仍保留已经停用的旧新手村登录脚本，且天空岛首次传送会修改玩家重生点，容易造成行为混淆，因此一并清理。

## 设计

### 1. Conquest `Bush` 兼容补丁

在 TN-C 的服务端/通用 Mixin 列表中加入一个仅针对 Conquest `Bush#updateShape` 的兼容 Mixin。

补丁只拦截该方法内部对 `BlockState#setValue` 的调用：

- 返回状态仍包含目标属性时，保持原行为并写入属性。
- 返回状态不包含目标属性时（典型情况是空气），直接返回该状态，不再写入不存在的属性。

补丁不改变原版树木生成算法，不删除城堡植物，也不取消任何结构生成。Mixin 配置保持非强制模式，使 Conquest 模组不存在时 TN-C 仍可加载。

### 2. 自动到达和重生点清理

- 从整合包 KubeJS 中删除已经停用的旧 `initial_town.js`，彻底移除其中历史遗留的登录传送和 `/spawnpoint` 代码。
- 删除天空岛管理器在玩家首次从地面传送到岛上时调用 `setRespawnPosition` 的逻辑。
- 保留玩家主动站入传送阵后的延迟、粒子、音效和双向传送。
- 保留登录时的新手村/天空岛坐标提示与岛屿生成检查。
- 不添加新的“远离村庄重新选出生点”算法。自然世界出生点仍由 Minecraft 世界种子与已安装的村庄模组决定。

## 验证

1. 添加针对兼容保护逻辑的自动化测试，覆盖“状态包含属性”和“状态不包含属性”两种分支。
2. 使用 Java 17 运行测试并构建 TN-C JAR。
3. 检查 Mixin 配置包含兼容补丁，且旧 KubeJS 登录传送脚本已从发布目录移除。
4. 将新 JAR和 KubeJS 删除结果同步到当前 PCL 实例。
5. 新建世界验证正常进入主世界；主动踩传送阵仍可传送，但不会修改重生点。
6. 在新的未生成区块中触发金合欢树/城堡附近世界生成，确认不再出现 Conquest `layers` 属性崩溃。

## 风险与回退

- 兼容补丁只作用于 Conquest `Bush` 的一个属性写入点，范围较小；若目标模组未来升级并修改方法字节码，Mixin 可因非强制配置跳过，但需要按新版方法重新适配。
- 删除旧脚本后，可通过 Git 历史恢复；不会删除世界存档或已有建筑。
- 已经写入存档的玩家重生点不会由本次更新主动清除。本次修改只阻止以后再次由天空岛逻辑写入。
