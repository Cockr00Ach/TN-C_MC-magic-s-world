# TN-C 赶路音乐系统设计

日期：2026-09-20

## 目标

在玩家进入世界后，由 TN-C 在所有维度中播放自定义赶路音乐。自定义音乐与 Minecraft
原版背景音乐不能重叠；第一版只实现通用赶路歌单，建筑专属音乐留到建筑坐标和范围确定后扩展。

## 素材入口

原始音乐统一放入仓库根目录的 `music-inbox/travel/`。该目录接受 MP3、WAV、FLAC 和 OGG，
允许中文文件名。接入工具负责转换为 OGG Vorbis、生成合法资源名、复制到
`src/main/resources/assets/tnc/sounds/music/travel/`，并生成声音注册表和歌单清单。

原始音频默认被 `music-inbox/travel/.gitignore` 排除，避免大文件或未确认授权的音乐被误传到公开仓库。
正式发布前必须确认每首音乐的使用和再分发授权。

## 播放行为

- 玩家处于任意可游玩的维度时均可播放赶路音乐。
- 曲目采用洗牌袋随机：每轮将全部曲目打乱并逐首播放，一轮结束前不重复；新一轮避免立刻重复上一首。
- 进入世界后先等待一个短随机间隔；每首结束后等待约 20–60 秒再播放下一首。
- TN-C 控制器启用后停止原版 `MusicManager` 当前曲目，并持续阻止原版背景音乐与自定义音乐重叠。
- 自定义曲目使用 `SoundSource.MUSIC`，因此服从游戏“音乐”音量滑块、暂停和静音设置。
- 离开世界、返回标题界面或切换服务器时立即停止曲目并清空本次会话状态。
- 切换维度不强制切歌；当前赶路曲目可以自然播放完毕。

## 技术结构

1. `TravelMusicCatalog` 读取生成的曲目清单并维护洗牌顺序。
2. `TravelMusicController` 运行在客户端 tick，负责等待、播放、结束检测和会话清理。
3. `TravelMusicSoundInstance` 以音乐声源播放单首流式 OGG，不把长音乐整体载入内存。
4. 客户端控制器只负责听感，不向服务器写存档，也不影响多人服务器逻辑。
5. 后续建筑音乐作为更高优先级的“音乐区域”接入：进入区域时暂停赶路调度，离开后恢复赶路歌单。

## 异常处理

- 歌单为空时保持静默，不反复报错。
- 单首资源缺失或解码失败时记录一次日志并跳过，不阻塞后续曲目。
- 音乐音量为零时不启动新曲目，但仍保持原版音乐禁用规则；恢复音量后继续调度。
- 重载资源后重新读取歌单并安全停止旧声音实例。

## 验收标准

- 在主世界、下界、末地或模组维度中均能听到歌单曲目。
- 连续播放一整轮不重复，同一首不会跨轮立即连播。
- 自定义曲目播放期间听不到原版背景音乐叠加。
- 音乐滑块、暂停、退回标题和重新进档行为正常。
- 缺少一首音频不会导致崩溃，其余曲目仍可播放。
- 第一版不包含建筑坐标、建筑判定和建筑专属曲目。
