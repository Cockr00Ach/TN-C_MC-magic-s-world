# 主世界天空岛新手村设计

日期：2026-09-20

## 背景

现有 v4 新手村能够完整放置 100 个结构分块，但城镇占地约 `281×337`，直接压到随机主世界地表后会留下明显的矩形切边，视觉上像整块地图被搬运过来。继续适配随机山地、河流、森林和不同海拔，会大量破坏建筑或要求复杂的地形重塑。

本次改造将新手村改为主世界内的预制圆形天空岛。玩家仍在普通主世界出生，通过附近的小型传送阵进入天空岛；不创建独立维度，不改变同伴已有的法术、模型和开局逻辑。

## 目标

- 在主世界生成一座独立、完整且轮廓自然的天空岛新手村。
- 尽量保留现有城镇建筑、主要道路、广场和南门布局。
- 用自然地形与古树根系消除原城镇矩形边界。
- 玩家从地面传送阵进入天空岛南门，并可双向返回。
- 生成过程可中断恢复，失败时不传送玩家、不留下永久区块票据。
- 地面入口仍位于随机出生点附近，并始终提供精确坐标。

## 非目标

- 不创建新维度。
- 不把天空岛内部做成可探索洞穴或地下任务区。
- 不在首版重做城镇建筑风格或任务内容。
- 不自动删除旧开发存档中的 v4 地面城镇。
- 不追求每个世界随机生成不同的岛形；首版优先保证美术质量和稳定性。

## 已确认的视觉布局

### 岛面

- 主岛采用不规则圆形，最终直径约 `500–520` 格。
- 现有城镇位于中央台地，建筑和主要道路基本不动。
- 城镇矩形四角外保留至少约 `35` 格自然缓冲，圆周方向通常有 `40–100` 格自然地形。
- 自然环由草坡、树林、苔藓、岩台、少量小池塘和收束道路组成。
- 树木密度向岛边增加，用于遮挡城镇原始矩形边界；不允许道路在岛边突然悬空截断。

### 岛体与根系

- 岛面为 `4–8` 格草土层，下方是约 `12–24` 格厚的不规则岩壳。
- 岛体不制作实心巨型岩锥，以控制方块数量和首次生成耗时。
- 底部由古树根系承担主要轮廓：约 4 条视觉主根、4–8 条副根，直径从 `12–18` 格逐渐收至 `2–4` 格。
- 根系只做外观，不设置可进入洞穴。
- 根尖配置小型发光晶体簇；不使用持续粒子或常驻实体，避免性能负担。
- 根系避免平行、等长和轴对称，侧面轮廓必须具有明显的自然变化。

### 高度

- 城镇道路基准面目标约为主世界 `Y=175`，南门安全落点约为 `Y=180`。
- 原城镇最高点放置后必须低于 `Y=310`，为主世界 `Y=319` 上限保留安全余量。
- 根尖最低点目标约为 `Y=90–110`。岛中心候选区域只需排除会与根系相交的极高山峰，不再要求地面能容纳整座城镇。

## 玩家动线

1. 玩家正常出生在主世界随机出生点。
2. 系统在出生点约 `100–250` 格内寻找一处可容纳小型入口的安全地面。
3. 聊天显示地面传送阵精确坐标；后续可再由任务系统增加指南针或路标。
4. 天空岛在后台生成，入口在全部结构校验成功前保持未激活状态。
5. 玩家踏入激活后的地面传送阵，传送到天空岛南门。
6. 南门设置对应的返回传送阵，并把玩家重生点设置为南门安全位置。
7. 玩家重新登录时只显示已保存坐标，不重复生成天空岛。

## 预制资产方案

采用“离线合成完整场景、运行时只放置模板”的方式，不在玩家世界中实时计算岛形。

### 城镇重导出

旧 v4 导出包含从源世界 `Y=32` 起的大块矩形地基，不能直接整体抬到空中。新导出需分离建筑与深层地基：

- 保留建筑、道路、方块实体和每列地表以下约 `8–16` 格的必要地基。
- 删除更深的矩形地下体，避免从侧面看到方形岩盘。
- 保持箱子、告示牌等方块实体数据，不导出生物实体。
- 以当前城镇中心和南门为稳定锚点，所有天空岛资产使用同一局部坐标系。

### 岛体离线生成

- 使用固定随机种子的离线生成器创建不规则圆边、表面起伏、岩壳和根系。
- 岛面中心按城镇高度图与道路边缘进行平滑衔接；外围起伏不能穿入建筑。
- 根系使用多段曲线和递减半径生成，之后与岩壳合并。
- 植被、岩石、池塘和晶体作为最后一层独立资产，便于后续美术迭代。
- 完整场景按最大 `48×48×48` 切分；空分块不导出。

### 资产分层

1. `sky_island_shell`：草土层、岩壳、主根、副根和晶体。
2. `sky_island_town`：城镇建筑、道路、方块实体和浅层地基。
3. `sky_island_detail`：树木、岩石、池塘、边缘道路与两端传送阵。

清单记录每个分块的层、局部坐标、尺寸、非空气方块数和校验哈希。运行时严格按岛壳、城镇、细节顺序放置。

## 运行时架构

超大结构生成从 KubeJS 命令链迁移到 `tnc` Java 模组中的持久化状态机。结构模板继续作为数据资源随整合包分发。

### 持久状态

服务器 `SavedData` 至少保存：

- 生成版本，首个天空岛版本为 v5。
- 当前阶段和下一个结构分块序号。
- 天空岛原点、中心、南门与地面传送阵坐标。
- 当前由生成器添加的强制加载区块集合。
- 最后失败的模板名、坐标和简短原因。

### 生成阶段

1. 初始化：读取主世界出生点，选择岛中心方向与地面入口候选点。
2. 岛壳：从最低根尖向上放置岛壳结构。
3. 城镇：放置建筑、道路和浅层地基。
4. 细节：放置自然环、晶体和岛上返回阵。
5. 校验：检查南门安全空间、关键模板计数和坐标。
6. 激活：写入成功版本，生成并激活地面传送阵，通知玩家坐标。

每次只处理一个 `48×48` 水平区域：添加本次生成器拥有的区块票据，等待区块可用，放置少量模板，保存检查点，再释放票据。退出游戏后从最近检查点继续。

### 传送阵

- 地面传送阵占地约 `15×15`，只需要适配小范围地面，不承担天空岛生成。
- 入口与南门出口成对保存；玩家进入中心触发区后传送。
- 传送前检查目标区域已加载、脚下为实体方块、头顶至少两格空气。
- 天空岛未完成、目标不安全或维度不正确时拒绝传送并显示原因。
- 传送触发由 Java 处理，避免依赖命令方块或每 tick 的全玩家 KubeJS 扫描。

## 错误与恢复

- 任一模板缺失、解析失败或放置抛出异常时，记录具体模板和坐标，停止后续阶段。
- 失败不写 v5 成功标记，不激活地面入口，不传送玩家。
- 状态机只移除自己成功添加的区块票据，不取消服务器或其他模组已有的强制加载。
- 服务器启动时先回收上次状态中记录的残留票据，再从检查点重试。
- 模板放置必须幂等；重复执行同一检查点不会复制实体或破坏已完成分块。
- 日志和玩家提示区分“仍在生成”“可自动恢复的失败”和“缺失资产、必须修包”三类状态。

## 旧世界与版本迁移

- v5 不删除 v4 已生成的地面城镇，避免大范围清空误伤开发存档。
- 旧测试世界可以继续用于功能验证，但会同时保留旧地面城镇。
- 天空岛最终视觉验收必须使用全新世界。
- 正式发布的新世界只生成 v5 天空岛和地面传送阵。

## 性能约束

- 运行时不执行覆盖整座岛的空气清场；目标高度默认应为空。
- 空结构分块不写入清单、不触发放置。
- 每 tick 放置数量由实际耗时限制，单 tick 预算目标不超过约 `40 ms`。
- 进度提示按 10% 或阶段切换发送，不刷屏。
- 视觉根系使用静态方块，不使用持续粒子、盔甲架或常驻装饰实体。

## 验收标准

- 从俯视和侧视均看不出原 `281×337` 矩形地图边界。
- 现有主要建筑、道路、广场和南门均完整保留。
- 主岛整体为不规则圆形，外围存在连续自然缓冲带。
- 岛底有清晰的古树根系与晶体轮廓，不是平板或实心规则锥体。
- 新世界只生成一座天空岛；入口和岛上出口可双向传送。
- 玩家始终获得地面入口、岛中心和南门的精确坐标。
- 生成中途退出后可继续，全部完成或失败后均无本系统遗留的区块票据。
- 任一分块失败时入口不激活，玩家不会进入半成品。
- 同伴最新法术、模型和命令在合并后的模组中继续正常加载。

## 验证方式

- 离线验证圆形边界、结构尺寸、局部坐标、重复方块位置、方块实体坐标和清单哈希。
- 对 Java 状态机测试完整成功、模板缺失、放置失败、中途停止、恢复继续和已有强制加载区块六种路径。
- 对双向传送测试未完成拒绝、落点阻塞拒绝、成功传送和重生点设置。
- 使用至少三个不同种子的全新世界实测入口选址与岛体生成。
- 在一次生成过程中强制退出客户端，再进入世界验证检查点恢复和票据释放。
- 最终进行俯视、侧视、岛边道路和南门落点的人工视觉验收。
