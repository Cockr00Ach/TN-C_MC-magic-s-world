# 天空岛玩家提示与旧开场白屏蔽设计

## 范围

本次只修改玩家提示与首次登录白。不修改天空岛生成、传送机制、传送阵建筑或 Stonecrest 城堡资源。

## 玩家体验

1. 玩家第一次进入尚未完成天空岛的世界时，屏幕中央显示大标题“天空岛向你投来注视”，副标题为“远方的浮岛正在苏醒”，并使用淡入、停留和淡出。
2. 勘测完成、分片数量和百分比等进度不再发送到聊天栏。程序日志仍保留详细进度。
3. 天空岛和传送阵完成后，在线玩家中央显示“传送阵已被唤醒”，副标题显示地面传送阵的 X/Y/Z。
4. 完成时聊天栏只发送一条地面传送阵坐标与“请前往该处寻找通往天空岛的入口”指引，不再同时发送天空岛中心和南门两组坐标。
5. 返回已完成的世界时，聊天栏仍提醒传送阵坐标；同一玩家不重复播放已看过的大标题。新玩家则会获得完成标题与坐标。
6. 生成失败和清单损坏等可操作错误继续在聊天栏显示，避免静默失败。

## 实现方式

- 使用 Forge/Vanilla 标题数据包由服务端向玩家发送标题、副标题和动画时间，不通过 KubeJS 执行 `/title`。
- 在玩家 `PlayerPersisted` 数据中保存 TN-C 的“已看过苏醒标题”和“已看过完成标题”标记，确保死亡、重进世界和服务端重启后行为一致。
- 将该项目的登录事件提升到 `EventPriority.HIGHEST`，先写入 `PlayerPersisted.ysjxmodelFirstJoinDialogShown=true`，使 `ysjxmodel` 原有的 `OpenFirstJoinDialogPacket` 不再发送。不修改供应商 JAR，不影响其他任务迁移和登录逻辑。

## 验证

- 单元测试锁定首次、返回、生成完成三种提示决策。
- 反编译或资源检查确认 `ysjxmodel` 使用的精确持久标记为 `ysjxmodelFirstJoinDialogShown`。
- Java 17 执行完整 `clean test build`，然后将同一 JAR 同步到仓库整合包与 PCL 实例并校验 SHA-256。
