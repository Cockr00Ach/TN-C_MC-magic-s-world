# 主世界首领总表（第三方模组，2026-09-30）

> 用途：给主线任务链、委托、地图标记挑"主世界能打的大怪"。
> 口径：**只要主世界**，**只要首领／小首领两档**（精英怪不算 —— 2026-09-30 定）。

---

## 〇、本表的口径与证据规则

**只用第三方模组 jar 自身的数据 + 模组自己生成的 config。**
以下**整合包作者自己的内容一律未作为依据**（本次调研中被显式跳过）：

| 被排除的作者内容 | 原因 |
|---|---|
| `config/openloader/data/yuansujuexing/**` | 作者加的 raid 定义、维度覆盖（含 `raidcraft/raids/*.json` 的 dimension 字段）|
| `config/openloader/resources/Elemental Awakening/**` | 作者改写的 champions 阶级名（一阶路边一条～九阶天灾）|
| `config/ascensio.json` | 作者的阶级难度倍率表 |
| `config/ftbquests/**` | 作者任务书 |
| `ysjxmodel / ysjxspells / ysjxteams / ysjx_weapons / ysjx_dimension` 五个 jar | 作者自己的模组 |

**档次判定**（只用模组自己的东西）：模组自带 `tags/entity_types/*boss*` / `forge|jerotes|c …/bosses.json` ＞ 实体的 `MobLevel` 枚举（EEEAB）＞ 击杀成就 `frame:"challenge"` 或点名击杀 ＞ 类常量池里的 `ServerBossEvent` / `BossEvent` / boss 音乐引用 ＞ 专属结构 + 专属 `hunt_*` 成就 ＞ config 里的独立数值档。

**维度判定**：`worldgen/structure/*.json` 的 `biomes` → 模组自己的 `tags/worldgen/biome/has_structure/*` 或 `#forge:is_*` / `#minecraft:is_*`；自然生成类看 `forge/biome_modifier/*.json` 的 `biomes`，或模组代码里的刷怪表（`javap` 反汇编）。

**读 `.nbt` 的前提**：jar 内 `structures/*.nbt` 是 **gzip 压缩**的，必须先解压再搜实体 id，否则永远搜不到。

## 四、必须知道的四个坑

### 1. Alex's Caves：模组语义 vs 本包实际，两回事

- **模组本体**明确是**主世界洞穴群系**：jar 内**没有** `dimension/`／`dimension_type/`；6 个洞穴群系写在 `data/alexscaves/worldgen/biome/*.json`；`BiomeGenerationConfig.class` 的常量池里 6 次出现 `minecraft:overworld`；`data/minecraft/tags/worldgen/biome/is_deep_ocean.json` 里写了 `alexscaves:abyssal_chasm`。
- **但本包另装了一个 addon** `Dimensions-of-Alex's-Caves-1.20.1-1.0.4.jar`（modId `alex_caves_dimensions`），它把 6 个洞穴做成了**以该洞穴为唯一群系的独立维度**（6 组 `dimension/*.json` + `dimension_type/*.json`），靠 6 把钥匙传送进入。
- 另外整合包作者还打包了一份 `config/alexscaves_biome_generation/*.json`（6 个洞穴全部 `disabled_completely: true` + `dimensions:["minecraft:overworld"]`）—— **这是作者内容，我按约定没拿来当依据**，但它若生效，主世界就不会生成这些洞穴。
- ⇒ **口径要你定**：按"模组语义"算，AC 的首领在主世界；按"本包实际部署"算，它们只在 addon 维度里。本表按前者列，并在此标注。

**档次上两位调研者的结论有分歧**（我保留在表里，标"高（本体语义）"）：
- 一路按"有**点名击杀成就**"判 ⇒ 把 `atlatitan` / `tremorsaurus` / `watcher` / `forsaken` / `mine_guardian` / `gloomoth` 列为**小首领**（本表采用）；
- 另一路按"有 `ACBossEvent`（boss 血条）"这一更严的标准全类扫描 ⇒ **只有 `luxtructosaurus` 一个算首领**，其余全归精英怪。
- 两说都能自证。若你按严标准，§二里 Alex's Caves 那 6 行应删掉。

### 2. Illage and Spillage 的 7 个首领在本包袭击里**刷不出来**（已证明是模组默认）

`config/illageandspillage-common.toml` 里 `magispeller / spiritcaller / freakager / old_freakager / old_magispeller` 的波次计数是**全 0**。
我用 `javap` 反编译 `Config$CommonConfig` 还原了每个数组的**代码默认值**，与配置文件逐位比对：**12 个键里 11 个完全相同** ⇒ 这些 0 是**模组自己的默认值**，不是谁改的，所以这条可以用。

**唯一被动过的是 `bossrandomizer_raidcount`**：模组默认 `0,0,0,0,1,0,0,1`（第 4 波与终波各 1 只），配置里被清零 ⇒ 终波 Boss随机者在本包被关掉了。来源不明，**本表不据此下结论**。

⇒ 结论：这 7 个首领**别指望在原版袭击里遇到**，要用就得靠刷怪蛋或自己写触发。
