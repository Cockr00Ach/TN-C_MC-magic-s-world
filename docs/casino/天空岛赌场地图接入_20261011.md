# 天空岛赌场地图接入

来源是用户提供的 `D:\ModTest\duchang.zip`，原存档不修改。保留其砂岩外墙、黑色玻璃、红绿大厅、原有楼梯、楼层、客房、Create 仿制板材及静态挂饰。

赌场位于天空岛西侧、原城镇边界外。v2 将原建筑向下嵌入岛体 7 格，建筑相对岛原点的范围为 `(66,88,234)` 到 `(109,122,297)`，约 44×64×35 格。入口露台维持原地面高度，原楼梯连通地下大厅；承台和通往西侧主路的台阶施工边界为 `(64,80,232)` 到 `(124,132,307)`。世界坐标应加上各存档的 `ORIGIN`，不能把这些相对坐标当成固定传送坐标。

地下红绿大厅安装一张轮盘桌、一张庄家牌桌、一张摇骰桌、一台幸运转轮、三台老虎机。三张桌子都是长 8 格、宽 4 格；幸运转轮宽 4 格、高 4.8 格。纵向排桌，侧边留出通道。设备都朝北，完整占地、地板与上方空间经过检查。右键射线覆盖整台设备，并在服务端复核距离及墙体遮挡。红绿黑选择、牌面花色、铜币结算、净赢钱烟花保留。

上层入口设置“赌场前台 · 小金”，右键展示玩法介绍；另有 24 名不同服装的客人，在上下大厅的可达通道中行走。寻路排除设备完整占地，人员持久化并使用固定 UUID，防止反复加载重复增加。

新版 JAR 在天空岛及地景完成后自动进行独立施工，兼容新世界和已有天空岛。玩家或生物在施工范围内时等待其离开。先检查整个现场，再分批放置；现场改建或容器冲突会暂停，避免覆盖玩家内容。施工恢复只接受原状态或目标状态，已存在的设备、库存及未领取奖金不会重新初始化。源地图的箱桶库存、战利品表、玩家和生物不复制。

管理员可用 `/tnc skycasino status` 查看进度、实际世界位置和冲突，用 `/tnc skycasino retry` 在解决冲突后重新检查。该命令不强制覆盖。

资源为 `src/main/resources/data/tnc/casino/island_v2.nbt`，独立于原天空岛 manifest 与地景层。保留原 `island_v1.nbt` 作为迁移基准，使用新的 `tnc_sky_casino_v2` SavedData。已有 v1 世界先保存 358 个家具/设备迁移位置的完整 NBT，再搬迁；容器库存与未领取奖金跟随原设备，移除源方块实体后再拆除，防止复制掉落。普通开门状态与草地变化允许迁移，结构改建仍会暂停。

生成器为 `tools/import_casino_map.py`，需要 nbtlib、numpy、Pillow。解压只读源存档位于 `work/casino-map-20261011/duchang`，v2 导入报告为 `import-report-v2.json`。Blockbench 参考工程可由 `tools/gen_casino_expansion_assets.py` 更新，包含当前尺寸及动画旋转中心；运行时几何仍以 Java 为准。

验证：59,741 个唯一且有界的施工记录，351 个清空库存的原地图方块实体，7 个静态装饰，47 个行走节点。赌场 17 项单元测试、20 项 GameTest 通过，涵盖完整点击范围、四种朝向、前台固定与客人实际走动、迁移数据保存、酒馆依赖恢复和开门迁移。整套 260 项 GameTest 中 259 项通过，仅已有的夜葫芦遮阴生长测试失败。开发客户端实际渲染 5 种设备、15 种状态及中奖烟花，审计无失败。

最新正式存档“新的世界 (13)”的只读迁移预检覆盖全部 59,741 个位置，未发现方块或容器冲突，结果见 `live-preflight-v2.json`。完整建筑仍需在正式整合包启动后巡场，不能将开发测试当成整合包建筑验收。
