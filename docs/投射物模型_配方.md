## 排查"紫黑方块"的正确顺序（血泪教训）

1. **先读日志** ✗（我绕了几小时才做 ✓）：
   ```powershell
   Select-String -Path logs\latest.log -Pattern 'tnc:projectile' -Context 0,2
   ```
   - `Missing textures in model tnc:projectile/X: ...` → **模型被烘焙了 ✓ 但贴图引用错** ✗ → 检查 ② 的目录与 ① 的引用 ✓
   - **完全没有这行** → **模型没被烘焙** ✗ → 检查 ③ 的清单里有没有这个名字 ✓（并在游戏里确认 `TN-C: registered N TN-C projectile model id(s)` 那行日志 ✓）
2. 再用二分法：把 `model_id` 换成一个**已知能显示**的号 ✓（本项目里是 `tnc:projectile/lightingball` ✓）→ 能显示就是**号/文件**的问题 ✓，不能就是**法术 JSON**的问题 ✓。

## 环境坑（都踩过）

- **打包 zip 必须用正斜杠条目名** ✗（Windows 默认反斜杠 → MC 完全读不了 → 资源包"启用却无效"）
- **`JAVA_HOME` 被 PCL 占用会让 gradle 静默不编译** ✗；`identical: True` 可能只是**两个旧文件互相比** → 必须**核对 jar 内容** ✓（已固定用 `D:\ModTest\.jdk17`）
- **不要改 Fabric 模组的 jar** ✗（Connector 重映射失败 → 启动崩溃）
- `sync.cmd` 是**双向**的 ✗：删了 kubejs 里的文件后不要再跑 sync ✓，否则游戏侧旧副本会被同步回仓库 → 再次覆盖 jar ✗
