### Blockbench 导出后必须手改的两处（2026-09-22 实测踩到）

用户导出 Java 模型时，**Blockbench 默认会带上这两样，直接放进 jar 就是不能被烘焙** ✗：

| 要改的 | 长什么样 | 改成 |
|---|---|---|
| **`texture_size`** | `"texture_size": [64, 64]` | **整行删掉** ✗（原版模型规范不认这个字段）|
| **贴图引用** | `"0": "texture"` / `"particle": "texture"` | `"0": "tnc:spell_projectile/<名字>"`（**两条都要改**）|

> `format_version` / `credit` / `groups` 保留没问题 ✓（现在能正常显示的 `lightingball.json` 也带着它们）。

### 尺寸换算（决定投射物看起来多大）

**最终大小 = 模型自身尺寸 × 法术 JSON 里的 `scale`** ✓

- 模型尺寸看 `elements` 的 `from/to` 跨度：`6` 单位 = 6/16 = **0.375 格**（`lightingball`）／`15` 单位 = **0.94 格**（`thunder_ball` 那个 353 方块的大雷球）
- 换模型**必须重算 `scale`** ✗：`cataclysm_thunder_orb` 原来用小模型配 `scale 5.0`（≈1.88 格），换成大雷球后不改就会变成 **近 5 格** ✗ → 已改成 `2.4`（≈2.25 格）
- 雷球链现有手感：t1 `0.8`(0.30 格) → t2 `2.8`(1.05) → t4 `5.0`(1.88) → t5 `2.4`×大模型(2.25)


> **验证脚本会替你查这三件事** ✓（`tools\verify_mod_jar.ps1`）：模型文件在不在、法术引用的号**在不在 `PROJECTILE_MODELS` 里**（不在 = 必然紫黑 ✗）、清单里有没有**没有文件的死条目**。

## 环境坑（都踩过）

- **打包 zip 必须用正斜杠条目名** ✗（Windows 默认反斜杠 → MC 完全读不了 → 资源包"启用却无效"）
