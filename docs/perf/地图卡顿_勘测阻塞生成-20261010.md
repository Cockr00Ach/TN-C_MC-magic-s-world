## 二、真因：三处 **同步** `ServerLevel.getChunk(...)`（都在 `SkyIslandManager`）

`level.getChunk(x, z)` 在区块未加载时是**阻塞式生成**：它在**主线程**上跑完地形、结构、
生物群系、POI 注册全套 ✗。在装了 280+ 模组（含 Conquest 那种 103MB 大包的）整合包里，
**一个区块花几百毫秒**很正常 ✓。于是：

| # | 位置 | 问题 | 量级 |
|---|---|---|---|
| 1 | `surveyStep` | 每个 tick 在候选地 `getChunk` 一次，只为读一次高度图 | 每 tick 超时 **~几百 ms** ⇒ 连续几十 tick 就把服务器拖到 30 秒后 ✗ |
| 2 | `chooseGroundPortal` | **一次调用**里对 16 个候选 × 9 个采样点 = **144 个区块**做同样的同步生成 | 单次 tick 卡死几十秒 ✗ **（36 秒那次就是它）** |
| 3 | `forceAreaChunks` | 对整块面积的**每个**区块同步 `getChunk`，并且**每个区块都 `setDirty()` 一次** | 一块面积几十~上百个区块挤在一个 tick 里 ✗ |

> 换算：一次 tick 预算 50ms。若每 tick 因生成区块超时 ~450ms，连续 72 个 tick 就正好累积到
> **~32 秒**，与日志里的 **36128ms / 722 tick** 吻合 ✓。

## 三、修法（补丁已写好并验证）

核心一句话：**申请区块用票据（区块系统在工作线程上加载），主线程只用
`requireChunk = false` 的非阻塞查询问"到了没有"，没到就下一 tick 再来** ✓。

| 改动 | 内容 |
|---|---|
| `surveyStep` | 不再 `getChunk`；用 `ensureSampleChunk()` 检查，未加载就**申请票据并原样重试本样本**（样本计数不推进 ⇒ 不跳过、不重复 ✓） |
| `chooseGroundPortal` | `finishSurvey` 里先经过 `portalSiteChunksReady()`：把要用的 16×9 个区块**一次全部申请**，没到齐就 `return` 留在 SURVEY 阶段；到位后原来的 `getChunk` 全是**缓存命中** ✓ |
| `forceAreaChunks` | 删掉阻塞的 `getChunk`（只挂票据）＋ `setDirty()` 从**每区块一次**改成**整批一次** ✓ |
| `ensureActiveChunksLoaded` | 改名 `activeChunksReady`，改成**非阻塞就绪检查**；三个调用点改成"没到位就下一 tick 再来" ✓（原来是"同步等到加载完" ✗） |
| 票据生命周期 | 采样票据用**独立 owner**（避免和岛屿原点票据撞车 ✗），勘测结束与关服时释放 ✓ |
| 保留不动 | `teleport()` 里那一句 `getChunk` —— 传送必须落在已加载区块，且**只有一个区块 + 玩家主动触发 + 3 秒冷却**，不是热点 ✓ |
