## 二、★ 我这一轮犯的错（必须记下来）

作者报"紫黑方块"时，我查到日志里的真因是对的 ✓ ——
`Failed to load model tnc:models/item/copper_coin.json` ＋
`JsonParseException: Invalid rotation -90.0 found, only -45/-22.5/0/22.5/45 allowed`，
也就是**那四块侧翼带着 `angle: -90`，而原版只接受 22.5 的整数倍，一个非法角度会让整个模型不加载** ✓。

**但我处理错了三步** ✗：

1. **我自己写了烘焙脚本，把 -90 的旋转"解释"了一遍 —— 结果转错了方向**：
   作者那四块侧翼本来是**贴平在币面里、沿 X 长条**的样子，
   我转完变成**沿 Z 竖起来的长条**，币的形状肉眼可见地变了 ✗
   （作者反应："**我模型都被你们改坏了啊，怎么方块都变了**"）。
2. 我**没有先问作者哪个形状才是对的**，而是按自己的几何推算就发了 ✗。
3. 更糟的是我在文档里把"我烘焙出来的那版"写成了正确结果 ✗ ——
   实际上**作者手里就有正确文件**；他随手一贴，问题就解决了 ✓。

**教训（写进铁律第十五条）**：
**"把作者的资源改到能加载"这件事，第一选择永远是"找作者要一份已经能加载的版本"，
而不是自己重算几何** ✗。作者有 Blockbench 工程、有原始文件；
我只有一份坏掉的 JSON，"以坏文件为唯一输入去反推作者意图"必然有猜的成分 ✓。
**改不动就先要源文件；自己动手就必须把"我猜的是什么"写清楚，并且先给作者确认再装机** ✗。
