## 四、★ 第二轮更正（作者："游戏里金银铜三个币模型都有问题，只有金币的模型是正确的"）

上一节"三份原样装进 jar 就对了"的结论**是错的** ✗ —— 装进去之后三个币**还是**紫黑／变形。
真因（这次是逐面算、并对着 1.20.1 原版源码读出来的）：

| 文件 | 上一轮结束时的状态 | 原版加载器实际会怎样 |
|---|---|---|
| `gold_coin.json` | 作者原稿，四个侧翼带**旧式**旋转块 `{"x":0,"y":-90,"z":0,"origin":[...]}` | `BlockElement.Deserializer` 只认 `"angle"` + `"axis"`（`getAxis`/`getAngle` 都是必填，`getAngle` 还只容许 0/±22.5/±45）⇒ **整个模型不加载** ⇒ 紫黑方块 ✗ |
| `copper_coin.json` / `silver_coin.json` | 被"烘焙"过，但 **Y 轴方向转反**（用了 `(z,-x)`；原版是 `(x,z)→(-z,x)`）| 能加载，但四个侧翼落在**币角外面**（x 18..20 / z 11..25），不是币缘（x 16..18 / z 1..15）⇒ 形状变了 ✗ |

烘焙方向的原版依据：`FaceBakery.applyElementRotation` → `Quaternionf.rotationAxis(angle, axis)`
（右手系），轴 Y、角度 A 时 `x' = x·cosA + z·sinA`、`z' = -x·sinA + z·cosA`；
顶点与 UV 的配对来自 `FaceInfo.fromFacing(dir).getVertexInfo(i)` + `BlockFaceUV`
（顶点 i 依次拿 `(u0,v0) (u0,v1) (u1,v1) (u1,v0)`），必要时还要用面上的 `"rotation": 90`
才能逐像素还原。

本轮做的（全部可复现）：

1. **`tools/gen_coin_models.py` 重写** ✓：识别旧式 `x/y/z` 旋转块；按原版右手系烘焙 ±90°；
   **自检逐面比对烘焙前后的 (位置, uv) 对**，不一致就不写盘 ✓
   （旧版脚本的符号错就是上一轮"形状变了"的真正原因 ✗）。
   `python tools/gen_coin_models.py` ⇒ 金币从 `tools/coin_authored/gold_coin.authored.json` 重新导入 ✓
   （四个侧翼：pivot 18,13 → x 16..18/z 1..15；pivot 0,13 → x -2..0/z 1..15；
   pivot 20,13 → x 18..19/z 2..14；pivot -1,13 → x -3..-2/z 2..14 —— 关于 x=8 左右对称 ✓）
2. **银/铜从金币模型重新导入** ✓（同一形状 + `tnc:item/coin_silver` / `coin_copper` 贴图）；
   作者的三枚币本来就是同一个形状，旧的（转反的）两份已被替换 ✓
3. 作者要求"**金币上有七个不同的像素点在正反面，这七个像素点在银铜币上都要保留**" ✓：
   七个标记在 (6,1)(7,1)(8,1)(9,1)(1,6)(14,6)(4,14)(11,14)，背面同 x、y+16；
   银丢 6 个像素、铜丢 4 个（重上色时并进了各自调色板）⇒ `tools/coin_marks.py` 以金币为基准逐像素恢复 ✓；
   模型上这 8 个像素只被 1 号元素（币面）的 `up`（正面）与 `down`（背面）两个面采样 ✓
4. **闸门** ✓：`tools/verify_mod_jar.ps1` 新增 G2，跑上面两个 checker 的 `--check`
