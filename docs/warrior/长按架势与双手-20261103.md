# 长按、架势保持与双手握持（2026-11-03）

这一轮修的是"手感"三件事，全部来自同一个反馈：

> 长按 e 被识别成一直短输入 e；长矛出招后变单手；振刀的长按架势应该按多久保持多久。

---

## 一 长按被吃成"连续短按"：GLFW 自动重复

**症状**：按住 E 不放，连招缓冲里堆满 `E E E E …`，`E+`（长按 E）永远判不出来。

**根因**：客户端原来靠 `KeyMapping#consumeClick()` 判定"按下"。这个计数器不只记真实按下，
**GLFW 的自动重复（`GLFW_REPEAT`）也会往里塞事件**——原版"按住 Q 连续丢东西"就是靠它。
所以按住 E 时每个重复周期都发一次 `TAP`，10 tick 后虽然也补发了 `HOLD`，但缓冲里
已经排了一队 E，服务端的"把刚按下的那一下轻点替换成长按"就替换到了一队 E 的最后一个。

**修法**（`client/WarriorComboKeys`）：

```java
boolean leftNow = LEFT.isDown();      // 只认这个
drainClicks(LEFT);                    // 点击计数照清，但不许当成"按下"
if (leftNow && !leftWasDown) {        // 上升沿 = 真按下
    WarriorComboInputPacket.send(WarriorMove.LEFT, WarriorComboInputPacket.TAP);
}
```

按键状态 `isDown()` 由 GLFW 回调在 tick 之外写好，一个 tick 内就是"当前是否按着"，
自动重复不会改变它。步法键（左 Ctrl）一起改了：原来重复点击会让"长按步法"在松手时
再多发一次 `TAP`（长按 + 短按双发）。

---

## 二 输入包：从两态变四态

`WarriorComboInputPacket` 原来是 `(move, held)`，现在 `(move, mode)`：

| mode | 含义 | 服务端做什么 |
| --- | --- | --- |
| `TAP` (0) | 轻点 | 记一段输入 + 一次基础攻击 |
| `HOLD` (1) | 按住超过 `HOLD_TICKS`(10) | 把缓冲里那一段改写成"长按" |
| `RELEASE` (2) | 松手 | 结束正在保持的架势 |
| `KEEPALIVE` (3) | 还按着（每 10 tick） | 续架势窗口，不产生输入 |

`RELEASE` / `KEEPALIVE` 只有"这一下确实发过长按"时才会发，
所以不会影响普通连招；服务端在没有架势时直接忽略。

## 三 动作包：`START` / `HOLD` / `RELEASE`

`WarriorAnimationPacket` 加了一个 `mode` 字节：

- `START`：正常演一遍，播完 3 tick 后自己过期（原行为）；
- `HOLD`：演到最后一帧**停住**。客户端 `Active#expired` 在 hold 时返回 false
  （只留 200 tick 的安全线），`progress()` 仍然裁在 1，所以姿势就是"定格在收势那一帧"；
- `RELEASE`：客户端把 hold 的 Active 换成"已经演完、再留 3 tick"的普通 Active
  ——松手是**软落地**，不是硬跳回站立。

姿势本身不用改：`WarriorPose` 一直按 `progress()` 取帧，定格就是 progress=1。

## 四 谁会被定格：只有长按的架势招

`WarriorComboService.finisher(..., boolean held)`：

```java
boolean sustain = held && skill.guardTicks() > 0;   // 振刀这类"架势"招
state.heldSkill = sustain ? skill : null;
if (sustain) WarriorAnimationPacket.hold(...); else WarriorAnimationPacket.broadcast(...);
```

- **轻点**放振刀：还是原来那套一次性架势（播完就收）；
- **按住**放振刀：定格，并且每 10 tick 一次 `KEEPALIVE` 把 `stanceUntil`（"架住攻击"的窗口）
  和抗性一起续上——按着就一直在架，松手立刻收架；
- 服务端还有一条 40 tick 的自动收架：客户端突然不续了（关界面、切维度、掉线），
  不能让角色一直摆着架势站在那儿；
- `interrupt()`（Shift 打断）也会顺手清掉 `heldSkill`。

刀光也跟着改了：`WarriorTrail` 用 `WarriorAnimationClient.swinging(id)`，
定格中的架势不算"挥"，不会一直拖一条尾巴。

## 五 双手握持：长枪 / 重剑 / 战锤

**症状**：长枪站着时看着是"双手提着"，一按 Q/E/Z 就变成单手抡——因为基础挥砍走的是
程序化姿势（`WarriorPoseMath`），那里左臂角度是 0，也就是垂在腿边。

**修法**：`WarriorWeaponFamily#twoHanded()`（纯枚举判断，单测能直接钉）：

```java
public boolean twoHanded() {
    return this == GREATSWORD || this == HAMMER || this == SPEAR;
}
```

`WarriorPose` 在程序化姿势套完之后，对双手武器的**左臂做镜像**：

```java
model.leftArm.xRot = pose.rightArmX();
model.leftArm.yRot = -pose.rightArmY();
model.leftArm.zRot = -pose.rightArmZ();
```

为什么是镜像而不是"把左手挪到杆上"：镜像两只手的动作完全对称，任何一帧都不会出现
"一只手在动、另一只手在抽筋"；而按坐标硬挪需要知道每把武器的杆在哪，美术一改模型就错位。
有 Blockbench 关键帧的动作（重剑/战锤/长枪的连招）**不覆盖**——那里的左臂是美术手摆的。
