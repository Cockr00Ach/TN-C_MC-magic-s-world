# 教官课程表（2026-11-03）

> 2026-11-04：槽位及按键已统一，前三槽固定为攻击／振刀／破振刀。旧操作示例由 [统一前三槽与招式辨识](统一前三槽与招式辨识-20261104.md) 取代；历史制作说明保留。

连招系统上线后，演武场的教官只剩"一位教官一节课"：洛克数盾挡、莉娅数蓄满、岚数风刃。
可学员手里已经有十二条连招、四种武器家族、四套架势招 —— 教官却不教这些，图鉴里写着
「洛克专项课」「莉娅」，点进去还是老一套。这份文档记录把它们接上的改动。

## 一、四位教官教什么

课程按顺序开，**做完一节当场开下一节**（不用退出去重新召）。第一课刻意保持与旧版一致：
老存档里"已完成 N 次"记的就是它，旧的服务端测试也按它跑。

| 教官 | 课程 | 目标 | 判定 |
|---|---|---|---|
| 洛克 · 盾卫 | 第一课 · 盾挡 | 5 次 | 举盾挡下教官的挥击（`ShieldBlockEvent`） |
| | 第二课 · 振刀 | 2 次 | 放出任意架势招（`WarriorComboRole.STANCE`） |
| | 第三课 · 铁壁 | 1 次 | 放出 `greatsword_combo_3`（重剑 E Q Z） |
| 莉娅 · 剑术 | 第一课 · 蓄满 | 5 次 | 攻击指示器 ≥85% 命中（`AttackEntityEvent` + 伤害事件） |
| | 第二课 · 破锋式 | 2 次 | `sword_combo_1`（Q Z E） |
| | 第三课 · 旋转斩击 | 2 次 | `sword_combo_2`（Q E Q Z Z Z） |
| | 第四课 · 逆鳞斩 | 1 次 | `sword_combo_3`（Z Z Q Q E E） |
| 岚 · 风刃 | 第一课 · 风刃 | 3 次 | 三格外风刃命中（`WindInfusion` 回调） |
| | 第二课 · 穿云箭 | 2 次 | `bow_combo_1`（长弓 Q Z） |
| | 第三课 · 后跃射 | 1 次 | `bow_combo_3`（长弓 Z E） |
| 演武陪练 | 连招靶 · 任意连招 | 3 次 | 在它身边打出任意三条连招 |

课程表的唯一来源是 `InstructorCourses`；连招 id 直接指向 `WarriorCombos`，**不另抄一份连招表**。
连招改名、改顺序、改门槛，教官这边不用动；反过来课程表里写了不存在的连招 id，
`InstructorCoursesTest` 会当场炸（否则玩家会练一辈子也不过关）。

## 二、连招怎么被"看见"

教官不监听任何连招事件。`WarriorComboService` 每次成功放招都会把冷却写进自己的
`State.cooldowns`（`skillId → 到期 tick`），教官这边**每 tick 轮询冷却的变化**：

```
ready > seen  →  这一招刚被放出来
ready == seen →  没动静
ready <  seen →  冷却被 /tempering combo reset 清零，只更新记录、不计数
```

这样两边文件互不依赖：连招系统加招式、改判定，教官不用改一行。
代价是"放过招但冷却没写"的情况看不见 —— 目前所有连招都走 `resolve()` 写冷却，所以成立。

陪练的连招靶同理，只是它不改 `TemperingTraining` 的状态：守势反击课照常上，
连招靶只旁听，两者互不干扰（守势课超时也不会把连招靶清掉）。

## 三、存档

`SpecialistTrainingData` 里现在有两套计数：

- `role` —— 这位教官一共结课多少次（旧键，含义不变，只增不减）；
- `role/courseId` —— 这一节课出师了没有（0/1）。

课程表靠后者决定下一课开哪节，所以**出师后复习不会把进度打回第一课**。
键的拼法（`role + "/" + courseId`）改了等于把所有人的专项课进度清零，
`SpecialistTrainingData.key()` 上写了注释，别动。

**认不出来的课程键在加载时扔掉**（`keepKnownCourses`）：课程改名会留下 `role/老id` 的死键，
它不只占地方——将来若有新课程恰好用了同一个 id，老进度会被当成"已出师"，玩家直接跳过一课。
死键扔掉后，下一次保存就干净了；`role` 总次数不是课程键，照旧保留。

### 复习按顺序轮转

复习局不再**固定重开最后一课**（以前台词说"想复习哪一节就练哪一节"，可玩家根本点不到别的课）。
现在按"这位教官已经结课多少次"取模：`InstructorCourses.review(role, count)`，四节课轮着过一遍，
课时长一样、仍不写课程键，但会**记一次结课次数**——不然轮转的下一格永远不动。
所以复习四次正好把四节课各过一遍，第五次回到第一节。

### 面板与指令

课程表是"按顺序开"的，所以"我练到哪了、后面还有几课"必须在**不跑回岛上**的地方也能看到。
三处显示读的是同一份服务端数据（`TemperingPacket.courses` / `.course`，协议 v21）：

| 位置 | 显示 |
|---|---|
| 屏幕底部（HUD） | 上课时一条`教官课 · 第二课 · 振刀 1/2`——只靠头顶名字的话，一低头看手就打不到了 |
| 教官终端（右键演武终端） | 选中那位的`莉娅 · 剑术 · 出师 1/4 · 全部 5/11 · 正在上 第三课 · 旋转斩击 1/2` |
| 武器图鉴（K）条目提示 | 带教官的条目多一行`教官 莉娅 · 剑术 · 出师 1/4 · 教的课 第三课 · 旋转斩击`（全学完写"已出师"） |
| `/tempering courses [角色]` | 整张课程表 + 每一项的 ✓/·，"后面还有什么"一次看全 |

## 五、表现

- **举盾循环**：新增 `block_hold`（40 tick 循环）——盾挡课全程架着盾，只有呼吸起伏。
  以前是反复重播 20 tick 的 `block`，接缝处会一顿。实现上**不开第二条控制器**：
  GeckoLib 两条控制器会互相抢同一批骨骼，而是让 `move` 控制器按状态切换动画名。
- **受击反馈**：新增 `hit`（10 tick）——木人桩挨打以前只有血条动，学员判断不出这一下来没来。
- **前摇看得见**：洛克抬手后伤害延后 **8 tick** 落地，并在抬手瞬间放 10 个 CRIT 粒子和
  一次挥击音效（原来只有 5 个粒子，且伤害与动作同一 tick，等于没有前摇）。
- **过关有声音**：每过一课响一次 `PLAYER_LEVELUP`（纯文字在演武场里太容易漏看），
  整套课出师时再响一次 `UI_TOAST_CHALLENGE_COMPLETE`。
- 两套皮肤差异维持原样（四张贴图），没有改模型结构：`InstructorGripModelTest` 与
  生成器里的 17 根骨头、握剑几何、UV 不重叠等检查全部照旧。

模型由 `tools/build_instructor_model.py` 生成（现在导 **8 条**动画），
生成后 `RESULT: ALL CHECKS PASSED` 才算完；**不要手改** `instructor.geo.json` /
`instructor.animation.json`，下次生成会覆盖。

## 八、边界

- 上课期间走开/倒地/换维度 → 课自动取消（45 秒限时仍然在）。
- 教官一次只有一位，召新的会收掉旧的（`adopt()` 里先 `cancel` 再 `remove`）。
- 专项课仍然是**纯练习记录**：不发磨砺、不推进主线毕业、不影响图鉴的"完成次数"门槛
  （图鉴那套条件看的是 `TemperingData`，见 `武器图鉴-20261101.md`）。
- 复习局只给动作反馈，不再写任何记录。
