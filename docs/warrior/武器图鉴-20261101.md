# 战士 · 武器图鉴（2026-11-01）

按 **K** 打开的界面。和魔法石同一套界面语言（底部页签切换分类、左栏说明、右栏条目），
但分类换成了**武器**，解锁方式换成了**条件**——一个磨砺点数都不花。

## 一 和魔法石的对照

| | 魔法石（V） | 武器图鉴（K） |
|---|---|---|
| 分类 | 元素：雷/火/冰/风/暗… | 武器：剑/盾/斧/长柄/弓/风刃 |
| 右侧条目 | 每条链一列，逐级往上 | 每条武器线内的招式链，逐级往上 |
| 怎么解锁 | 花魔法点数，点击即学 | **不花点数**：磨砺到线、训练够次数、评分够高、盾牌试炼毕业 |
| 数据来源 | 服务端同步的 `MagicStoneData` 镜像 | 服务端同步的 `TemperingPacket` 镜像 |
| 网络动作 | 有解锁/配键请求 | **没有新动作**，纯只读 |

为什么不做成"投点数"：磨砺值已经是"永久成长值"，再让它当货币花掉，就等于
把成长和消费混成一条线——练得越久反而越"穷"。所以磨砺只负责**成长与减伤**
（`TemperingRules.reduction`），招式由条件开放。

## 二 六条武器线

| 武器 | 定位 | 条目 | 已实装 |
|---|---|---|---|
| 剑 | 直刺、横扫、反击 | 6 | 3 |
| 盾 | 挡、格、压制；举盾不耗盾耐久 | 5 | 2 |
| 斧 | 与剑共用反击判定，但更重 | 4 | 1 |
| 长柄 | 距离更长 | 3 | **0**（尚未开课） |
| 弓 | 远程 | 3 | **0**（尚未开课） |
| 风刃 | 风灌注武器的主动能力 | 6 | 3 |

合计 27 条：**9 条已实装，18 条规划中**。

长柄和弓没有对应机制，页签照样列出来（免得玩家以为图鉴漏了武器），
点进去只有灰色的"规划中"条目，不会骗人去练一个不存在的东西。

## 三 条件解锁

每个条目写清"要做到什么"，五类条件（`WarriorCodex.Gate`）：

| 条件 | 含义 | 备注 |
|---|---|---|
| 磨砺 | 永久积累值 ≥ N | 只读，不扣 |
| 天赋 | 天赋等级 ≥ N | 角色创建/剧情给的，**训练不提升** |
| 完成训练 | 专项训练完成次数 ≥ N | 来自 `TrainingGroundData` |
| 最佳评分 | 历史最高评分 ≥ N | 0..100 |
| 盾牌试炼 | 已毕业 | `TemperingData.guardGraduate` |

条目三态：

- **已开放**：所有条件满足，亮绿色；
- **进行中**：显示百分比与"还差多少"（例如「磨砺 1000（当前 320）」）；
- **规划中**：尚未实装，恒灰、恒 0%，不参与"点亮"计数。

百分比取**所有条件里最弱的那条**，不是平均值：条件之间是"与"关系，
平均值会让"差一条"看起来像"快好了"。规划中的条目百分比恒为 0，理由同上。

## 四 入口分工（终端瘦身）

| 入口 | 打开什么 | 能做什么 |
|---|---|---|
| **K**（可在 选项 → 控制 → TN-C 改键） | 武器图鉴 | 看六条武器线、条件、进度 |
| 演武场中央终端右键 | 教官终端 | **只有**：选教官、调难度、开始/结束练习 |
| `/tempering panel` | 同一个教官终端 | 同上（命令方便测试） |

终端面板从 360×340 收到 360×196，把磨砺/风刃/守则那一大段文字删掉了——
那些信息现在在图鉴里，而且更完整。终端里按 K 可以直接跳到图鉴。

**协议没动。** 按 K 时客户端先本地开屏，再发一个既有的 `VIEW` 请求刷新数据；
回包到达时按客户端的一个布尔标志决定"重建图鉴"还是"打开终端面板"。
所以 `PROTOCOL_VERSION` 仍然是 14，没有为了一个只读界面去动同步格式。
（2026-11-03：协议已升到 **20**，是为刀波/虚影的同步加了新包，与本图鉴无关。）

## 五 实现

| 文件 | 作用 |
|---|---|
| `warrior/WarriorCodex.java` | 目录 + 条件判定（纯 Java，服务端客户端共用同一段代码） |
| `warrior/client/WarriorCodexScreen.java` | 600×288 面板，`uiScale` 自适应，底部 6 页签，左栏详情、右栏链列 |
| `warrior/client/TemperingClient.java` | `progress()` 把镜像转成 `WarriorCodex.Progress`；`hintCodex()` 决定回包开哪个界面 |
| `warrior/client/WarriorPracticeScreen.java` | 瘦身后的教官终端 |
| `warrior/client/WarriorPracticeKeys.java` | K 改成开图鉴 |

界面细节：

- 底部页签标签带计数「剑 1/3」= 该武器**已点亮 / 已实装**，规划条目不算分母；
- 每行左边画物品图标（剑=**龙之剑**、盾=盾牌、重武器=**重剑**、长柄=**破天戟**、弓=**长弓**、风刃=羽毛），
  未开放盖一层暗色，规划中盖得更重；
  （2026-11-03 起改用战士自己的武器当图标，原来是铁剑/铁斧/三叉戟 —— 图鉴讲的是自研武器线，
  用原版图标会显得在讲别的游戏。）
- 左栏是**选中条目**的详情：名字、`武器 · 链 · 第 N 级`、状态、进度条、效果、怎么练、逐条条件（✓/·）；
- 悬停任意一行给同样的信息（tooltip 画在缩放之外，跟随真实光标）。

## 六 测试

**单元测试** `WarriorCodexTest`（9 项，`gradlew test --tests '*WarriorCodexTest*'`）：

- id 唯一、链非空、级数从 1 起；
- 规划条目永不"已开放"、不指向教官；
- 已实装条目必须写条件（否则等于白送）；
- 条件判定与提示文字用的是同一份数字；
- 百分比取最弱一条（用构造出来的探针条目测规则，不受目录改动影响）；
- 无天赋角色一个条目都不亮；
- 六条武器线都有页签，长柄/弓确实没有已实装条目；
- 页签计数只数已实装。

**渲染审计** `tools/test-warrior-ui.ps1`（开发客户端，不进存档）：

- 9 张截图：训练面板 3 种状态 + 图鉴 6 个页签各一张；
- 断言训练面板 8 个按钮、三个动作按钮的可用态与数据一致、恰好一位教官被选中；
- 断言图鉴有 6 个页签，并且**真的用鼠标点击**切换页签后，该页条目数等于目录条目数
  （顺带验证小窗口下 `uiScale` 的点击坐标换算没算歪）；
- 断言所有按钮**整个落在面板内**：条目一多就会被排到面板外，那种"点不到"只能靠几何断言抓。

顺带修掉一个只有"面板被重进"才会暴露的老问题：`WarriorPracticeScreen.init()` 原来拿
`this.width` 再除一次 `fit`，而服务端每推一次快照都会 `rebuildWidgets()` → `init()`，
连推两次面板就会越缩越小。现在两个界面都从**窗口真实尺寸**重算，重进多少次都不变。

服务端 19 项 GameTest 不受影响（本版没有改任何服务端判定）。

## 七 边界

- **图鉴不发放任何能力**。它只读进度；"能不能用"仍由各自机制判定
  （例如风刃要求风灌注武器 + 200 磨砺，图鉴只是把这条写清楚）。
- 天赋不能靠训练提升，图鉴里把它当门槛显示，不是"可练项"。
- 长柄/弓的页签是占位：先有分类，再谈机制。
- 规划条目只是路线图，落地时要先实装机制，再把 `implemented` 改成 `true`
  ——`plannedEntriesNeverPretendToBeAvailable` 会盯着这条。
