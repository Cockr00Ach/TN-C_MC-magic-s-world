# 战士修习体验优化

在既有天赋、磨砺减伤、守势反击与风灌注基础上改善成长准确性和实战反馈。天赋 0 不能成长、普通玩家不能改天赋的规则保持有效。

## 玩家可见的变化

- `/tempering panel` 打开「战士修习」，查看天赋倍率、个人磨砺上限、当前减伤、下一成长目标、首次训练完成情况和风刃冷却。
- 界面可开始/取消守势反击训练。开始后关闭界面返回实战；所有资格和奖励仍由服务器判定。
- 实战训练期间显示三次格挡进度、四秒反击倒计时和超时提示。窗口超时后再次格挡即可刷新。
- 重复开始不会重置正在进行的格挡进度；失去资格（倒地、死亡、旁观、创造或天赋归零）时结束本次训练。
- 首次训练预期奖励会计入天赋倍率与剩余上限；已经完成首次训练的角色显示练习状态。
- 成长提示使用当前角色的个人上限。达到新阶段或天赋上限时给出一次明确提示。

## 成长精度

原先每笔奖励单独向下取整，低天赋在多笔奇数奖励时会丢失半点成长。现在以半点为最小精度累积，并写入世界存档。

例如 1 级天赋连续获得两次基础 3 点奖励：第一次增加 1 点并保留 0.5，第二次增加 2 点，总计 3 点，符合 0.5 倍成长。退出再登录不丢失余数。达到上限时清除溢出的余数；管理员直接设置磨砺或改变天赋时清除之前的余数。

原始磨砺存档保留，当前有效磨砺仍受到天赋上限约束；没有通过界面加入、自选或重掷天赋的入口。

## 同步与验证

协议版本 11，客户端和服务器需一起更新。服务器只在状态变化时同步训练和冷却，客户端按游戏 tick 显示倒计时，避免每帧发请求。客户端只能发送查看、开始、取消动作，无法提交点数、天赋或领奖数量。

10 项规则测试和 8 项隔离服务端测试已通过，覆盖半点累积/保存、个人上限、反击窗口边界、重复开始保留进度、资格失效中止，以及界面状态网络往返。既有减伤、首次奖励防重复和灌注炉台回归也通过。

界面渲染检查通过 `powershell -File tools/test-warrior-ui.ps1` 运行。该检查在开发客户端标题页使用模拟显示状态，覆盖无天赋、可开始修习、低天赋窗口过期、高天赋反击窗口/冷却四种画面，并核对开始/取消按钮的启用状态。它不进入存档；审阅环境临时排除与面板无关的 `ArcanaGhostRendererMixin`，结束后恢复原构建资源，因此不等价于完整整合包实战验证。

本次四种画面均已实际渲染、人工查看，按钮状态断言通过。预览：[可开始修习](../previews/warrior-practice-ready-20261026.png)、[训练窗口和冷却](../previews/warrior-practice-active-20261026.png)。
