# 剑虚影透明与遮挡修复（2026-11-14）

问题来自三处叠加：放大剑影使用 `entityTranslucentCull`，透明面仍写深度，可能挡掉后续怪物模型；附魔物品的 glint 与正常模型又被重定向到同一个缓冲，重复提交几何；连招高 alpha 与多盒模型的内部面叠加，使虚影过实。另外，旧 Alpha 顶点包装器的 float 路径会再次进入 int 路径，重复乘 alpha，修复这一点时必须同时降低目标不透明度。

新增独立虚影材质，使用物品图集、标准透明混合、背面裁剪与 LEQUAL 深度测试，只写颜色；保留光照、覆盖纹理和普通雾色。原本的实体武器与上一轮实体饰件材质没有改动。

虚影烘焙模型每个 renderPass 只通过 `renderModelLists` 提交一次，保留原有相机变换、握柄缩放、纹理和染色，不再为虚影重复构造附魔闪光。逐面的不透明度范围为普通攻击 .07–.10、连招 .10–.14；第一人称再乘 .65，另乘原有攻击渐入渐出。刀光、剑气与大招光效保留。

第一人称仍在手部阶段绘制。第三人称只在世界收集窗口捕获实际武器矩阵、法线矩阵与模型，最多 64 项，在 `AFTER_LEVEL` 的主目标恢复之后绘制；保存并恢复全局模型视图矩阵与雾距，不能再乘该事件的 PoseStack。队列在帧首、窗口结束或换世界时丢弃旧请求，拒收背包人物预览等窗口外提交。

客户端回归覆盖透明度上限、各顶点颜色路径单次缩放、材质字节码、附魔不再重复绘制与帧队列生命周期，并复查上一轮的实体饰件遮挡。实际日志、测试数量、JAR 哈希、原包逐条保留检查与安装备份记录在 `work/weapon-phantom-transparency-release-20261114/receipt.json`。

本轮不拉取或推送提交，不修改存档。尚未进行实际 GPU/Oculus 视觉验收；第三人称在透明水体后的合成排序仍需实机观察。
