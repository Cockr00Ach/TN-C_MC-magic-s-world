# 战士 · 连招动画制作说明（2026-11-01）

给"自己动手做下一把武器动作"用的一页说明。现有 15 条动画全部按这套规则，
`WarriorComboAnimationsTest` 会盯着其中每一条。

## 一 文件放哪

```
src/main/resources/assets/tnc/animations/entity/战士连招/
├── 长剑连招.json    4 条（美术原作）
├── 重剑连招.json    4 条
├── 战锤连招.json    4 条
└── 长弓连招.json    3 条
```

Blockbench 里直接 **Export → Bedrock Animation**（`format_version: 1.8.0`），
骨骼名必须和 `assets/tnc/geo/entity/self.geo.json` 一致：

| 骨骼 | 管什么 |
|---|---|
| `bone` | 整个人（yaw = 转身、pitch = 前倾后仰） |
| `head` | 头 |
| `armLeft` / `armRight` | 两条手臂（x 负值 = 向前/向上抬） |
| `legLeft` / `legRight` | 两条腿（x 正 = 抬腿） |

路径里有中文没关系：客户端是**按 classpath 直接读**的，不走 `ResourceLocation`
（后者只允许 `[a-z0-9/._-]`，中文路径构造就抛异常）。开发环境和打包后的 jar 都成立；
正式客户端里还会用 Forge 的 `ModFile#findResource` 兜一次底，两条路都读不到才算丢文件。
进游戏后 `logs/latest.log` 会打印 `TN-C: 连招关键帧 15 条 -> [...]`，条数不对就是这里的问题。

## 二 动画名规则

动画名 = **武器前缀 + 按键序列**，和连招顺序一一对应：

| 动画名 | 招式 | 顺序 |
|---|---|---|
| `长剑QZE` | 破锋式 | Z Q E |
| `长剑QEQZZZ` | 旋转斩击 | Q E Q Z Z Z |
| `长剑QE长Z` | 架势·振刀 | Q E + 长按 Z |
| `长剑ZZQQEE` | 逆鳞斩 | Z Z Q Q E E |
| `重剑ZQE` / `重剑QQZ` / `重剑EQZ` / `重剑QEE` | 破阵斩 / 山崩 / 铁壁 / 壁立 | 见环 |
| `锤QZZ` / `锤EEZ` / `锤ZQQ` / `锤QEQ` | 碎骨 / 震地 / 断招 / 沉渊 | 同上 |
| `弓QZ` / `弓EQ` / `弓ZE` | 穿云箭 / 疾影射 / 后跃射 | 同上 |

名字同时是代码里的键（`WarriorComboAnimations.BY_CLIP`），**改名要同步改代码**，
否则那一条会被当"文件不存在"，退回程序化动作。

## 三 时长必须对得上

`animation_length`（秒）× 20 = `WarriorAnimation` 里那个枚举的 `durationTicks`。

| 动画 | 文件时长 | 枚举 tick |
|---|---|---|
| `长剑QZE` | 0.875 | 18 |
| `重剑QQZ` | 1.10 | 22 |
| `锤EEZ` | 1.15 | 23 |
| `弓EQ` | 0.70 | 14 |

差 1 tick 都会让动作卡在最后一帧（服务端广播的时长更短）。这条由
`clipLengthMatchesTheBroadcastDuration` 一次性验完全部 15 条。

## 四 关键帧写法约定

- 时间是**秒**，角度是**度**；关键帧之间线性插值，超出首尾取端值。
- **首帧必须是全 0**（人站着），否则动作一开始会从奇怪的角度"弹"过去。
- **末帧建议回到 0**，让动作结束瞬间接回原版待机姿势；长剑四招的收势帧留在
  前倾姿势上也没问题（动作放完立刻回待机，看不出跳变）。
- **两条手臂都要动**：重剑/锤是双手武器，只动右臂看起来像在甩棍子。
- `position` 关键帧**会被忽略**：文件里写 `[0,0,-60]` 那种"整体前冲"不会生效，
  位移由服务端 `dash / backstep` 负责，客户端再叠一次会看到人被推两次。
- 转身用 `bone` 的 y（`长剑QEQZZZ` 的旋身是 687.5°，超过 360° 才会真的转一圈）。
  **注意**：`bone` 的 yaw 在游戏里是"整只模型绕脚下转"，不是只扭躯干 —— 所以想让人原地转身
  就把角度写足，不需要（也不要）在 `body` 上再补一份。
- 左手玩家由 `WarriorPose` 自动镜像，不用做两套。

## 五 加一把新武器动作：四步

1. **放文件**：`assets/tnc/animations/entity/战士连招/<武器>连招.json`。
2. **加枚举**：`WarriorAnimation` 末尾追加（id 就是 ordinal，**只能往后加**），
   数值填 `animation_length × 20`，`cn()` 补中文名。
3. **接映射**：`WarriorComboAnimations.BY_CLIP` 加 `动画名 → 枚举`；
   如果是一份新文件，再往 `FILES` 里加一组路径（第一项中文名，第二项 ASCII 备用名）。
4. **挂连招**：`WarriorCombos` 里对应 `WarriorSkill` 的 `animation` 参数换成新枚举。

`WarriorPoseMath` 里最好也补一个 `case`（挑最接近的程序化动作），
那是"文件丢了"时候的退路，不会 T 字。

## 七 动画"看不见"的四个坑（2026-11-01 全踩过）

按顺序排掉，基本就能定位到底是哪一层断了：

| 现象 | 真实原因 | 怎么确认 |
|---|---|---|
| 按了连招，人和平时一模一样 | 注入点挂在 `HumanoidModel#setupAnim` TAIL，而 `PlayerModel#setupAnim` 在 `super` 之后还会跑 `setupAttackAnimation()`；连招一放就 `swing()`，我们摆的手臂被原版挥砍覆盖 | 改成注入 `PlayerModel#setupAnim` TAIL（现版本）；改完日志里应是 `Mixing WarriorPoseMixin ... into net.minecraft.client.model.PlayerModel`，且没有 `Mixin apply failed` |
| 启动报 `InvalidInjectionException: Invalid descriptor` | `PlayerModel<T extends LivingEntity>`，擦除后描述符是 `(LivingEntity;FFFFF)V`；写成 `Player` 就匹配不上，refmap 也要跟着改成 `PlayerModel;m_6973_(...LivingEntity...)V` | 报错原文里 "Expected ... but found ..." 两个描述符对比着看 |
| 动作文件明明在 jar 里，游戏里却是程序化姿势 | 客户端 `latest.log` 里会有 `TN-C: 动作 XXX 没有骨骼关键帧`；对应 `WarriorComboAnimations.BY_CLIP` 的键名和 JSON 里的动画名不一致 | `grep "连招关键帧" logs/latest.log`，正常应打印 `连招关键帧 15 条 -> [长剑QZE, ...]` |

另外两条容易忽略的：

- 必须在**第三人称（F5）**看自己，第一人称只渲染手臂。
- 一次终结技只有 0.9～1.2 秒，按完连招立刻看，别等收招之后。

第四条坑（转身方向这条最容易白做一天）：

| 现象 | 真实原因 | 怎么确认 |
|---|---|---|
| 回旋斩/旋身动作"完全不转"，只有上半身拧了一下 | 根骨骼 `bone` 的 yaw 被加到了 `body` 上。原版人形模型的 `rightArm/leftArm/leftLeg/rightLeg` 挂在**模型根**上，`body` 里只有一个躯干方块，所以只转躯干 | 现在 `bone` 的 yaw 由 `WarriorPoseRender` 旋转 `PoseStack`（等价 Blockbench 旋转根骨骼），`WarriorPose` 只把 x/z 加到 `body`；单测 `rootYawIsHandedToTheWholeModel` 钉住了 687.5° 这个值 |
