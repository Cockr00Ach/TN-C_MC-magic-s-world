## 一、证据：加载期的失败按来源统计

数据来自客户端 `logs/latest.log`（2026-10-06 22:25 那次启动，37042 行）。

### 按命名空间（模型/方块状态加载失败）

| 命名空间 | 失败条数 | 说明 |
|---|---|---|
| **`conquest`** | **3626（blockstate）＋ 553（模型）** | ★ 压倒性主因 ✗ |
| `kaleidoscope_end` | 80 | 别的 mod |
| `soulsweapons` / `beyonddimensions` | 各 16 | 别的 mod |
| **`tnc`（我们）** | **12（blockstate）＋ 9（模型）** | 见第三节 ✓ |

### 异常类型

| 异常 | 次数 | 谁 |
|---|---|---|
| `JsonSyntaxException: Missing axis, expected to find a string` | **367** | conquest ✗ |
| `FileNotFoundException: conquest:models/block/generic_branch/template/tinted_overlay` | **125** | conquest ✗ |
| `FileNotFoundException: .../thin_diagonal_*` | 78 | conquest ✗ |
| `FileNotFoundException: .../thick_diagonal_mossy_*` | 70 | conquest ✗ |
| `JsonParseException: Invalid rotation 10.0/31.0/15.0/7.0/9.0/12.0/12.5/44.0/17.0/21.0 found, only -45/-22.5/0/22.5/45 allowed` | 合计约 **110** | conquest ✗ |

> ★ **`conquest` 的模型里有大量非法旋转角**（10°、31°、15°、7°、44°……）。
> 原版只接受 **−45 / −22.5 / 0 / 22.5 / 45**，**一个非法角就让整个模型不加载** ⇒
> 它每一个方块状态都要失败一次、都要打一整段栈 ✗ ——
> 这正是"加载特别久"的机器级原因（**和我们的法术无关**）。

来源：`mods/ConquestReforged-forge-1.20.1-1.6.0.jar`（**103 MB**）。

## 二、★ 我们自己也造了一处伤（**已修**）

日志里有一条是**我们自己的**：

```
[ModelManager] Failed to load model tnc:models/projectile/dark_hand.json
JsonParseException: 'from' specifier exceeds the allowed boundaries: (-1.820E+0 -2.510E+0 -2.375E+1)
```

**真因是我上一轮加的"黑线"** ✗：
为了"几条黑线拴着好几只手"，我把模型拉长到 z ±29.75，而原版加载器只允许 **−16 .. 32**
⇒ **整个模型拒绝加载** ⇒ 那只手在游戏里**根本是隐形的** ✗。
（`recenter()` 把包围盒中心放到原点，所以**模型一旦长过 ~32 单位，最近居中就必然越界** ✓。）

**已修** ✓：
1. 模型本身做短（黑带 z −15..−7.5、三只手按 1.25 缩放 ⇒ z 收在 −18..+15），
   **整体交给 spell JSON 的 `scale` 去放大**（那正是 `scale` 存在的意义 ✓）；
2. `recenter()` 现在**自己会夹取**到加载器窗口内（能居中就居中，不能就贴边用满窗口；
   实在超过 47.8 单位直接**报错而不是静默生成废模型** ✓）；
3. 尺寸仍按"意图长度"重算 ⇒ t1~t5 依旧是 **1.6 / 3.2 / 8 / 16 / 32 格** ✓。

## 三、★ 新增闸门：这类"构建绿、游戏里隐形"的坑不能再靠日志发现

`tools/verify_mod_jar.ps1` 原来只查 `models/item/**`（D1b7），
理由是"别的路径走不同的加载方式" —— **那个理由对投射物模型是错的** ✗
（日志明确显示 `dark_hand` 是被 **ModelManager/ModelBakery** 拒的 ⇒ 它走的就是普通面包房 ✓）。

新增 **D1b8**：扫 `assets/tnc/models/**`，检查 `from`/`to` 是否在 **−16..32** 内 ✓。分两级：

| 路径 | 级别 | 依据 |
|---|---|---|
| `models/projectile/**` | **PROBLEM（红）** | 有实证：日志里 `dark_hand` 就是被普通面包房拒的，游戏里会被画 ✗ |
| `models/block/**`、`models/entity/**` | **note（黄）** | 只有 6 个此类模型已经越界，**属于结构/展示那边的工作、不是法术这边的** ✓；每次跑都会列出来，不会被忘掉 ✓ |

## 五、给作者的直接建议（按收益排序）

1. ★ **先动 `ConquestReforged`**：它是加载慢的主因（约 6450 条失败）。
   二选一：
   - **换版本**（1.6.0 的模型旋转角大面积非法，很可能是它自己的打包问题）；
   - 或者**先禁用它**试一次启动 —— 如果加载时间立刻大幅下降，就确认是它 ✓。
2. **`resourcepacks/` 里有 5 个包**（含 66 MB 的"无限战争材质包"与 `TN-C-Models.zip`）——
   资源包会**成倍增加烘焙量**。逐个禁掉试，是最快的二分法 ✓。
3. **内存**：日志里**没有** `-Xmx` 记录（PCL 不写进日志）。若分配偏低（<6G），
   加载期会大量 GC ⇒ 表现为"特别久"。这个我读不到，**要你在 PCL 里看一眼** ✓。
4. **帧率低**要另测：这份日志是**加载期**的，里面**没有** tick 超时或渲染警告
   （`tick took` 命中的都是别的 mod 的版本说明文字，不是真的超时 ✗）。
   要查帧率得靠**卡的时候的 `logs/debug.log`**（F3 也会显示实体/区块数）——
   请把**卡的那一段**发我，我按同样方式定位 ✓。
