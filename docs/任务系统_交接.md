## 四、🔴 三条硬知识（都是这轮实测出来的，别再踩）

### 4.1 作者的章节**从来没进过 git** —— `config/` 被整体排除

所以 `config/ftbquests/`、`config/whisperingquests/` **都不在版本库里**：

- `git checkout` **救不回来** ✗
- 归档前的工作区副本删掉后就没第二份了

**后果**：`archive/author-quest-content/` 是作者旧章节的**唯一副本**，
已为它加 `.gitignore` **唯一例外**并提交（含 `MANIFEST.txt` 的 SHA256 清单，可用于核对副本完整）。

### 4.2 ⚠️ **同一个坑会卡住我们自己的正文**（待拍板）

我们新写的 FTB 章节同样**不会进 git** → 换机就丢、队友拿不到、只能手工搬进整合包。
**需求**：给 `config/ftbquests/quests/` 放开一个例外纳入版本控制。
不做的话，任务系统的产出就是"**不在仓库里的仓库内容**"。
（`剧情总纲.md` §八 编剧系统 AAA 也独立提了同一条，两边判断一致 ✓）

### 4.3 `sync.cmd` 只增不删，而且是双向的

| 命令 | 行为 |
|---|---|
| `push` | 只覆盖已存在且工作区较新的文件；**不删除**目标端多出来的文件 ✗ |
| `pull` | 会把游戏端多出来的文件**同步回工作区** ✗ → 删掉的东西会"复活" |

**所以删任务章节必须两边都删**：工作区删 + 游戏实例删。只删一边迟早出问题。

## 五、作业流程（写一章任务）

```
0. 先读 剧情总纲.md（§6.2 单条任务结构 / §6.3 术语表 / §6.4 红线）；有缺口就回去问编剧系统 AAA
1. 写章节：config/ftbquests/quests/chapters/<id>.snbt
   · id/filename 是 16 位大写十六进制（作者的习惯，可直接沿用同风格）
   · 新章节挂到分组：改 chapter_groups.snbt（建议新增 &6TN-C · 元素觉醒，见 剧情总纲 §6.1）
2. 需要 NPC 对话触发 → 在 ftbq_bindings.json 加一条 <对话节点> : <任务 id>
   ⚠️ 任务 id 必须真实存在于某个章节里，否则就是悬空引用（这次删章节踩到了）
3. 同步：cd D:\ModTest\modpack ; .\sync.cmd push
4. 重启游戏（任务数据在启动时读；/reload 不一定重读任务）
5. 进游戏按 J 打开任务界面，逐条核对标题/描述/目标/奖励
6. 回报：把"实施结果 + 遇到的问题"写进本文或交接段；数值/机制类需求写「需求单」给对应专题
```

**口径基准**（编剧系统 AAA 定）：任务标题 ≤12 字人话、描述 2–4 句讲"为什么"、
**NPC 不解释系统**（不要说"需提升亲和力到 6"，要说"你身上的火还没烧透"）、
术语统一用**魔法石 / 亲和力 / 魔法点数 / 链 / 勇者级 / 领域魔法**。
