## 二、真因：Blockbench 新版导出的**多轴旋转**，原版不认

出问题的元素长这样（三个 coin 里各有 4 处）：

```json
"rotation": { "x": 0, "y": -90, "z": 0, "origin": [18, 0, 13] }
```

而**原版只认单轴形式**：

```json
"rotation": { "angle": -90, "axis": "y", "origin": [18, 0, 13] }
```

原版 `BlockElement.Deserializer` 直接读 `angle` / `axis` 两个键 → 读不到就抛
`Missing axis, expected to find a string` → **整个模型文件加载失败**（不是丢掉那一个元素 ✗）。

> ⚠️ 注意：`"texture_size"` 在**物品模型**里是合法的（Blockbench 会写，原版忽略它）✓ ——
> 它**不是**这次的原因。`投射物模型_配方.md` 里那条"必须删 texture_size"是**投射物烘焙**那条路的
> 特殊要求，不要混为一谈 ✗。

## 三、修好了什么

新增转换器 **`tools/fix_multiaxis_rotations.py`**（纯 ASCII，可重复跑）：

```
python tools\fix_multiaxis_rotations.py
```

它对 `assets/tnc/models/` 下每个模型：

1. **只有一个轴非零**且角度是 22.5 的倍数 ⇒ **无损**改写成 `{angle, axis, origin}` ✓
   （原版角度语义 = 绕该轴转 `-angle`，所以直接沿用原值即可 ✓）
2. **角度为 0** ⇒ 整个 `rotation` 键删掉（原版没有 rotation 就是"不转"）✓
3. **多于一个轴非零** ⇒ **拒绝猜**，报 `[manual]` 让人工处理 ✓（见 §四）

## 四、⚠️ 另一件没修的事：**龙的展示模型也加载不了**

扫描发现还有 3 个文件是多轴**同时非零**，脚本拒绝转换：

```
models/block/dragon_display_dark.json
models/block/dragon_display_light.json
models/entity/dragon_block.json
```

它们的旋转是这种（100 个元素里几乎每一个都带）：

```json
"rotation": { "x": 2.23, "y": -5.91, "z": 1.2, "rescale": false, "origin": [...] }
```

**为什么不能像 coin 那样机械转换**：原版元素旋转**只支持一个轴**（角度还得是 22.5 的倍数），
而龙这些角是**任意值、三个轴同时非零** ⇒ 原版**根本没有对应的表达能力** ✗。
硬改成单轴会把龙的姿态弄坏（比"加载失败"更糟：能显示但是歪的）。

**它是哪来的**：`tools/gen_dragon_block_model.py` **故意**这么生成的 ——
脚本注释写着把"cube → 骨骼 → root"整条链**折成一个 vanilla 元素旋转**，
并自己推导了 `rx(-X) @ ry(-Y) @ rz(Z)` 这个乘积。**推导本身是对的**，
漏掉的只有一件事：**原版反序列化器不认 `{x,y,z}` 这种写法** ✗。

**三条出路**（需要作者拍板，我不擅自改，因为会动到龙的外观）：

1. **换成 geo + GeckoLib 渲染** —— 走和 `庄鹊让`/天使同一条已验证的路，
   骨骼原生支持多轴 ✓，而且不用再"折角度"；代价是渲染器要重写。
2. **把旋转烘进顶点** —— 原版模型只支持轴对齐的方块 ✗，只有 90° 的倍数才可能，
   所以对这条龙**基本不可行**（角度是 2.23 / -5.91 这种）。
3. **保留现状**（龙展示体继续不显示）直到重做 —— 最省事，但要接受"这两条龙现在看不见"。

> 影响面：`dragon_display_light` / `_dark` 是载具方块，被
> `TNLightDragonChain` / `TNDarkDragonChain` 用来"把龙装进展示里" ✓ ——
> 也就是说**这两条链的展示环节现在是坏的**（法术本体不受影响）。

## 五、给下一个接手的人的检查清单

**任何新模型进 jar 之前，跑这两条**：

```powershell
# 1) 结构性检查：有没有原版表达不了的 rotation
python tools\fix_multiaxis_rotations.py

# 2) 装机（脚本会跑 verify_mod_jar.ps1）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-to-pack.ps1 -Wait
```

**装机后**（进过一次游戏、走到资源加载完）搜日志 —— 这是唯一能证明"模型真的能用"的地方：

```powershell
Select-String -Path <实例>\logs\latest.log -Pattern 'Failed to load model|Unable to load model'
```

> 教训：**物品/方块的"注册"和"模型加载"是两件事** ✓。
> 注册成功只保证 `/give` 拿得到东西，**模型能加载**才决定它是不是紫黑 ✗。
> 而"模型加载失败"平时**没有任何红字进聊天栏**，只在资源重载日志里 —— 所以必须去日志里查。
