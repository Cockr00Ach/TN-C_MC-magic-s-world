## 一、怎么跑起来（每天要用的命令）

```powershell

$env:JAVA_HOME = 'C:\Users\FDCX\AppData\Roaming\.minecraft\runtime\java-runtime-beta'

.\gradlew.bat build

# 2) 装进整合包（⚠️ 游戏开着会拒绝覆盖 jar —— 这是保护机制，不是 bug）
powershell -ExecutionPolicy Bypass -File tools\install-to-pack.ps1

# 3) 验证（jar 内容 / 法术清单 / 效果白名单 / mixin / 字节码版本 …）
powershell -ExecutionPolicy Bypass -File tools\verify_mod_jar.ps1

# 4) 把改动同步进整合包（kubejs 与 TN-C 资源包；Java 改动要靠 2) 装机）
cd D:\ModTest\modpack
.\sync.cmd push
```

> **任何时候都不要用 `git add -A` 直接提交大文件** —— 仓库守卫会拦（单文件 >2 MB），
> 整合包本体与世界存档一律走网盘，不进 git。

## 四、改代码时的铁律（每条都是踩出来的）

1. **`tools/*.ps1` 必须纯 ASCII** —— 中文注释被 GBK 读法吞换行会导致整个脚本解析失败
2. **先写引擎 JSON、再进目录** —— 反过来会"学得到但放不出"、法杖多空槽
3. **学派名**：风=`AIR` ✗WIND、暗=`SOUL` ✗DARK、光=`HEALING` ✗LIGHT
4. **音效 id**：只有 `spell_engine:generic_<school>_casting/release`，**风系只有 `generic_wind_charging`**
5. **原版效果优先**：absorption/resistance/regeneration/blindness/slowness/speed/strength/wither…
   只有"精确数值的自定义增益"（风 +300%、火 +200%）才必须写效果类
6. **加枚举值前先 grep 全项目的 switch**，或者先给各处 switch 加 `default` 兜底再改
7. **生成出来的文件要改就改生成器**，别手改（会被覆盖 + 容易改漏）
8. **构建命令必须带守卫**：`BUILD FAILED` 就不提交、自动回滚
9. **"观感不对"先查字段**（比如射线像火球 = 缺 `orientation`），再考虑美术
10. **别凭印象数东西**：数法术要**解析 JSON**、数调用点要 **grep**、找插入点要看**上下文**（别抓第一个匹配）

> 详细版见 `PROJECT-STATE.md` §6（引擎能力：三种模板 / CLOUD / AREA / BEAM / orientation /
> 原版效果 / 学派名 / 音效）与 §7（方法论六条）。
