# 新同伙加入：运行包、源码与协作

第一次加入请给三件东西：**当前完整整合包压缩包、GitHub仓库地址、明确分工**。只给仓库还不能保证能开游戏；只给压缩包则不能形成源码协作。

## 首次运行包

压缩当前版本目录：`D:/垃圾桶/PCL 正式版 2.9.3/.minecraft/versions/元素觉醒1.4.3-魔改版-20260915`。发本轮修复安装后的包。内部合作者需要的模组、KubeJS、配置与资源可一起给；是否附个人测试存档取决于分工。做天空岛内饰必须另明确给哪个专用世界，做代码通常不需要所有私人存档。

新人要使用Java17，启动器要能补齐Minecraft本体、assets与libraries；它们可能在版本目录之外，所以版本文件夹压缩包不等于一套离线独立启动器。现有启动器能联网下载依赖即可。账号登录和个人凭据由新人自行配置，不发送你的账号令牌。

## 仓库与运行目录分别放

仓库：`https://github.com/Cockr00Ach/TN-C_MC-magic-s-world`。

你在GitHub仓库设置里邀请新人的账号为协作者，对方接受邀请。新人克隆到独立源码目录，另将整合包解压到游戏运行目录。让Agent知道这两个绝对路径，配置Java17，阅读最新状态与交接文档，确认构建和安装方式。

源码中的`modpack`是需要同步的补丁文件，并没有保证包含所有第三方模组、完整资源和运行依赖。不要在解压整合包里直接`git init`后把所有存档、日志、缓存上传。编译产物由Agent安装进运行包`mods`，KubeJS等补丁按明确清单同步。

本轮已拉取并合并同伙的光系法术、龙、天使和阿波罗资源更新。当前本地修订若尚未推到远端，新人单纯clone远端不会拿到这些未推送的本地新修改；可同时给本轮源码交接压缩包，或者随后通过正式分支/PR同步。不要把“已经拉取”理解为“本地所有工作已经推送”。

## 每天怎么协作

1. 开工前拉取最新代码，先保存自己的修改；不随便强制reset或覆盖别人改动。
2. 每个人有明确范围和独立分支；一项工作一个提交/PR，说明变更、测试与安装版本。
3. 避免同时编辑相同法术目录、中央注册表、中文语言文件。必须一起改时先沟通文件负责人。
4. 天空岛内饰继续由装修负责人维护；原始世界单独回传，不擅自改生成模板。主任务书由主策维护，别人新增页或改奖励应说明具体文件，不能整套覆盖。
5. 存档、模型和大资源使用明确版本号与修改清单，不把最后收到的压缩包无差别覆盖所有文件。
