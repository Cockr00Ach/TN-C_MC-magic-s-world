## 二、第三条：**闸门错，文件对**，照他们说的改反而会把好的改坏

协作者报的是：

```
data/tnc/dialogues/tavern/guest_01.txt -> @id tnc:tavern/guest_01 (expected tnc:guest_01)
```

他们的结论："这 49 个文件 `@id` 与文件名不匹配 ⇒ **NPC 会哑巴**"。
**实测结论相反** ✗ —— 我把三处源码都读了，它们**自洽**，文件写 `tnc:tavern/guest_NN` 是**必须**的：

| # | 位置 | 代码 | 含义 |
|---|---|---|---|
| 1 | `tavern/TavernGuestEntity.mobInteract` | `ResourceLocation.fromNamespaceAndPath("tnc", "tavern/" + seatId)` | 酒馆客人的对话 id **就是** `tnc:tavern/guest_NN` ✓ |
| 2 | `dialogue/DialogueLoader.get` | `ResourceLocation.fromNamespaceAndPath(ns, DIR + "/" + id.getPath() + ".txt")` | 拿这个 id 去找的正是 `dialogues/tavern/guest_NN.txt` ✓（文件确实在那）|
| 3 | `dialogue/DialogueLoader.parse` | 断言"文件里声明的 `@id` == 加载用的 id" | 所以文件里**必须**写 `tnc:tavern/guest_NN` ✓ |

**反证**：如果按闸门要求改成 `tnc:guest_NN`，加载器就会去找
`data/tnc/dialogues/guest_NN.txt` —— **那个文件不存在** ✗ ⇒
`DialogueLoader` 打 `script file missing` ⇒ **那才会真的哑巴** ✗。
**所以"修"这 49 个文件 = 把正确的改成坏的。**

**真正的 bug 在闸门**：它把期望值算成"命名空间 + **文件名**（去掉扩展名）"，
**漏了子目录** ✗ —— 只对根目录下的文件成立。根目录那 12 个文件因此一直是绿的，
直到上游把酒馆客人放进 `dialogues/tavern/` 才暴露 ✓。

**修法**（`tools/verify_mod_jar.ps1`）：期望值改成
`tnc:` ＋ 该文件**相对 `data/tnc/dialogues/` 的路径**（去掉 `.txt`）✓ ——
根目录文件的行为不变（相对路径就是文件名本身）✓。

验证：

```
[ok] dialogue directives are well-formed (0 @act, ids match file names)
exit=0
```

（`@act` 计数为 0 是正常的：这 49 个酒馆短句脚本本来就没有 `@act` 指令 ✓。）
