# 新机器环境配置（clone 之后第一次跑通）

> **用途**：换一台电脑、或者新人第一次 clone 之后，照着这一份就能把
> 「编译 → 装机 → 验证」跑通。**不需要改仓库里任何文件。**
>
> 本文只讲**机器相关**的配置。项目技术现状见 `docs/当前状态.md`，
> 全局交接见 `PROJECT-STATE.md`，「每天要用的命令」见 `docs/项目交接.md`。

---

## 一、需要什么

| 东西 | 要求 | 为什么 |
|---|---|---|
| JDK | **17**，且是**完整 JDK**（要有 `javac` / `jar`）| `build.gradle` 写死 `JavaLanguageVersion.of(17)`；Gradle 8.8 自身也跑在 17 上 |
| 整合包 | 元素觉醒 1.4.3 魔改版，**已解压的实例** | 编译只用到它里面 4 个 jar（见第四节），但必须解压好 |
| 网络 | GitHub 要能访问（国内要代理）| 直连 `github.com:443` 会被限速/重置 |

**JDK 17 不需要另外装一颗。** 整合包启动器自带的 runtime、或者 JetBrains 系 IDE 的
`jbr`（JetBrains Runtime 17）都是完整 JDK，可以直接当 `JAVA_HOME` 用。先确认它带 `javac`：

```powershell
& "$env:JAVA_HOME\bin\javac.exe" -version     # 期望输出 17.x
```

> ⚠️ **启动器自带的 runtime 不一定是 17。** 本机的
> `%APPDATA%\.minecraft\runtime\java-runtime-delta` 就是 **21**。
> 拿 21 跑 Gradle，`java.toolchain` 会找不到 17 而编译失败 ——
> 要的是「把 `JAVA_HOME` 指向一颗 17」，不是「随便哪颗都行」。

## 二、机器路径：设两个环境变量就够了

工具脚本里的路径**全部是自动推断**的（统一在 `tools\_common.ps1` 和 `modpack\sync.ps1`）：

| 脚本要找什么 | 怎么找 |
|---|---|
| 仓库根 | 由脚本**自身位置**推出 —— clone 到哪个盘、哪个目录都行 |
| 整合包工作区 | `<仓库>\modpack\` 下**唯一**那个文件夹（`archive\` 不算）|
| 实时游戏实例 | ① `-LiveRoot` / `-Instance` 参数 → ② `$env:TNC_LIVE_ROOT` → ③ 在 `E:\download`、`D:\download`、`C:\download`、`%APPDATA%\.minecraft` 里搜同名文件夹 |
| `javac` / `jar` / `javap` | ① `%JAVA_HOME%\bin` → ② 启动器自带 runtime → ③ `PATH` |

所以「配置本机路径」= **设两个环境变量**，不用改仓库：

```powershell
# 指向"存放整合包实例的那一层"，不是实例本身
$env:TNC_LIVE_ROOT = 'D:\邵子豪\mc整合包'

# 指向一颗 JDK 17
$env:JAVA_HOME     = 'D:\software\PyCharm 2024.1.4\jbr'
```

`TNC_LIVE_ROOT` 下面应该是这个结构 —— 实例文件夹名必须和它**完全一致**：

```
<TNC_LIVE_ROOT>\
└── 元素觉醒1.4.3-魔改版-20260915\      ← 实例根目录（里面有 mods\ config\ kubejs\ ...）
    ├── mods\
    ├── config\
    ├── kubejs\
    └── ...
```

要让它**固定下来**（新开的窗口也生效）：

```powershell
[Environment]::SetEnvironmentVariable('TNC_LIVE_ROOT', 'D:\邵子豪\mc整合包', 'User')
[Environment]::SetEnvironmentVariable('JAVA_HOME',     'D:\software\PyCharm 2024.1.4\jbr', 'User')
```

> `tools\tnc_instance.json` 里记的是一条**具体机器**的实例路径，只给
> `show_tnc_log.ps1` 用。它**只在那个路径真的存在时**才生效，否则自动回退到上面的推断 ——
> 所以换机器**不用**去改它，也不该把自己的路径提交进去。

## 三、跑起来

```powershell
cd <仓库>
$env:JAVA_HOME     = '<JDK17>'
$env:TNC_LIVE_ROOT = '<versions 那一层>'

# 1) 取回 4 个只用于编译的 jar（从本机整合包里复制）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\fetch-libs.ps1

# 2) 编译
.\gradlew.bat build

# 3) 验证产物（jar 内容 / 法术清单 / 效果白名单 / mixin / 字节码版本 …）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify_mod_jar.ps1

# 4) 装机（游戏开着会拒绝覆盖 jar —— 那是保护机制，不是 bug）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-to-pack.ps1
```

> ⚠️ 还有一个 `tools\verify_spells.ps1`，但它的 **D 段「卷轴交付链」检查已经过期** ——
> 那是「魔法石」路线之前的旧逻辑，所以现在会对 74 个法术里的 **66 个报假问题**
> （已记在 `docs\法术专题_交接.md` 末节）。A/B/C 三段（字段名 / 枚举值 / 必需字段）仍然有效。
> **别拿它的退出码当验收标准** —— 装机闸门是 `verify_mod_jar.ps1`。

### 🔴 首次构建必须先把代理写进 `gradle.properties`

**这是最容易卡住的一步，而且卡住时没有任何报错。**

Gradle 会为 build **派生一个单次 Daemon**（日志里那句
`a single-use Daemon process will be forked`），而通过 `GRADLE_OPTS`
设的系统属性**不会跨过这个边界**传进去。结果就是：环境变量里明明设了代理，
构建却一直在直连下载上卡死、日志一行不涨。

代理必须写在 `gradle.properties` 里。不想污染仓库，就放 Gradle 用户目录：

```properties
# %USERPROFILE%\.gradle\gradle.properties
systemProp.http.proxyHost=127.0.0.1
systemProp.http.proxyPort=7897
systemProp.https.proxyHost=127.0.0.1
systemProp.https.proxyPort=7897
systemProp.http.nonProxyHosts=localhost|127.0.0.1|[::1]
```

端口按本机代理改（Clash Verge 的 HTTP 端口默认是 7897）。

**git 是另一套**，它不读 Windows 系统代理：

```powershell
git config http.https://github.com.proxy http://127.0.0.1:7897
```

> 代理没开时 git 报 `Connection was reset` —— 那是代理没开，不是仓库坏了。

## 四、`fetch-libs.ps1` 到底要哪 4 个 jar

`build.gradle` 把它们声明成 `compileOnly`（**只用于编译，不会打进我们的 jar**），
所以不在版本库里，每个 clone 都要取一次：

| `libs\` 里的名字 | 从整合包哪里来 |
|---|---|
| `spell_engine-0.15.12+1.20.1_mapped_srg_1.20.1.jar` | `mods\.connector\` |
| `spell_power-0.12.0+1.20.1_mapped_srg_1.20.1.jar` | `mods\.connector\` |
| `touhoulittlemaid-1.5.2.jar` | `mods\touhoulittlemaid-1.5.2-forge+mc1.20.1.jar` ← **要改名** |
| `geckolib-4.8.4.jar` | `mods\geckolib-forge-1.20.1-4.8.4.jar` ← **要改名** |

后两个**必须改名**：`build.gradle` 用的是 `flatDir` 仓库，它按 `<名字>-<版本>.jar`
去解析，原文件名里的 `+` 会被当成**动态版本号**。

脚本找不到整合包时，可以直接指过去：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\fetch-libs.ps1 -PackDir "<实例>\mods\.connector"
```

## 六、别踩的坑

1. **`tools\*.ps1` 必须纯 ASCII。** PowerShell 5.1 按 ANSI 读没有 BOM 的 `.ps1`，
   中文注释会读坏换行、整个脚本解析失败（已踩过，见 `PROJECT-STATE.md`）。
2. **每个 clone 要开一次提交守卫**：`git config core.hooksPath tools/git-hooks`
   （`fetch-libs.ps1` 结尾会提示，但**不会**替你改 git 配置）。
3. **`git add -A` 之后看一眼文件数**，别把整合包本体或存档收进去。
4. **`libs\` 和 `modpack\*\mods\` 不进版本库**，这是 `.gitignore` 有意为之。
