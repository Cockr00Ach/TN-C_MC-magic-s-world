# 天空岛持续掉帧与模型内存排查

用户正式启动参数：-Xmx7680m，G1GC。16GB物理内存。日志出现90%堆使用提示及多次服务器落后2～73秒；AllTheLeaks先提示未发现，后列出一个旧ClientLevel、一个LocalPlayer和67区块，不能把首条提示当成已经证实无限增长泄漏。

初步对象直方图（jcmd GC.class_histogram，包含完整GC）：原资源配置在世界尚未完整进入时就有6,704,850,264字节活对象，其中7,089,140个BakedQuad、约2,298万String及大量模型JSON/数组。单纯加长加载时间无法释放这些常驻模型；7.5GB堆几乎没有临时分配余量。

隔离试验开启ModernFix已有的动态资源能力后，完整进入新世界后活对象4,021,873,208字节，BakedQuad为62,954。此次同时加载了世界结构/区块，所以总内存不是相同运行阶段的一对一对照；模型对象数量下降明确，仍须同存档路线和实际1600×900渲染对照。存在两个ClientLevel实例，旧世界引用尚待进一步归因，不把动态模型加载描述为修复了所有第三方泄漏。

ModernFix官方说明：动态资源把方块和物品模型改为按需加载，可能与非标准模型API发生兼容问题，因此必须验证整包模型和贴图。来源：https://github.com/embeddedt/ModernFix/wiki/Dynamic-Resources-FAQ 。本轮不删除模组、建筑、NPC或玩家存档，也不减少贴图/特效质量。

新增显式隔离测试开关SkyhavenProfile，堆固定为正式启动的7680MB，沿镇中心、田庄、工坊、镜湖、高台、重访镇中心六段移动，记录帧间隔P50/P95/P99、50/200ms长帧数、GC次数与GC耗时、堆使用和服务器tick时间。隐藏Windows窗口曾返回1×1渲染目标，先前此类帧率结果作废；审查器现强制1600×900，并在每段报告实际framebuffer大小及原生截图。不存在实际画面就不接受性能结果。JFR在该整合包JVM下产生空文件，未将空文件当作性能证据，使用JVM GC计数器和活对象直方图。

正式配置仅加入mixin.perf.dynamic_resources=true，安装时保留其他现有配置并备份。源码仓库提供最小覆盖配置，队友pull后必须同步配置到运行实例，不能只替换JAR。

正常分辨率基线（work/skyhaven-lag-real-baseline）：同一既有隔离世界，1600×900、7680MB堆、同一诊断JAR、光影开启，六段累计GC 166,470ms，95个超过200ms的帧；镇中心P99=1440.5484ms，GC 26,901ms/50秒，堆7543MB。此数据取代此前1×1隔离窗口的无效帧率。

同存档同JAR同堆光影对照完成：优化后六段累计GC 1006ms，超过200ms的长帧1次；各段P99为19.5ms, 12.9ms, 13.3ms, 13.9ms, 11.9ms, 13.8ms。堆取样约4.2～5.0GB，原配置约7.2～7.7GB。路线从各场景出发，含空中穿越及岛边，天气可能遮挡景观；这组数据确认内存压力/GC停顿改善，不将固定路线帧率外推为全场景GPU性能保证。另以静态多地点原生截图检查模型和光影兼容。
