# Medieval Town 地图接入进度

最后更新：2026-09-19

## 已完成

- 从 `D:\mc_building\_世界\Medieval Town` 的 1.19.1 Anvil 存档读取现代小写 chunk 格式。
- 通过建筑密度确认主城核心区域，并选择完整抽取框：
  - X：`-820..-540`
  - Y：`32..191`
  - Z：`32..368`
- 旧版 `Y=120..255` 只包含高处单栋建筑，已废弃并保留在工作区备份中。
- 直接从 Anvil 存档导出 `281 × 160 × 337` 的完整城镇。
- 切成 48 格以内的 Minecraft structure NBT：100 个分块、4,654,379 个非空气方块、2,194 个方块实体。
- 模板保留源 DataVersion 3105，由 Minecraft 1.20.1 DataFixer 升级旧告示牌等数据。
- 结构文件已放入 `kubejs/data/tnc/structures/medieval_town/`。
- 添加首次登录自动生成脚本：`kubejs/server_scripts/world/initial_town.js`。
  它在随机出生点约 384 格范围内比较八个候选区域，选择起伏最小、深水最少的位置生成完整城镇。
- 生成过程由 `startup_scripts/00_initial_town_manifest.js` 驱动，共 724 个分步操作：48 次区域加载、480 次限额清理、100 次结构放置和 48 次卸载。
- 每 tick 只执行一项操作；任一结构失败时解除当前强加载区域且不写成功标记。
- 玩家在完成后收到中心与南门坐标，传送至原存档南门对应位置并设置重生点。
- 添加 `kubejs/startup_scripts/disable_author_initial_spawn.js`，在服务器启动阶段将
  `ysjx_dimension` 的 `.ysjx_magic_association_initial_spawn` 强制设为 `false`，保留作者的其他五个维度和传送器，只取消首次登录强制传送。

## 当前放置方案（v4）

源地图 `Y=64` 地面基准会对齐候选区域的最高采样地面。生成器逐个 48×48 区域强加载，分层清除地面以上的干扰地形，再自下而上放置该区域的模板。这样不会超过 256 个强加载区块和 `/fill` 的 32,768 方块限制。

旧 v3 测试世界不会自动删除错误建筑；v4 验收必须新建世界。

## 工具

- `tools/export_medieval_town.py`：从 Anvil 存档导出 Sponge v2 中间蓝图。
- `tools/convert_schem_to_structures.py`：按 48 格上限切成 Minecraft structure NBT。
- `tools/export_town_structures.py`：直接导出完整城镇结构并保留方块实体。
- `tools/build_town_runtime_manifest.py`：生成限额、分批执行的 KubeJS 操作清单。
- `tools/test_initial_town_runtime.js`：模拟成功与失败生成路径。
