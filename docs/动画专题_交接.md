# 动画系统MMM · 剧情演出专题交接文档

> **一句话职责**：**表现剧情的动画** —— 剧本里写成 `（…）` 的**动作提示**，
> 要在游戏里**真的做出来**（谁、在什么时候、做什么动作 + 镜头给谁看）。

## 一、这个专题为什么存在

`剧情总纲.md` §八 自己写着：

> 作者原有章节基本是物品收集清单式……**剧情表现力目前是零**，
> 我们写的第一批真·剧情任务会是这个包里**第一次有人说话**。

而 `剧情\开场_分离之后.md` 的附注把这批需求**已经点名列好了**：

> ★ 旁白仅剩 ★ **七处动作提示**（那杯酒／钱压杯下／推登记簿／合上登记簿／后屋声响／塞盾／回头看烟）
> —— **都是镜头能看见的**

**这七处就是本专题的第一批工单。** 它们在文本里是"镜头语言"，
在游戏里现在**只是一行括号文字** ✗ —— 中间缺的那一层，就是我的活。

## 三、已验证的技术事实（不是猜的，每条都有出处）

### 3.1 对话系统已经能做"时间轴"的骨架

| 事实 | 位置 |
|---|---|
| 对话剧本是**纯文本**、按行播、编剧可直接改 | `data/tnc/dialogues/*.txt`（`DialogueLoader` / `DialogueScript`）|
| 一行 = `说话人 + 文本`，**说话人为空 = 旁白** —— 那七处动作提示现在就是这么播的 | `DialogueScript.Line` 的 javadoc |
| 播完能**接力下一段**（`@next`），由**服务端**决定接哪段 | `DialoguePackets.DialogueDone` → `DialogueNetwork.playNext` |
| 网络通道**全 mod 只有一条**（`tnc:main`），包 id 从 100 起和魔法石错开 | `DialogueNetwork` 的 javadoc |

> ⇒ **结论**：动作触发的挂点现成 —— 不必新开网络通道，也不必改对话协议的语义 ✓。

### 3.3 三条"看着能做、其实做不了"的路（别重复走）

   反序列化成 PlayerAnimator 的 `KeyframeAnimation`，绑在**玩家**身上（`net.spell_engine.client.animation.AnimatablePlayer`），

3. ✗ **本机没有 `.bbmodel` 工程** —— `D:\blockbench\Blockbench.exe` **在**，
   但 `D:\blockbench` 下**没有任何 `.bbmodel`**；用户自制模型（fireball/waterball/lightingball/thunder_ball）
   都在 `magic_modelandtexture\`，是**投射物**，不是角色 ✓。

**三条轴的约定（这套骨架）**：

| 轴 | 效果 | 例子 |
|---|---|---|
| X | 手臂/腿**前后摆** | 抬到胸前 ≈ X **−84** |
| Y | **左右转** | 头右转 ≈ Y **−24**（正 = 左转）|
| Z | 手臂**张开/夹紧** | 夹到胸前 ≈ Z **−18** |

表里的记法：`arm(forward=84, inward=18)` / `head(pitch=6, yaw=-24)` / `body(pitch=5)`，
时间轴用**帧**（20 帧 = 1 秒，游戏 20 tick/秒）✓。

### 6.1 现状（谁做了什么）

| 动作名 | 谁做的 | 挂在哪句台词 |
|---|---|---|
| `wipehand` | **用户**（Blockbench）| `@act wipehand` → 「他跟你说过「看清楚了就回来」…」|
| `pointcup` | **用户**（Blockbench）| `@act pointcup` → 第一句「你在这儿坐了一整夜了，归。…」|
| `confused` | **用户**（Blockbench）| `@act confused` → 「……你这个人，认起死理来比谁都犟。…」|
| ~~`idle`~~ | 我（`tools/gen_npc_animation.py`）| **已删（2026-09-23）** —— 用户要求"播完两遍就站着"，
  平时不播任何动画，保持模型静止站姿 ✓（该生成器只留作"以后要待机动作"的工具）|

### 6.1b 播放规则（2026-09-23 用户定稿）

- **每个动作连着播两遍** ✓（`RawAnimation.begin().thenPlayXTimes(name, 2)`，常量 `ACTION_REPEATS = 2`）
- **播完就站着** ✓ —— 没有动作时控制器返回 `STOP`、不写任何骨骼
- ⚠️ 前提：动画 JSON 里必须 `"loop": false` ✗，否则它会自己一直循环、"两遍"就无从谈起
- 改遍数只改 `SelfBedrockNpcEntity.ACTION_REPEATS` 一个常量 ✓

### 6.2 ★ 怎么把动作接到台词上（`@act` 标记）

在 `data/tnc/dialogues/<剧本>.txt` 里，**在台词行的上一行**写 `@act <动作名>`：

```
@act pointcup
Self|你在这儿坐了一整夜了，归。桌上那杯酒你一口没动，……
```

- **只作用于紧接的那一行**，那行一显示出来就播 ✓
- 动作名必须与 `assets/tnc/animations/entity/*.json` 里的动画名**完全一致** ✗ 写错不会崩，
  但游戏里什么都不动（日志里会有一行 `TN-C anim: failed to trigger …`）
- **写错的两种笔误会被直接报错**（不做静默忽略 ✓）：连续两个 `@act`、`@act` 挂在文件末尾没有台词
- 动作名只能是**短 ASCII 单词**（`a-z A-Z 0-9 _ -`）✗ 中文名会被拒

### 6.3 播放链路（为什么这么做）

```
客户端（对话框翻到那一行）
      │  ActionRequest{npc UUID, action}          ← 客户端只"报点"
      ▼
服务端（核对：真是我们的剧情 NPC？在玩家 16 格内？名字合法？）
      │  triggerAnim("action", "<名字>")
      ▼
GeckoLib 同步给所有客户端 → 大家都看得见 ✓
```
- **服务端权威**：客户端只能"请求"，伪造 UUID 也指挥不了别的生物 ✓
- 台词推进时机在客户端（玩家点击翻页），所以由客户端发起请求 ✓

### 6.4 ★ 踩坑记录：GeckoLib 4.8.4 **没有**控制器优先级

两条控制器同时作用于同一根骨头（`armRight`）时，**后处理的会盖住前一条** ✗ ——
症状是"动作播了但看不出"，因为 `idle` 的擦手姿势把动作的抬手拉了回来。

- ✗ `AnimationPriority` / `setAnimationPriority` 在这个版本**不存在**（我最初写错了，编译期就炸）
- ✓ 当时的解法：`idle` 控制器**主动让位**（点播动作在播时返回 `STOP`）
