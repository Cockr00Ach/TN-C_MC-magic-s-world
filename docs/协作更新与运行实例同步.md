# 协作更新与运行实例同步（给接手的 Agent）

更新日期：2026-11-02。本说明用于队友让 Agent “pull 最新版本、更新整合包、准备试玩”的情况。用户明确只要源码时不安装运行包。

## 1. 拉取源码，保留本地工作

先检查 `git status`，拉取并合并远端更新；有本地修改时保留它们，不硬重置、不覆盖队友成果。记录本次实际拉取的提交。内存优化已由 `b07f9f69` 引入，这是历史定位点，**不要把仓库回退到这个提交**，使用当前最新版本。

**git pull 成功 ≠ 游戏实例已更新。** Git不追踪TN-C构建JAR和大部分第三方运行文件；仓库中的整合包目录也常常只是镜像。

## 2. 定位当前电脑实际使用的实例

根据用户指定的实例、启动器当前版本设置或最近启动记录确认 `gameDir`。核对其 `mods/`、`config/` 与整合包版本，不要照抄作者电脑的绝对路径，也不要把另一套整合包当作目标。查看启动记录时不得输出完整启动命令，其中可能包含登录凭据。

仓库现有发现函数位于 `tools/_common.ps1`，可使用 `Find-TncWorkPack`、`Find-TncLivePack`。便携式PCL不在默认搜索位置时，可以把 `TNC_LIVE_ROOT` 环境变量设为本机启动器的 **versions 父目录**（例如 `自己的PCL目录/.minecraft/versions`），该函数会拼接版本文件夹名。如果仍无法唯一定位，向用户询问实际实例路径，不要猜测后写入。

## 3. 本次内存优化：必须同步配置

仓库来源：`modpack/元素觉醒1.4.3-魔改版-20260915/config/modernfix-mixins.properties`。

目标：**实际 gameDir** 下的 `config/modernfix-mixins.properties`。

要启用的唯一配置项：

```properties
mixin.perf.dynamic_resources=true
```

实际操作要求：

1. 确认实例已有 ModernFix。本轮不需要新增或升级任何第三方JAR；若该模组缺失，明确报告实例与基础包不一致，不要随意下载安装其他版本。
2. 修改前，把现有配置备份到带时间戳的备份位置，优先放在实例 `config/` 目录外。
3. 如果这一项已有有效的 `false`，改为 `true`；如果不存在，追加；如有重复的有效定义，合并成唯一一条 `true`。以 `#` 开头的示例或注释不算有效定义。
4. **保留其他所有自定义项和注释。** 仓库里是最小覆盖配置，不要整份复制覆盖已有配置文件，不要重置其他性能/兼容选项。
5. 重新读取目标实例的文件，确认恰好有一条有效键，且值为 `true`。不能只检查仓库镜像，更不能把注释里的 `# mixin.perf.dynamic_resources=true` 当成已经开启。
6. 完全退出并重新启动游戏后生效。无需重建世界，不修改 `saves/`，不迁移或重新生成天空岛。

这项配置通过按需加载模型来减少常驻内存。只换 TN-C JAR、不更新实际配置，不会得到本轮内存优化。

## 4. 同步本次其他运行内容

若拉取包含 `src/main/java/`、`src/main/resources/` 等TN-C变更，还要按仓库既有流程使用JDK17构建，运行必要校验，备份并安装新JAR；联机双方使用同一版。只有说明文档更新，或仅启用上述ModernFix配置时，不必为此重新构建JAR。

现有通用入口（在仓库根目录运行；自动发现实例必须已指向本机正确目标）：

```powershell
.\gradlew.bat build
powershell -NoProfile -ExecutionPolicy Bypass -File tools/install-to-pack.ps1
```

`tools/install-to-pack.ps1` 不接受 `-LivePack` 参数；便携式PCL使用上面的 `TNC_LIVE_ROOT` 指定 versions 父目录，不要编造参数，也不要用 `-SkipVerify` 绕过安装检查。安装前先完成拉取、构建和准备，游戏退出后再替换JAR，不得覆盖运行中的文件。完成后核对实际实例JAR与构建产物SHA-256相同。

`tools/install_skyhaven_memory_fix.py` 是作者本机的验收安装器，会读取未纳入Git的 `work/` 性能证据。队友机器缺少这些日志是正常情况；**不要为让它通过而伪造报告或删除断言**。队友按本文合并配置，其他JAR更新使用既有通用流程。

涉及KubeJS或FTB内容时，只同步本次实际变更的自有内容，并使用对应专题安装流程；不要把整个config、任务书或存档目录粗暴替换。README中的历史“清空任务”记录不代表本次更新授权。

## 5. 向用户报告什么

完成后明确报告：

- 拉取后的提交号。
- 实际运行实例的绝对路径。
- 实际实例配置是否已核对为唯一有效的 `mixin.perf.dynamic_resources=true`。
- 是否构建、安装了TN-C JAR；如安装，是否哈希一致。
- 是否需要用户完整重启游戏；是否做了启动／实机测试，不能把未测试写成通过。

如果只拉了源码、尚未定位或同步运行实例，必须写清楚“源码已拉取，游戏实例尚未更新”，不能只报“更新完成”。
