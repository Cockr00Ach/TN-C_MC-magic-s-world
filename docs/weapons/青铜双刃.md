# 青铜双刃：四器合铸的唯一成品

按双持参考图替换青铜战戟：主手是有中央镂空与宽护手的宽刃长剑；配对刃是带内侧缺口、回弯长刃和反向尾锋的武器。材质沿用古铜、锈蚀、铸纹和皮缠，模型保持四分之一单位细节。

## 物品与使用规则

- 整套只有一个真实物品栈，不能拆成两个物品；两片刀刃共用强化、耐久、附魔和投掷锁。
- 兼容旧存档，沿用内部ID `tnc:bronze_halberd`，显示名称改为“青铜双刃”。已有旧战戟就地替换为新成品，原NBT及10级强化继续有效。
- 工作台配方仍是四种不同的原始青铜武器各一把、全部强化10级，产出一套强化10级双刃。
- 必须放在主手，副手槽必须真实为空。副手有盾牌、方块或任何物品时，禁止普通攻击、战士连招、蓄力投掷和召唤，并移除该武器的攻击/攻速属性。清空副手后恢复。
- 占用副手时终止蓄力及连招架势。正在飞行的双刃若失去握持条件，则转为回收，不继续命中造成伤害。
- 战斗天赋启用时，即使副手被占用，也会消费战斗用Q/E按键，防止误触原版丢弃与背包操作；此时不发送连招输入。
- 普通右键仍是30游戏刻蓄力并整套投出、自动回收；潜行＋右键仍召唤原有青铜人偶。人偶生命、12基础攻击、10分钟存在时间和消失后2分钟冷却沿用原实现。

## 双手显示与战士系统

融合成品归入已有长剑家族，复用现有Q/E/Z、原招式伤害、范围、冷却和命中反馈；第二把刀只追加显示，绝不额外结算一次伤害。人偶同步改为双持外观并使用已有长剑招式。

原版第一人称手臂渲染器通过受检的Mixin Invoker复用，配对刃由相同真实物品栈绘制。第三人称为Steve、Alex和人偶追加配对刃层。整个流程不写入副手槽，不向玩家背包、地面或网络创建独立刀刃物品。

GUI、掉落物和投掷物显示整套；有效握持时，主手显示宽刃，另一只手显示回弯刃。两个模型的握柄轴均位于模型枢轴(8,8,8)。原版单物品渲染的自定义入口直接读取成品几何与UV，不依赖额外模组。

## 校验

测试覆盖副手占用、禁止副手独立使用、四把原武器的兼容性、原版模型解析、握柄枢轴与武器家族。打包后核对实际Minecraft SRG方法、Invoker描述符、refmap和注册配置。仅做离线资源预览、构建和安装校验，不启动游戏。

安装器原来只扫描 `*Mixin.java`，会把合法的 `BronzeHandInvoker.java` 接口误报为“无源码”。源码发现规则现覆盖Mixin、Invoker、Accessor三种命名，并保留原有的双向声明检查。`tools/regression/test_mixin_source_discovery.ps1` 直接执行安装器实际扫描表达式，验证三类源码与普通辅助类的区别。
