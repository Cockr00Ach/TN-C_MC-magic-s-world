## 二、日常工作流（5 条命令，照抄）

```powershell
# 0) 必须先设 JAVA_HOME（⚠️ 不要用 .minecraft\runtime 那个，PCL 会占用它导致 gradle 静默不编译 ✗）
$env:JAVA_HOME = 'D:\ModTest\.jdk17'          # 项目内固定 JDK17 副本 ✓

cd D:\ModTest

# 1) 编译（改了 Java 才需要）
.\gradlew.bat build

# 2) 装机（游戏开着会被拒 ✗ —— 这是保护机制 ✓；PCL 的 java 进程也会挡，可跳过脚本直接复制）
#    脚本:  powershell -ExecutionPolicy Bypass -File tools\install-to-pack.ps1
#    直接:  Copy-Item D:\ModTest\build\libs\tnc-1.0.0.jar <整合包>\mods\tnc-1.0.0.jar -Force

# 3) 只改法术 JSON / 模型贴图 -> 不需要装机：
#    · 法术 JSON 在 mod jar 里 -> 要重新编译+装机（见上）
#    · 资源包/贴图类 -> 同步 + 重进游戏

# 4) 同步 + 验证
cd D:\ModTest\modpack ; .\sync.cmd push        # ⚠️ 这是【双向】同步 ✗ 见第六节
cd D:\ModTest ; powershell -ExecutionPolicy Bypass -File tools\verify_mod_jar.ps1

# 5) 【只在改了剧情文案时】重新生成残卷正文 -> 再编译装机
#    正文的唯一来源是 剧情\宝箱传说残卷.md 的【卷文】段（文书专题维护）
powershell -ExecutionPolicy Bypass -File tools\gen_scroll_lang.ps1
powershell -ExecutionPolicy Bypass -File tools\gen_scroll_lang.ps1 -Check   # 只解析不写
```

**铁律**：**不要只看 `identical: True`** ✗ —— 构建失败时它只是"两个旧文件互相比" ✓。
**永远核对 jar 内容** ✓（本专题的所有"改了没反应"事故都源于此 ✗）。

### 3.2i-9 第八轮（作者："怎么魔力又不自动恢复了，还有为什么会自动学习啊，删去"）（2026-09-29 20:3x）

#### A. 回魔"换世界之后永久停摆"——真因是 **负数时间差**（闷声 `return`，连日志都没有）

一个 **JVM 里换存档** 就会出现，和"回魔挂在哪个 tick 事件上"**完全无关** ✗（3.2i-3 那轮加的双驱动治不了它）：

| 事实 | 证据 |
|---|---|
| 世界 A（老存档）最后还在回魔 | `19:54:56 TN-C: mana regen 188 -> 202 / 270 (+14 every 40t)` |
| 19:54:58 退出世界；20:02 进**新开的存档**（advancement 数 249→250→251…＝新世界 ✓） | `Stopping server` @19:54:58 / `Loaded 249 advancements` @20:03:14 |
| 换世界后整局 **`TN-C/mana` 只有 1 行**（driver alive），魔力卡在 90 上 20 多秒不动 | `20:03:11 TN-C: mana regen driver alive: PlayerTickEvent` → 之后 0 行 ✗ |
| 同一时间 `gate` 照打（说明玩家/魔力数据都在）：`BLOCKED lightning_storm reason=NOT_ENOUGH_MANA 90 / 100` 连续 6 次，20 秒里 90 一动不动 | 20:21:17 ~ 20:21:38 |

代码根因（`MagicStone.tickManaRegen`）：

```java
long now = serverPlayer.level().getGameTime();          // ✗ 每个世界各自的 gameTime
Long lastRegen = LAST_REGEN.get(uuid);                  // ✗ static 表，跨世界不清
if (lastRegen != null && now - lastRegen < interval) return;   // ✗✗ 负数 < 40 恒成立
```

- 老存档 `gameTime` 是**大数**（几十万～上百万），新开存档从 **0** 开始 ⇒ `now - lastRegen` 是**负数** ✗；
- `负数 < 40` 恒为真 ⇒ 这个 `return` 把回魔**永久**挡在门外（要等新世界时间追上老世界，几十万 tick ≈ 十几小时 ✗），
  而且这条 `return` 是**静默**的 ⇒ 日志里什么都没有，看起来像"回魔功能坏了" ✗✗。

★ 修法（`MagicStone.java`）：

1. **时间基准换成 JVM 单调时钟**：`nowTicks() = System.currentTimeMillis() / 50` ✓
   —— 跨世界、跨维度、世界时间倒退都不会再翻转；`LAST_REGEN` / `LAST_CAST` 都用它 ✓
   （`LAST_CAST` 有同一个坑：旧世界的"未来时间戳"会让"施法后暂停"永久生效 ✗，一起换掉 ✓）。
2. 判据加保险：`now >= lastRegen && now - lastRegen < interval` ✓、`since >= 0 && since < castDelay` ✓。
3. `PlayerLoggedInEvent` 里 `forgetTimers(uuid)` 清掉这三张按 UUID 记账的表 ✓（换世界一定走这里）。
4. **第三个驱动入口**：`TnSpellMechanics.tickPlayer` 里直接调 `MagicStone.tickManaRegen(player)` ✓
   —— 这条路上的日志在**两个世界里都被证明是活的** ✓（`TN-C/learn`、门禁日志照打），
   内部有"每周期只回一次"的闸门，多入口不会回魔翻倍 ✓。
5. **"回魔算出来是 0"不再静默**：`regen <= 0` 时每 10 秒打一行 WARN，把
   `manaRegenPerSecond / manaRegenPercentPerSecond / maxMana / interval` 全写出来 ✓（下次一眼定位 ✓）。
6. 顺手把"施法后暂停"的日志节流到 1 秒一行 ✗（原来**每 tick 一行**，一次施法 3 秒就是 60 行噪音）。

#### C. 这一轮的**教训**（写给下一轮）

- **凡是"每 N tick 一次"的节流，判据里出现 `now - last` 就必须考虑负数** ✗

### 3.2i-13 第十二轮：光系三条实机反馈（t5 放不出来 / 光翼链飞不了 / 天使 ×2 高）（2026-10-01）

#### A. 「天使的悲悯异常放不出来」（`light_wingspan` 同病）

日志实锤（不是猜 ✓）：

```
NullPointerException: Cannot read field "type" because "action" is null
    at SpellHelper.intent(SpellHelper.java:956)
    at SpellHelper.performImpacts(SpellHelper.java:599)
    at SpellHelper.performSpell(SpellHelper.java:268)
```

- 根因：这两个 JSON 的 `impact` 数组里多了一个**只有 `particles`、没有 `action`** 的元素 ✗
  （当时想"再来一层烟花"）。引擎对**每个** impact 元素都调 `intent(action)` ⇒ `action == null` **NPE** ✗
  ⇒ `performSpell` 半路炸掉 ⇒ **既不生效、也不发 `SPELL_CAST`** ⇒ 玩家看到的就是"按了没反应" ✗。
- 判据（很好用 ✓）：日志里 `gate ALLOW …` 之后**没有** `SPELL_CAST … action=RELEASE`
  而是等来 `TN-C: FIZZLE <法术> … progress=0.0` ⇒ 十有八九是引擎在 `performImpacts` 里炸了 ✗。
- 修法：**纯粒子并进同一个 impact 的 `particles` 数组** ✓（一个 impact 允许多组粒子 ✓）。
- 守卫：新增 `SpellImpactIntegrityTest`（遍历 `SpellCatalog` 里所有编了 JSON 的法术，
  断言每个 `impact[i].action` 存在 ✓）—— 以后再写裸粒子元素，`gradlew build` 直接红 ✗。

#### B. 「飞行链都没法飞，我也没看见翅膀」（★ 两个独立根因，**都不是**"事件死了"）

1. **飞行被风速链每 tick 收走** ✗：日志 `TN-C/light: 光翼飞行 给上` 在 47 秒里出现 **768 次**（＝每 tick 一次）

   - **`isLoaded()` 判据太松** ✗：只要有骨头就算成功 ⇒ 空模型（导出坏了）也走 geo 路 = 画空白 ✗。

   - 教训：**"渲染器在跑 + 顶点提交了 + 看不见" ⇒ 先查变换、再查剔除/绕序** ✓；

## 六、环境坑（每一条都真踩过）

1. **`JAVA_HOME` 被 PCL 占用 → gradle 静默不编译** ✗，而 `identical: True` 只是两个旧文件互相比 ✓ → 已固定 `D:\ModTest\.jdk17` ✓，且**必须核对 jar 内容** ✓
2. **打包 zip 必须用正斜杠条目名** ✗（Windows 默认反斜杠 → MC 完全读不了 → 资源包"启用却无效"）
3. **kubejs 与 mod jar 同 id 时以 kubejs 为准** ✗（数据包后加载）→ 用了模型的法术只留在 jar ✓
4. **不要改 Fabric 模组的 jar** ✗（Sinytra Connector 重映射会失败 → 启动崩溃）
5. **`sync.cmd` 是双向的** ✗：删了 kubejs 里的文件后不要再跑 sync ✓，否则会从游戏侧"恢复"回来 → 再次覆盖 jar ✗
6. **`tools/*.ps1` 必须纯 ASCII** ✗（中文会被 GBK 读法吞换行导致解析失败）
7. **改模型贴图引用时注意目录**：引擎只认 `textures/spell_projectile/` ✓（写成 `textures/projectile/` 会"模型在、贴图找不到"→ 紫黑 ✗）
8. **深色 UI 里 `{}`/引号会破坏 PowerShell**：脚本里别在单引号字符串里混 `{` ✓，提交信息里别用 `"` ✓（用 `-F 文件`）
