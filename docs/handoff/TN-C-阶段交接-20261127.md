# TN-C 阶段交接 · 2026-11-27

## 队友安装与验收

在 Windows 上拉取团队分支后，从仓库根目录运行安装和复核。存在多个实例时给两条命令都加 `-GameDir "实际 PCL 实例路径"`。看到安装和复核退出码都为 0 后再重启游戏。详细路径查找及依赖说明见[团队客户端同步](../天空岛团队客户端同步.md)。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/sync-team-client.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/sync-team-client.ps1 -VerifyOnly
```

团队发行锁固定 TN-C 成品及其源码。Voxy 下载备用，默认关闭。已安装 FTB Quests 的实例只同步团队维护的 `tnc_sky_academy.snbt` 单章，替换前备份。联机请让房主或服务端使用同一代 TN-C。检查新版地形和学院场地请新开世界；虚镜魔核可以直接在现有存档试玩。

## 玩法与联调

| 内容 | 验收方式 |
|---|---|
| 天空岛与学院 | 新开天空岛验收烘焙地形和听风场地。按剧情到瑟兰处验收开眼，完成后按 F8 切换。输入 `/skylesson` 查看现场研习指引。听风时留意特写能否看清魔力经过风铃柱，以及点柱后的反馈。 |
| 虚镜魔核 | 用 `/dungeon mirror` 进试玩，正式守关在星眠幻庭第 30 层。先分别以空技能栏和已学、已装配的水球进场。后一种可以空手。单人镜像从魔核侧面出场，旧试玩存档由池水迁移到齐平石地。 |
| 镜像近战 | 二阶段验收拉开距离时的真实末影珍珠，整场最多两颗。近身连续命中后，镜像有机会接脚下放网与头顶倒岩浆，割网可打断。水逐格扩散，同一水源及其流出水共用 30 秒期限，收桶也会排掉水流。岩浆与蛛网按十秒地形账本回收。两阶段镜像清完后近身打碎 1 HP 真镜。 |
| 无昼圣堂 | OP 用 `/sanctum boss` 跳到首领演练，再用 `/sanctum phase 1`、`2`、`3` 或 `next` 检查受击部位和转场。二阶段凝视 5 秒后接 10 秒血屏。二转三重点看胸口露手、撕壳、黑场和重掌。用 `/sanctum phase frenzy` 试低血量转招，`/sanctum leave` 退出；演练不会写入主线通关。 |
| 魔法与生态 | 已装配固有魔法的语音入口沿用原施法规则。复查自由火法爆炸与凝聚效果、水牢穹顶以及现有水系语音。新世界查看陆生、海生和空中生态、牧场外形与野生植物分布。旅行音乐入世界后等 10–15 分钟，之后每曲之间随机等待 10–15 分钟。 |

虚镜的完整操作见[试玩说明](../boss/虚镜魔核-试玩.md)。此前 Forge 虚镜专项通过 22 项，覆盖水的扩散与收回、珍珠抛出与安全落点、割断蛛网阻止岩浆。整包中另复测了空手已装配角色的镜像水球。无昼圣堂独立 Forge 回归通过 15 项，实机确认了指定部位的剑和固定水球受击，最终光影下的转场仍需复看。

## 建模与资源

- 虚镜魔核按黑晶外壳、黑水镜面、双符环与可拆背壳制作，小真镜藏在外壳里。运行时资源在 `assets/tnc/mirror/` 与 `textures/entity/mirror/`，可编辑工程和枢轴表在[虚镜模型源文件](../../model-source/boss/echoing_mirror)。
- 战士兵器连续曲面版随 TN-C JAR 分发。44 件手持武器和五把弓的拉弦档位采用 Forge OBJ 曲面及对应贴图。这轮连续曲面处理没有覆盖走专门渲染的青铜双刃；ZIP 自带既有双刃资源。
- [战士兵器源文件](../../model-source/warrior-arsenal)包括早期可编辑 Blockbench 工程、表面版输入与曲面生成脚本。最终曲面以 `assets/tnc/models/item/weapon_surfaces/` 的 OBJ 为准。脚本由项目根目录的 `src/main/resources` 读取武器家族定义，可用环境变量 `TNC_WEAPON_REPO` 指定仓库路径。Forge 已离线核验 59 个曲面状态，实际光影、第一人称挥动和实际帧率待复看。之前在本机用 OpenLoader 试玩过的队友应检查同名旧测试包的覆盖优先级，保留自定义资源时按需启停。

## Windows Java 闪退

两份本机报告显示 Microsoft OpenJDK 21.0.7+6 的 HotSpot C2 在 `type.cpp:1283` 崩溃，分别正在编译 `WarriorTrailCurve.limit` 和 `WarriorTrailVolume.resample`。相同指纹时，在该 PCL 实例的 JVM 参数中保留原有设置并追加下面两项，完全退出并重开 PCL 后启动。原机器已备份并写入实例版本配置，实际 JVM 接受两项参数；战斗场景尚未复现验证。其他玩家的启动配置由他们自己的实例管理。

```text
-XX:CompileCommand=exclude,com.tnc.tnc.warrior.WarriorTrailCurve::limit
-XX:CompileCommand=exclude,com.tnc.tnc.warrior.WarriorTrailVolume::resample
```
