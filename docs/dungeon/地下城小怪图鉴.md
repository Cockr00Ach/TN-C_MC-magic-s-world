## 一、先说清楚"改造已有的"能做到哪一步

地下城（Dungeon-Realm，内嵌 Library of Exile 框架）里原有的小怪，**动画改不了**：

| 主题 | 名册来源 | 我们能不能改 |
|---|---|---|
| cement 14 种 | `eeeabsmobs:immortal_*` + `mebahelcreaturesdraugr:draugr_*` | ✗ 只能改权重 |
| nether 12 种 | `blackgoldalliance:*` | ✗ 只能改权重 |
| sandstone 26 种 | `jerotesvillage:*` + `illageandspillage:*` + `raidsenhanced:*` | ✗ 只能改权重 |
| tent 9 种 | `torchesbecomesunlight:*` | ✗ 只能改权重 |
| evil_villager 4 种 | 原版灾厄 | ✗ 只能改权重 |
| **forest / generic_undead / spider_forest / green / map_default** | **原版凑数**（僵尸/蜘蛛/史莱姆/女巫） | ✓ **整张换掉** |

所以 v1 的思路是：**补短板 + 不抢戏**。5 套原版主题整表重写，5 套第三方主题只追加少量权重。

刷怪表的位置（这是数据包覆盖，改这里就等于改地下城，不用动 jar）：

```

    library_of_exile/library_of_exile_mob_list/<theme>.json
```

改造脚本（可复跑、幂等）：

```powershell

python tools\apply_dungeon_mob_lists.py --apply    # 真写
```

### 新增词缀（3 个）

`library_of_exile_mob_affix/` 里原有 7 个词缀，我们补 3 个**纯属性型**（和现有 7 个同一套
`attribute_mob_affix` 序列化器，不碰它的行为型序列化器 —— 那个 schema 没文档，猜错就是启动崩）：

| 词缀 | 效果 | 权重 |
|---|---|---|
| `tnc_armored` 铁甲 | 护甲 ×1.3~1.6 | 800 |
| `tnc_vicious` 凶猛 | 攻击力 ×1.2~1.45 | 700 |
| `tnc_fleet` 疾行 | 移速 ×1.15~1.35 | 750 |

> ⚠️ 词缀**是否作用在我们自研实体上未验证**：框架按 `affects: MOB` 挂属性，
> 理论上对所有怪物生效，但这依赖它挂的是 `Mob` 而不是"它自己注册的怪物白名单"。
> 实机时用 `/damage` 看同一只怪两次的血量/伤害是否不同即可判定。

## 三、攻击方式：前摇 → 命中 → 后摇

每只怪的攻击都是**三段时间轴**，动画关键帧与它同源（生成器按同一组 tick 出片），
所以"动画还在抬手、伤害已经出了"这种错位不会发生。

| 攻击 | 起手距离 | 前摇 | 后摇 | 冷却 | 命中瞬间发生什么 | 反制 |
|---|---|---|---|---|---|---|
| `CHARGE` 冲撞 | 6 | 22t | 12t | 70t | 朝目标直线突进 0.85 格/t，锥形 3 格内伤害 + 击退；**撞墙自晕 50t** | 侧移后贴墙站，让它撞墙 |
| `HOOK` 甩钩 | 8 | 12t | 14t | 60t | 把目标朝自己拽近（0.95 格/t + 上抛），伤害 ×0.6 | 别在它正前方 8 格停下 |
| `POUNCE` 跃击 | 6 | 10t | 12t | 50t | 起跳扑脸，落点锥形 3 格伤害 ×0.9 | 抬头的瞬间横向拉开 |
| `VOLLEY` 三连弩 | 18 | 14t | 12t | 55t | 三发弩箭（第三发更快更疼，2.0 格/t） | 贴脸/找柱；三发之间有间隔 |
| `POT` 火罐 | 14 | 16t | 14t | 70t | 抛物线罐子，落点 3 格范围伤害 + 点燃 4s | 看抛物线落点走开 |
| `BEAM` 射线 | 16 | 20t | 10t | 80t | 即时射线（最远 16 格），线上 1 格内受伤 + 点燃 2s | 前摇 20t 最长，躲柱子后面 |
| `BURROW` 钻地 | 12 | 10t | 20t | 90t | 钻到**目标背后 1.8 格**冒出并造成伤害 | 别背对开阔地；听到声音就转身 |
| `BIND` 锁链 | 10 | 14t | 12t | 80t | 定身：移动速度 -80% 持续 3s，并清空动量 | 优先集火（它的伤害只有 3） |
| `FROST` 冰霜 | 7 | 14t | 12t | 60t | 锥形 5 格：伤害 + 减速 II + 冻结 100t | 别站在正面锥形里 |
| `SUMMON` 召唤 | 8 | 20t | 16t | 200t | 召 2 只掘墓尸虫（同主人上限 4 只，存活 20s） | 先杀僧；它一召就会分心 |
| `OVERHEAT` 重拳 | 4 | 14t | 10t | 40t | 锥形 3.2 格重击 + **积热**；4 层后过热停机 4s | 数它的拳，停机时**伤害 ×2** |
| `DETONATE` 自爆 | 3.5 | 24t | 6t | 200t | 膨胀后炸开 3.2 格（伤害 ×1.4 + 点燃），自己也没了 | 前摇 24t 很长，跑开就行 |
| `WHIRL` 横扫 | 4.5 | 16t | 14t | 80t | 原地转一圈，4.5 格内**全体**受伤并被推开 —— 绕后也没用 | 举斧过头就是预警；退到 5 格外 |
| `GRAB` 触手攻击 | 3.2 | 16t | 16t | 90t | **六条触手前伸约 2.9 格**，按每条触手的尖端各自判定：够到谁就缠谁（跑到身后也没用），命中即拖近 + 减速 III 3s；够不到就是够不到 | 退到 3.5 格外就安全；被缠住时跳一下能脱开 |

> ⚠️ 触手怪是**唯一按部件尖端结算**的怪：`TNDungeonMob.TENTACLE_TIPS` 存了六条触手全伸展时的
> 尖端坐标（来自生成器的 grab 片段：绕 X +30°、前伸 36 像素、缩放 1.2），每个尖端一个 1.5 格判定盒。
> **改动画就要同步这六个数**，否则会出现「看着够到却没伤害」或者「隔空抓人」。它的起手距离
> 也因此只有 3.2 格 —— 不再是以前那个 6.5 格的圆。

数值常数在 `DungeonSpecies.Kind` 里（`windup / recover / cooldown / reach`），
动画时长在生成器同一张表里，两边一起改。

## 四、动画（每只 5 段，共 85 段）

| 片段 | 时长 | 循环 | 用途 |
|---|---|---|---|
| `idle` | 3.0s | ✓ | 呼吸/待机摇摆 |
| `walk` | 1.0s | ✓ | 按体型驱动的步态（双足/四足/六足/蠕虫各不相同），**双足与机甲的小腿相位滞后半个步 → 膝盖会弯** |
| `attack` | 0.8–1.4s | ✗ | 一次性，由 `triggerAnim("action", "attack")` 触发 |
| `special` | 1.2s | ✓ | 过热停机 / 诵经 / 钻地 / 锁链保持 |
| `death` | 1.0s | ✗ | 倒地 + 缩小 |

实现方式（`TNDungeonMob#registerControllers`）：

- `state` 控制器：`死亡 > special（过热/定身）> 移动则 walk > 否则 idle`
- `action` 控制器：一次性片段，播完自然回落，**不会卡在攻击姿势**

骨架按**九类原型**生成：双足（`biped`）、小哥布林（`small_biped`）、兽人体型（`bulky_biped`）、牛头人（`bull`）、四足（`quadruped`）、六足（`insect`）、机甲（`mech`）、蠕虫（`grub`）、触手（`tentacle`）。动画只允许动**该骨架真实存在的骨头** —— 这条由
`tools/check_dungeon_mob_assets.py` 与 JUnit `DungeonMobAssetsTest` 双向把关。

### 5.1 每个方块有自己的 UV

第一版所有方块都从材料区的左上角采样（`uv=[0,0]` / `[512,0]` …），
结果整只怪共用同一小块贴图 —— 这就是"丑"的根：**看不出零件，只能看出一坨色块**。

现在 `pack_uv()` 用货架装箱算法给**每个方块**在自己的材料区里分一块矩形
（bedrock 盒式展开 `2*(d+w) × (d+h)`，块间留 2px），贴图不再重复。

17 只合计 **2208 个方块 / 13248 个面**（第一版是 160 方块），单只 118–148 个：

### 5.2 逐面绘制

`paint()` 不再"每个材料区画一张图"，而是**按面画**：遍历 UV 计划里的每个面矩形，
各自上色，然后叠四层：

1. **形体明暗** —— 面内上下渐变，配合朝向系数（顶 1.16 / 底 0.72 / 侧 0.86–1.02）；
2. **材质细节** —— 毛皮走笔、骨裂、锈蚀坑、苔斑、黄铜高光带、布纹经纬、冰晶棱面…；
3. **接缝 + 内高光** —— 1px 亮边（上/左）与 1px 暗边（下/右），让零件彼此分离；
4. **2px 角部遮挡** —— 每个面下角压暗，做出"卡角"的手绘感。

强调色（眼睛/核心/灯）会额外叠一层中心向外衰减的辉光，读起来是"发亮"而不是"涂了黄色"。

### 5.3 两个必须修的几何坑

- **共面闪烁**：细节甲片如果和本体表面同平面，进游戏会 z-fighting 闪。
  `resolve_flush_faces()` 自动检测并沿法线推离 0.02（1/800 格，肉眼不可见，但不闪了）。
- **脚离地/悬空件**：六足腿原本在膝盖处差 1 格、脚底停在 y=1，整只怪悬浮 6cm。
  `audit_dungeon_mob_rigs.py` 抓出来后把腿链改成 髋5→股5→胫2→足0，并给尸虫同款修正。

> ⚠️ 美术仍是**程序化手绘**：结构、UV、动画、配色、明暗都是真的，细节密度也对得上
> 100+ 方块的模型；但笔触是算法画的，不排除某些面看起来偏"壁纸感"。
> 真要美术级质感，得在 Blockbench 里手调模型、在 PS 里重画贴图 —— 管线不用改，
> 重导后 `check_dungeon_mob_assets.py` 与 `render_dungeon_mob_preview.py` 照跑。

## 六、代码结构

| 文件 | 职责 |
|---|---|
| `dungeon/DungeonSpecies.java` | **唯一数值表**：17 只的血/伤/速/甲/体型 + 14 种攻击的时序 |
| `dungeon/TNDungeonMob.java` | 公共实体：动画控制器、AI、`performImpact()` 里 12 路命中结算、掉落、存读档 |
| `dungeon/DungeonGoals.java` | 两条 AI：`Approach`（靠近）与 `Attack`（起手） |
| `dungeon/DungeonBoltEntity.java` | 远程弹体（弩箭 / 火罐），借原版 `ThrownItemRenderer` 显示 |
| `dungeon/DungeonMobRegistration.java` | 12 实体类型 + 属性表 + 12 刷怪蛋 + 弹体 |
| `dungeon/client/DungeonMobGeoModel.java` | 17 只共用一个模型类，按物种 id 拼路径 |
| `dungeon/client/DungeonMobRenderer.java` | 共用渲染器，按 `scale()` 放大精英 |
| `dungeon/client/DungeonMobClient.java` | 客户端挂 17 个渲染器 + 弹体渲染器 |

**注册线不能漏**：`TNMod` 构造函数里的
`com.tnc.tnc.dungeon.DungeonMobRegistration.register(modEventBus)`，
漏了就是 17 个实体静默不存在（jar 里有类、游戏里查不到）。

### 7.1 无头实机（GameTestServer）—— 这是真的 Minecraft

`runGameTestServer` 起的是一个**真专用服务器**（不是 mock）：真注册、真属性、真 AI、真伤害结算，
跑完自动退出。9 项测试覆盖：

| 测试 | 证明什么 |
|---|---|
| `everySpeciesSpawnsWithItsOwnStats` | 17 只都能生成，且每只拿到**自己那一份**血量/攻击力；`DungeonSpecies.of()` 反查正确 |
| `chargeWindupActuallyDealsDamageToItsTarget` | 冲撞前摇走完**真的掉血**，且攻击后回到可用状态 |
| `crossbowmanFiresThreeBolts` | 三连弩正好生 3 个弹体（不多不少） |
| `steamSentinelOverheatsAfterFourPunchesAndTakesDoubleDamage` | 第 4 拳进入过热；过热期同样伤害**掉约两倍血** |
| `orcWhirlHitsTargetsBehindIt` | 横扫是 360°，站在**背后**的靶子也会掉血（锥形判定会漏） |
| `tentacleGrabOnlyReachesAsFarAsItsTentacles` | 触手**真的有射程**：4 格外打不到，避免退化成"隔空抓人" |
| `tentacleGrabPullsAndSlowsItsTarget` | 触手抓取造成伤害 + 减速 + 给目标一个朝自己的动量 |
| `graveGrubDetonatesAndDies` | 自爆伤到人，且自己必死（不会变成永动机） |
| `ashMonkSummonsTwoMinions` | 一次召 2 只，且归属正确（不会被别的怪重复计） |
| `umbralBinderLocksItsTargetInPlace` | 锁链真的挂上减速效果 |
| `burrowTeleportsBehindTheTarget` | 钻地后到目标身边（距离确实变近） |
| `eliteScalingDoublesAndAHalfTheHealth` | 精英 2.5 倍血 + 体型变大 |

**这一轮靠它抓到的真 bug**：`isEnemy()` 原本只认 `Monster`，导致锥形/AoE 伤害
**打不到村民**（地城里"关着村民的房间"是常见房间，怪走进去打不到人 = 白给）。
靶子用村民后冲撞与自爆双双不掉血，一跑就露馅。现在判定是
玩家(非创造) + 怪物 + 铁傀儡 + 村民，同类小怪互不打。

三件踩过的环境坑（别人复用这套测试时会再踩一遍）：

1. `building_test_empty` 模板只有 **5×5×5**，坐标写 7 会直接判 "outside the structure"；
2. 分批不能靠 `--batch`（`Main` 的参数解析器不认，会直接启动失败），
   要用仓库既有的 **namespace 分批**：`@GameTestHolder("tncdungeon")` + 把模板放到
   `data/tncdungeon/structures/` + `-PdungeonMobTests`；
3. GeckoLib 在本仓库是 `compileOnly`（运行时由整合包提供），无头测试必须
   `-PdungeonMobTests` 时才 `runtimeOnly` 塞进去，否则启动就 `NoClassDefFoundError: GeoEntity`。

### 7.2 唯一没验的：画面

无头服务器**不加载客户端资源**，所以"模型看起来对不对、贴图有没有紫黑格、动画会不会 T 姿势"
这三件事机器判不了（顺带一提：GeckoLib 的模型/动画解析也在客户端，
服务端测试永远不会碰到它）。人工确认清单：

1. 刷怪蛋摆出来 → 模型可见、动画在动（不是 T 姿势、不是紫黑格）；
2. 打它 → 前摇看得到，伤害在自己预期的时刻出；
3. 在地下城维度里 `/kill` 与自然刷出各一次，精英粒子是否正常；
4. 日志里有没有 `Failed to load texture` / `bone missing` / `no attributes`。

前 3 条里"伤害时刻"和"精英"已被 GameTest 覆盖，**只剩视觉**需要人眼。

## 八、怎么加第 13 只

1. `tools/gen_dungeon_mobs.py`：`SPECS` 加一条（骨架原型 + 调色板 + `kind`），`ORDER` 加 id；
2. 跑生成器 + 校验器；
3. `DungeonSpecies` 加一行（数值 + `Kind`）；
4. `tools/apply_dungeon_mob_lists.py` 的表里加权重；
5. 跑 `DungeonMobAssetsTest`（它会替你把"id 拼错 / 片段缺 / 骨头缺"全抓出来）。

`kind` 复用现有 12 种就不用写新 AI；要新机制才需要在
`TNDungeonMob#performImpact()` 里加一个 case，并在 `Kind` 里补时序。
