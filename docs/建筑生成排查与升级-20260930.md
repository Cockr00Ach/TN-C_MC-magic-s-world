# 大型建筑定位与生成升级（2026-09-30）

## 用户报告与只读证据

用户报告 Elden 西岸城堡群 `/locate structure tnc:elden_coastal_castle` 与赫萝斯堪德宫殿 `/locate structure tnc:stonecrest_fortress` 只有坐标，抵达没有建筑或施工；其他建筑会启动。还要求参考灾变，避免抵达后等待几分钟施工。

本地正式实例为 `D:\垃圾桶\PCL 正式版 2.9.3\.minecraft\versions\元素觉醒1.4.3-魔改版-20260915`。只读审计 `saves/新的世界` 的17032个已保存区块，仅找到一个有效的大型起点（末地浮岛）；`tnc_landmarks_v1.dat`也只有末地浮岛job。当前和最近两日聊天日志没有用户这次两栋建筑的定位/传送坐标，因此不能声称已在用户的具体故障位置复现，亦不能把未保存的内存状态当成已完成建筑。

旧管线：原生Structure只留下单块marker；只有其postProcess或起点区块升级到FULL的Load事件才入队。locate仅需StructureStart存在，不保证marker的FULL阶段已执行。入队后还需预检每片NBT、勘测、整地，再每tick放一片。末地浮岛3128片，仅放片理论下限约156秒；第一条job等待区块/避让玩家会堵住后续job。

灾变参考为官方仓库 `lender544/new1.20.1` 的 `RuinedCitadelStructure` 和 `Burning_Arena_Structure`，使用Structure/TemplateStructurePiece随区块生成；不是开局预生成全世界。

## 本次改动

1. 新世界：`LandmarkGenerationMode`在世界加载时持久化生成模式。新建主世界启用随区块放置；marker不再排后台施工。
2. `LandmarkChunkFeature`通过Forge biome modifier在FEATURES阶段调用，仅处理当前WorldGenRegion区块。以同种子、原生随机分布、地形和生物群系条件复算起点，再放当前区块相交的NBT片；不强加载远处起点、不写邻区块。
3. `LandmarkSites`缓存世界/生成器状态/结构/候选坐标的合法站点；`piecesFor`按局部XZ和原点对齐索引，远超8区块的侧翼也能放置。保留原建筑尺寸、模板、地形融合和Conquest known-shape兼容设置。
4. 原有世界不切算法：避免将新世界的整地与旧施工日志混用。每5秒后台检查玩家周围站点，通过有超时的起点区块票促使真实marker到FULL；必须看到实际marker才入队，绝不只凭新的噪声预测覆盖旧房屋。附近已FULL区块的保存marker也独立复查。
5. 旧施工改为轮转+软8ms批处理预算；一个job等待不会卡住全部。施工票短期保留避免换任务立即卸载，但上限64个区块，闲置100tick释放。
6. `LandmarkArbitration`做确定性的建筑间排斥；深渊选址和旧挖坑任务都避开这些大型建筑，避免新旧管线互相破坏。深渊挖坑本身本次未改为区块式生成。
7. `buildingGameTests`启动配置补上开发映射转换，修复装备Mixin在开发测试环境的启动失败；不改变正式装备玩法。

涉及的四类：Elden、赫萝斯堪德整座宫殿、哥特大教堂、末地浮岛。普通小型建筑和天空岛任务系统不改。

## 使用与限制

- 两个locate指令不变。坐标是南侧接近点，并非建筑中心，建筑主要向北展开。
- 新世界完成正常区块加载时应同时出现建筑切片，不再等整栋逐tick施工；超大建筑仍有正常地形生成、读NBT和网络区块传输耗时，不能承诺瞬间加载。
- 旧世界到达接近点后自动恢复检查，仍可能显示安全施工进度；可用 `/tnc landmark status` 查看暂停原因。不要站在实际施工体积里阻挡安全避让。
- 旧存档曾更换生物群系/分布/地形数据包时，新的预测未必能发现远端旧起点；到原保存的locate接近点仍会从真实marker恢复。没有索引的历史起点不能凭新预测盲目补建。
- 未删除用户区块、未修改源地图、未缩减城堡侧翼、未直接编辑用户存档。
